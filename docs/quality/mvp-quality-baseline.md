# 映见 MVP 质量基线

> 状态：当前质量合同。它分别验证从首页“图片应用”和“动起来”两个大入口开始的独立任务链，不再以传统修图工具数量、参数覆盖或批量能力作为完成标准。

## 质量对象

映见只评价五个用户可感知结果：

1. 用户能在首页一眼区分并选择“图片应用”或“动起来”；
2. 用户能在所选任务内顺利选中一张源照片；
3. 用户能看懂并确定适合当前任务的风格；
4. 图片应用得到忠于源照片、稳定可复现的结果；
5. 动起来得到与所定风格一致的新作品，首个生成重点是让静态图片动起来。

参数、滤镜、蒙版、模型和渲染阶段只是内部执行材料，不是独立产品质量对象。

## 通用硬门

- 源照片始终只读；应用结果和生成结果都是独立派生物。
- 风格必须有稳定身份和版本。切换风格替换当前风格，不把多个风格暗中叠加。
- 结果必须绑定源照片身份、风格版本和源状态版本；过期结果不能冒充当前结果。
- 应用与生成具有不同的等待、费用、隐私和失败语义，界面必须在执行前说明。
- 两个任务只在首页以大入口并列；进入任一任务后只显示当前任务的一个主操作，切换任务返回首页。
- 取消、失败、退后台或应用重启不得损坏源照片、创作草稿或已经完成的结果。
- 预览、最终结果、再次打开和再次导出不得逐次累积效果。
- 图片、人脸特征、完整提示词、签名 URL 和供应商错误不得进入普通日志。

## 自动工程门

### 主旅程

正式集成测试必须通过生产导航分别完成：

```text
首页 → 图片应用 → 选择图片 → 定静态风格 → 应用 → 静态结果 → 导出或返回
首页 → 动起来   → 选择图片 → 定动态方向与风格 → 确认生成 → 动态结果 → 导出或返回
```

测试至少覆盖：

- 取消选图不创建空草稿；
- 任务选择先于选图，进入任务后不会出现另一个任务的主操作；
- 返回首页切换任务不会复用错误的 `creationIntent`、状态或迟到结果；
- 风格未确定时不能执行；
- 切换风格只保留最后一次选择；
- 应用成功、失败和撤销；
- 生成创建、等待、取消、失败、重试和完成；
- 风格变化后旧生成结果明确标记为旧版本；
- 冷启动恢复最后一个安全状态；
- 导出使用当前结果，不使用过期预览或临时代理图。

### 应用

“应用”必须证明：

1. 相同源照片、风格定义和引擎版本得到稳定结果；
2. 人物身份、主体结构、构图和不可变内容符合风格保护规则；
3. 预览和最终导出在方向、构图、色彩趋势、强度和保护规则上同义；
4. 重复打开、保存、恢复或导出不会二次套用风格；
5. 未知风格版本、不支持能力和越界内部参数严格拒绝；
6. 应用失败时继续显示上一个安全结果并允许重试或换风格。

### 生成

“生成”必须证明：

1. 只有用户明确选择生成后才创建任务；
2. 上传范围、预计消耗和结果类型在创建任务前可见；
3. 任务具备稳定幂等身份、超时、取消、重试和成本上限；
4. 失败、取消或质量拒绝不会破坏源图、当前风格或任何已有结果，也不会错误扣除权益；
5. 生成结果绑定创建时的源照片与风格版本；
6. 用户继续定风格后，旧任务可以完成，但结果必须标记为旧版本；
7. 供应商对象、原始响应和密钥停留在 Adapter 边界之外。

### 动态作品

首个“图片动起来”切片必须额外证明：

- 方向、画幅、主体身份和整体风格在时间轴上稳定；
- 没有不可接受的脸部漂移、肢体增生、背景闪烁、边缘撕裂或周期跳变；
- 播放、暂停、重播、退后台和恢复不会丢失任务或结果；
- 保存的是正式动态产物，不是屏幕录制或预览缓存；
- 源照片和任何已有静态结果保持不变；
- Reduce Motion 开启时，界面动画减弱，但用户主动生成的动态作品仍可通过明确操作播放。

具体容器、编码、时长、帧率和分辨率由动态实现 Spec 冻结，冻结后必须进入最终产物回查。

## 人工质量门

正式结果使用同一源照片、匿名随机顺序和冻结候选进行 1–5 分评价；4 表示自然可靠、可以发布。

### 风格

| 维度 | 通过门 |
|---|---|
| 风格辨识度 | 中位数 ≥ 4 |
| 与风格描述或参考的一致性 | 中位数 ≥ 4 |
| 主体与身份保持 | 全部通过 |
| 色彩、细节与构图完整性 | 中位数 ≥ 4 |
| 不同风格之间的有效差异 | 至少 80% 参与者能稳定区分 |

### 应用结果

| 维度 | 通过门 |
|---|---|
| 第一结果可发布 | 中位数 ≥ 4 |
| 无需传统工具补救 | 至少 70% 目标用户认可 |
| 预览与导出一致 | 全部通过 |
| 灾难性身份或结构错误 | 0 |

### 动态结果

| 维度 | 通过门 |
|---|---|
| 动作自然且符合照片内容 | 中位数 ≥ 4 |
| 静态与动态风格连续 | 中位数 ≥ 4 |
| 人物身份与主体稳定 | 全部通过 |
| 闪烁、扭曲和异常增生 | 灾难性错误为 0 |
| 值得保存或分享 | 至少 60% 目标用户认可 |

## 可用性门

五名符合目标用户资格的参与者在没有讲解的情况下完成同一冻结候选：

1. 在首页不经讲解区分“图片应用”和“动起来”，并为指定结果选择正确入口；
2. 在每个任务内选择一张自己的照片；
3. 用浏览、文字、语音或参考图中的任一方式确定风格；
4. 正确解释两个任务的结果、等待与费用差异；
5. 分别完成一次图片应用和一次动态生成；
6. 找到结果、处理失败并完成导出。

通过要求：

- 所有人都能复述两条任务链为“先选图片应用或动起来，再选图片、定风格并完成当前任务”；
- 没有人在定风格页寻找另一个任务入口，且能通过返回首页主动切换任务；
- 没有人寻找曝光、磨皮、滤镜或“更多工具”才能继续；
- 至少 80% 的执行选择在首次点击时正确；
- 隐私、费用或等待相关误解为 0；
- 所有阻断问题都有清楚、可执行的恢复动作。

## 设备与性能

Simulator 和 Debug 只证明工程路径；冻结候选必须在低、中、高三档真实 iPhone 上验证。

| 指标 | 低档 | 中档 | 高档 |
|---|---:|---:|---:|
| 选图后风格界面可用 | ≤ 4.0 s | ≤ 2.5 s | ≤ 1.8 s |
| 本地风格切换反馈 p95 | ≤ 180 ms | ≤ 140 ms | ≤ 100 ms |
| 12 MP 应用结果导出 | ≤ 8 s | ≤ 5 s | ≤ 3.5 s |

生成耗时不与本地应用混为一个预算。创建生成任务后 300 ms 内必须显示真实任务状态；供应商的终态时限、超时和成本上限必须由候选合同明确记录。

峰值附加内存不得超过设备物理内存的 25%，且不得超过 512 MB。资源压力可以降低预览质量，不能降低最终应用结果或静默改变生成请求。

## 完成状态

- **功能实现完成**：入口、状态、失败恢复、持久化和窄自动测试闭环。
- **模拟器验证通过**：生产导航主旅程和可访问性工程检查通过。
- **候选已冻结**：源码、版本、配置、风格版本、生成供应商版本和产物身份固定。
- **真机验收通过**：同一冻结候选通过设备、人工风格、应用结果和动态结果门。

任何缺失项均保持 `待验证` 或 `阻断`，不能由截图、旧 build、单次成功或传统工具能力代替。
