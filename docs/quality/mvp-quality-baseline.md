# 映见 MVP 质量基线

> 状态：当前质量合同。它验证从首页优化照片、换风格、去背景 / 去杂物和做动态效果四个入口开始的独立任务链，不再以传统修图工具数量、参数覆盖或批量能力作为完成标准。

## 质量对象

映见只评价六个用户可感知结果：

1. 用户能在首页一眼区分并选择优化照片、换风格、去背景 / 去杂物或做动态效果；
2. 用户能在所选任务内顺利选中一张源照片；
3. 用户能完成本地优化、换风格或受支持的清理；
4. 用户能在需要时看懂并确定适合换风格或动态任务的风格；
5. 三个静态任务得到忠于源照片、稳定可复现的结果；
6. 做动态效果在当前服务未接入时真实说明不可用、不上传、不创建任务、不扣费；服务接入后才评价动态作品。

参数、滤镜、蒙版、模型和渲染阶段只是内部执行材料，不是独立产品质量对象。

## 通用硬门

- 源照片始终只读；应用结果和生成结果都是独立派生物。
- 风格必须有稳定身份和版本。切换风格替换当前风格，不把多个风格暗中叠加。
- 结果必须绑定源照片身份、风格版本和源状态版本；过期结果不能冒充当前结果。
- 静态与生成具有不同的等待、费用、隐私和失败语义，界面必须在执行前说明。
- 四个任务只在首页以大入口并列；进入任一任务后只显示当前任务的一个主操作，切换任务返回首页。
- `CreationTask=optimize|style|cleanup|motion` 是任务身份；`CreationIntent=apply|motion` 仅为执行分支。历史 `apply` 草稿必须恢复为 `style`。
- 清理只接受语义白底/背景处理和局部本地擦除；透明 alpha 抠图、无限制路人移除和生成式补全不在当前质量声称范围。
- 取消、失败、退后台或应用重启不得损坏源照片、创作草稿或已经完成的结果。
- 预览、最终结果、再次打开和再次导出不得逐次累积效果。
- 图片、人脸特征、完整提示词、签名 URL 和供应商错误不得进入普通日志。

## 自动工程门

### 主旅程

正式集成测试必须通过生产导航分别完成：

```text
首页 → 优化照片 → 选择图片 → 本地优化 → 静态结果 → 导出或返回
首页 → 换风格 → 选择图片 → 定静态风格 → 应用 → 静态结果 → 导出或返回
首页 → 去背景 / 去杂物 → 选择图片 → 语义背景或本地擦除 → 静态结果 → 导出或返回
首页 → 做动态效果 → 选择图片 → 服务未接入状态（无上传、无任务、无成本）
```

测试至少覆盖：

- 取消选图不创建空草稿；
- `CreationTask` 选择先于选图，进入任务后不会出现另一个任务的主操作；
- 返回首页切换任务不会复用错误的 `CreationTask`、`creationIntent`、状态或迟到结果；旧 `apply` 草稿恢复为换风格；
- 风格未确定时不能执行；
- 切换风格只保留最后一次选择；
- 优化、风格应用和受支持清理的成功、失败和撤销；
- 动态服务未接入时不创建、不等待、不取消、不重试和不收费；生成服务接入后再覆盖创建、等待、取消、失败、重试和完成；
- 服务接入后，风格变化使旧生成结果明确标记为旧版本；
- 冷启动恢复最后一个安全状态；
- 导出使用当前结果，不使用过期预览或临时代理图。

### 静态任务

优化、换风格和去背景 / 去杂物必须证明：

1. 相同源照片、任务、风格定义（如适用）和引擎版本得到稳定结果；
2. 人物身份、主体结构、构图和不可变内容符合风格保护规则；
3. 预览和最终导出在方向、构图、色彩趋势、强度和保护规则上同义；
4. 重复打开、保存、恢复或导出不会二次套用风格；
5. 未知风格版本、不支持能力和越界内部参数严格拒绝；
6. 失败时继续显示上一个安全结果并允许重试或返回当前任务；清理拒绝未支持的 alpha 与生成式语义。

### 动态服务（当前不可用）

当前做动态效果入口必须证明：

1. 当前服务未接入状态可被用户理解；
2. 不上传、不创建远端任务、不展示虚假进度、不收费；
3. 返回首页或稍后再试不改变源图、风格或任何已有结果；
4. 供应商对象、原始响应和密钥继续停留在 Adapter 边界之外。

服务接入同一变更中，必须恢复并验证稳定幂等身份、确认前可见的上传/成本、取消、重试、结果来源绑定和失败不扣费合同。

### 动态作品

服务接入后的首个“图片动起来”切片必须额外证明：

- 方向、画幅、主体身份和整体风格在时间轴上稳定；
- 没有不可接受的脸部漂移、肢体增生、背景闪烁、边缘撕裂或周期跳变；
- 播放、暂停、重播、退后台和恢复不会丢失任务或结果；
- 保存的是正式动态产物，不是屏幕录制或预览缓存；
- 源照片和任何已有静态结果保持不变；
- Reduce Motion 开启时，界面动画减弱，但用户主动生成的动态作品仍可通过明确操作播放。

具体容器、编码、时长、帧率和分辨率由动态实现 Spec 冻结，冻结后必须进入最终产物回查。

## 人工质量门

正式结果使用同一源照片、匿名随机顺序和冻结候选进行 1–5 分评价；4 表示自然可靠、可以发布。

### 风格

| 维度 | 通过门 |
|---|---|
| 风格辨识度 | 中位数 ≥ 4 |
| 与风格描述或参考的一致性 | 中位数 ≥ 4 |
| 主体与身份保持 | 全部通过 |
| 色彩、细节与构图完整性 | 中位数 ≥ 4 |
| 不同风格之间的有效差异 | 至少 80% 参与者能稳定区分 |

### 应用结果

| 维度 | 通过门 |
|---|---|
| 第一结果可发布 | 中位数 ≥ 4 |
| 无需传统工具补救 | 至少 70% 目标用户认可 |
| 预览与导出一致 | 全部通过 |
| 灾难性身份或结构错误 | 0 |

### 动态结果

| 维度 | 通过门 |
|---|---|
| 动作自然且符合照片内容 | 中位数 ≥ 4 |
| 静态与动态风格连续 | 中位数 ≥ 4 |
| 人物身份与主体稳定 | 全部通过 |
| 闪烁、扭曲和异常增生 | 灾难性错误为 0 |
| 值得保存或分享 | 至少 60% 目标用户认可 |

## 可用性门

五名符合目标用户资格的参与者在没有讲解的情况下完成同一冻结候选：

1. 在首页不经讲解区分优化照片、换风格、去背景 / 去杂物和做动态效果，并为指定结果选择正确入口；
2. 在每个任务内选择一张自己的照片；
3. 用浏览、文字、语音或参考图中的任一方式在换风格任务确定风格；
4. 正确解释三个静态任务与动态效果的结果、等待与费用差异；
5. 分别完成一次优化、换风格和受支持的清理，并识别动态服务未接入且无成本；
6. 找到静态结果、处理失败并完成导出。

通过要求：

- 所有人都能复述四条任务链为“先选优化、换风格、清理或动态效果，再选图片并完成当前任务”；
- 没有人在任一任务页寻找另一个任务入口，且能通过返回首页主动切换任务；
- 没有人寻找曝光、磨皮、滤镜或“更多工具”才能继续当前任务；
- 至少 80% 的执行选择在首次点击时正确；
- 隐私、费用或等待相关误解为 0；
- 所有阻断问题都有清楚、可执行的恢复动作。

## 设备与性能

Simulator 和 Debug 只证明工程路径；冻结候选必须在低、中、高三档真实 iPhone 上验证。

| 指标 | 低档 | 中档 | 高档 |
|---|---:|---:|---:|
| 选图后任务界面可用 | ≤ 4.0 s | ≤ 2.5 s | ≤ 1.8 s |
| 本地风格切换反馈 p95 | ≤ 180 ms | ≤ 140 ms | ≤ 100 ms |
| 12 MP 应用结果导出 | ≤ 8 s | ≤ 5 s | ≤ 3.5 s |

当前动态服务未接入，因此没有生成耗时预算、进度或成本可声称。服务接入后，生成耗时不与本地任务混为一个预算；创建生成任务后 300 ms 内必须显示真实任务状态，供应商的终态时限、超时和成本上限必须由候选合同明确记录。

峰值附加内存不得超过设备物理内存的 25%，且不得超过 512 MB。资源压力可以降低预览质量，不能降低最终应用结果或静默改变生成请求。

## 完成状态

- **功能实现完成**：入口、状态、失败恢复、持久化和窄自动测试闭环。
- **模拟器验证通过**：生产导航主旅程和可访问性工程检查通过。
- **候选已冻结**：源码、版本、配置、风格版本、生成供应商版本和产物身份固定。
- **真机验收通过**：同一冻结候选通过设备、人工静态任务结果与当前可用能力门；动态结果门在服务接入候选中补齐。

任何缺失项均保持 `待验证` 或 `阻断`，不能由截图、旧 build、单次成功或传统工具能力代替。
