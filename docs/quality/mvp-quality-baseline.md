# 映见 MVP 质量基线

> 状态：目标 MVP 质量合同。它验证从首页四个入口开始的具名结果直达、不阻塞工作区和独立任务链；任何运行时未开通能力都必须保持真实不可用，不能用近似能力冒充通过。

## 质量对象

映见只评价七个用户可感知结果：

1. 用户能在首页一眼区分并选择优化照片、换风格、去背景 / 去杂物或做动态效果；
2. 用户能在所选任务内顺利选中一张源照片；
3. 用户能看到当前任务固定、完整的能力列表，进入时没有默认选择、推荐、排序或自动执行；
4. 用户能点击一个具名结果并直接看到该能力的执行、必要云端确认或真实不可用状态；
5. 用户能完成当前真实支持的优化、换风格或清理能力；
6. 三个静态任务得到忠于源照片、绑定所选能力且可追溯的结果；
7. 做动态效果的三项本地方向点击即生成对应 MP4，AI 自然动效只在必要云端确认后创建一次任务；二者都不得相互替代。

参数、滤镜、蒙版、模型和渲染阶段只是内部执行材料，不是独立产品质量对象。

## 通用硬门

- 源照片始终只读；应用结果和生成结果都是独立派生物。
- 结果必须绑定源照片身份、用户明确选择的 `CreationCapability`、该能力已确认输入的冻结版本（如有）和源状态版本；过期结果不能冒充当前结果。
- 换风格结果还必须绑定稳定风格身份和版本。切换风格替换当前风格，不把多个风格暗中叠加。
- 静态与生成具有不同的等待、费用、隐私和失败语义，界面必须在执行前说明。
- 四个任务只在首页以大入口并列；进入任一任务后持续显示图片与当前任务的直达选项，切换任务返回首页。
- `CreationTask=optimize|style|cleanup|motion` 是任务身份；用户点击后保存的 `CreationCapability` 才是具体能力身份；`CreationIntent=apply|motion` 仅为页面分支。历史 `apply` 草稿必须恢复为 `style`。
- 四组能力按产品固定顺序完整展示且初始无选中项。分析、AI、历史和设备不能推荐、排序、组合、替换、降级或执行能力。
- 真实可用性以 [MVP Spec](../product/mvp-spec.md) 和当前运行时能力目录为准。新建创作不展示历史文字/语音/参考图风格入口；任何未开通的云能力必须独立显示不可用，不得自动改走本地能力。
- 取消、失败、退后台或应用重启不得损坏源照片、创作草稿或已经完成的结果。
- 预览、最终结果、再次打开和再次导出不得逐次累积效果。
- 图片、人脸特征、完整提示词、签名 URL 和供应商错误不得进入普通日志。

## 自动工程门

### 主旅程

正式集成测试必须通过生产导航分别完成：

```text
首页 → 优化照片 → 选择图片 → 点击优化结果 → 本地执行 / 必要云确认 / 真实不可用 → 静态结果
首页 → 换风格 → 选择图片 → 点击日系 / 胶片 / 插画 / 电影感 → 本地直接应用 / 插画必要云确认 → 静态结果
首页 → 去背景 / 去杂物 → 选择图片 → 点击清理结果 → 直接执行 / 必要输入与云确认 → 静态结果
首页 → 做动态效果 → 选择图片 → 点击动态方向 → 本地直接生成 / AI 必要云确认 → 动态结果
```

测试至少覆盖：

- 取消选图不创建空草稿；
- `CreationTask` 选择先于选图，进入任务后不会出现另一个任务的主操作；
- 选图后完整显示当前任务固定能力列表，进入时没有默认能力；用户点选前没有分析后执行、上传、任务或费用；
- 选中后只执行该能力；不支持、失败或质量拒绝时不推荐、不组合、不替换、不降级、不自动切换；
- 返回首页切换任务不会复用错误的 `CreationTask`、`creationIntent`、状态或迟到结果；旧 `apply` 草稿恢复为换风格；
- 未点击风格时不能执行；点击本地风格后不出现第二个应用按钮；
- 切换风格只保留最后一次选择；
- 优化、风格应用和受支持清理的成功、失败和撤销；
- 三项本地动态的直接生成与 AI 自然动效的云端创建、等待、取消、失败、重试和完成分别覆盖；
- 服务接入后，静态风格生成在已确认 `StyleDefinition` 变化时把旧结果标记为相对当前选择过期；动态生成只在源图、已选动态方向或该方向的已确认输入变化时把旧结果标记为相对当前选择过期；
- 冷启动恢复最后一个安全状态；
- 导出使用当前结果，不使用过期预览或临时代理图。

### 静态任务

优化、换风格和去背景 / 去杂物的每一项已实现静态能力必须分别证明：

1. 相同源照片、任务、用户选择的能力、风格定义（如适用）和引擎版本得到稳定结果；
2. 人物身份、主体结构、构图和不可变内容符合风格保护规则；
3. 预览和最终导出在方向、构图、色彩趋势、强度和保护规则上同义；
4. 重复打开、保存、恢复或导出不会二次套用风格；
5. 未知风格版本、不支持能力和越界内部参数严格拒绝；
6. 失败时继续显示上一个安全结果并允许用户重试或返回能力列表；系统不得选择另一能力。未实现能力保持独立不可用。

### 动态服务

当前做动态效果入口必须证明：

1. 轻微动态、镜头推进和光影流动点击后只调用本地编码器，不上传、不创建远端任务、不收费；
2. AI 自然动效点击后先显示必要上传和权益确认，确认后只创建一个稳定幂等任务；
3. 云状态位于图片上，不遮挡底部选项；网络或生命周期变化后只关联原任务，不自动复制任务；
4. 取消、失败、超时或结果拒绝不改变源图、已选方向或任何已有结果；
5. 供应商对象、原始响应和密钥继续停留在 Adapter 边界之外。

### 动态作品

服务接入后的首个“图片动起来”切片必须额外证明：

- 方向、画幅、主体身份和整体风格在时间轴上稳定；
- 没有不可接受的脸部漂移、肢体增生、背景闪烁、边缘撕裂或周期跳变；
- 播放、暂停、重播、退后台和恢复不会丢失任务或结果；
- 保存的是正式动态产物，不是屏幕录制或预览缓存；
- 源照片和任何已有静态结果保持不变；
- Reduce Motion 开启时，界面动画减弱，但用户主动生成的动态作品仍可通过明确操作播放。

具体容器、编码、时长、帧率和分辨率由动态实现 Spec 冻结，冻结后必须进入最终产物回查。

## 人工质量门

正式结果使用同一源照片、匿名随机顺序和冻结候选进行 1–5 分评价；4 表示自然可靠、可以发布。

### 风格

| 维度 | 通过门 |
|---|---|
| 风格辨识度 | 中位数 ≥ 4 |
| 与风格描述或参考的一致性 | 中位数 ≥ 4 |
| 主体与身份保持 | 全部通过 |
| 色彩、细节与构图完整性 | 中位数 ≥ 4 |
| 不同风格之间的有效差异 | 至少 80% 参与者能稳定区分 |

### 应用结果

| 维度 | 通过门 |
|---|---|
| 第一结果可发布 | 中位数 ≥ 4 |
| 无需传统工具补救 | 至少 70% 目标用户认可 |
| 预览与导出一致 | 全部通过 |
| 灾难性身份或结构错误 | 0 |

### 动态结果

| 维度 | 通过门 |
|---|---|
| 动作自然且符合照片内容 | 中位数 ≥ 4 |
| 静态与动态风格连续 | 中位数 ≥ 4 |
| 人物身份与主体稳定 | 全部通过 |
| 闪烁、扭曲和异常增生 | 灾难性错误为 0 |
| 值得保存或分享 | 至少 60% 目标用户认可 |

## 可用性门

五名符合目标用户资格的参与者在没有讲解的情况下完成同一冻结候选：

1. 在首页不经讲解区分优化照片、换风格、去背景 / 去杂物和做动态效果，并为指定结果选择正确入口；
2. 在每个任务内选择一张自己的照片；
3. 在换风格任务直接点击日系、胶片、插画或电影感，并看到本地直达结果或插画的必要云端确认；
4. 正确解释三个静态任务与动态效果的结果、等待与费用差异；
5. 分别完成一次优化、换风格、清理和本地动态，并正确识别需要云端确认或当前运行时不可用的选项；
6. 找到静态结果、处理失败并完成导出。

通过要求：

- 所有人都能复述四条任务链为“先选任务，再选图片，再由自己选一个具体能力”；
- 没有人在任一任务页寻找另一个任务入口，且能通过返回首页主动切换任务；
- 没有人寻找曝光、磨皮、滤镜或“更多工具”才能继续当前任务；
- 至少 80% 的执行选择在首次点击时正确；
- 隐私、费用或等待相关误解为 0；
- 所有阻断问题都有清楚、可执行的恢复动作。

## 设备与性能

Simulator 和 Debug 只证明工程路径；冻结候选必须在低、中、高三档真实 iPhone 上验证。

| 指标 | 低档 | 中档 | 高档 |
|---|---:|---:|---:|
| 选图后任务界面可用 | ≤ 4.0 s | ≤ 2.5 s | ≤ 1.8 s |
| 本地风格切换反馈 p95 | ≤ 180 ms | ≤ 140 ms | ≤ 100 ms |
| 12 MP 应用结果导出 | ≤ 8 s | ≤ 5 s | ≤ 3.5 s |

当前动态服务未接入，因此没有生成耗时预算、进度或成本可声称。服务接入后，生成耗时不与本地任务混为一个预算；创建生成任务后 300 ms 内必须显示真实任务状态，供应商的终态时限、超时和成本上限必须由候选合同明确记录。

峰值附加内存不得超过设备物理内存的 25%，且不得超过 512 MB。资源压力可以降低预览质量，不能降低最终应用结果或静默改变生成请求。

## 完成状态

- **功能实现完成**：入口、状态、失败恢复、持久化和窄自动测试闭环。
- **模拟器验证通过**：生产导航主旅程和可访问性工程检查通过。
- **候选已冻结**：源码、版本、配置、风格版本、生成供应商版本和产物身份固定。
- **真机验收通过**：同一冻结候选通过设备、人工静态任务结果与当前可用能力门；动态结果门在服务接入候选中补齐。

任何缺失项均保持 `待验证` 或 `阻断`，不能由截图、旧 build、单次成功或传统工具能力代替。
