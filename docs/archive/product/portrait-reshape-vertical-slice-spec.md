# 人像塑形纵切 Spec

Status: validation-incomplete

> 工程状态：iOS ImagePipeline V8、Vision 多脸/多人体适用性、局部形变、背景保护、移动端逐目标控制、撤销/恢复以及预览/导出链路已贯通。候选使用 Metal `CIWarpKernel` 的 source-coordinate inverse warp 与受保护局部缩放，并有输出轮廓和保护区回归测试。该状态只表示工程实现已贯通；在冻结样片逐参数量化、五人盲评和候选设备门全部通过前，不得标记为质量完成。

> 决策日期：2026-08-09。用户明确指出仅有克制肤质处理不足以构成“让用户变美”的 MVP；确定性的基础五官和身体塑形进入 iOS 首发 P0。本文不包含生成式换脸、妆容或自由液化。

## 1. 用户结果

已有图片中的一个或多个人脸在满足各自安全条件时，可以独立调整：

- `一键自然美化`：把质感磨皮、肤色与面部光线、瑕疵减弱的安全推荐值写入三个真实参数，不改变几何；
- `面部塑形`：逐脸提供瘦脸、小头、下颌、下巴、大眼、鼻形和嘴形；
- `身体塑形`：逐主体提供整体瘦身、增高、肩、腰和腿部调整。

三个非几何参数以及全部逐目标塑形参数必须独立、可归零、可撤销。三套推荐可以通过一键自然美化设置非几何参数，但不得自动设置任何几何参数；只有用户显式操作才产生非零几何参数。

## 2. P0 范围

### 2.1 面部塑形

- 最多三个高置信度人脸；正脸与轻侧脸。多人照片不得因此整体拒绝。
- 用户先选择目标人脸，再分别使用瘦脸、小头、下颌、下巴、大眼、鼻形和嘴形滑杆；每张脸全部默认 `0`。瘦脸和小头为 `0...100`，其余为可双向调整的 `-100...100`；首轮 UI 安全范围分别限制为 `0...50` 与 `-50...50`。
- 使用人脸框、轮廓和五官关键点建立局部形变场。
- 每项只作用于相应受保护局部；调整瘦脸或小头时，眼、鼻、嘴的相对结构不得漂移。
- 明显侧脸、严重遮挡、关键点缺失、脸过小或背景保护失败时只关闭对应人脸，不阻断其他人脸。

### 2.2 身体塑形

- 最多三个高置信度主体；肩、髋、腿部与躯干可见区域、人体分割和姿态结果必须一致，用户显式选择目标。
- 分别提供整体瘦身、增高、肩、腰和腿部滑杆，全部默认 `0`。整体瘦身、增高和腿为 `0...100`，肩和腰为 `-100...100`；首轮 UI 安全范围分别限制为 `0...35` 与 `-50...50`。
- 每项只调整对应受保护区域；整体瘦身不改变头部与四肢，增高和腿部调整不得改变头宽或背景结构。
- 坐姿/遮挡导致目标区域不完整、宽松衣物无法确定轮廓、姿态点缺失、人物分割失败或背景保护失败时，只关闭对应目标工具，不阻断其他主体和基础编辑。

## 3. 明确不做

- 肌肉、胸部、臀部或姿态生成。
- 手工推脸/推身材画笔。
- 年龄推断、性别推断；应用不根据推测年龄自动处理或拒绝某张脸。
- 云端人脸/人体上传、生成式补背景或身份迁移。

## 4. 版本化配方与边界

- `ImagePipelineV8` 承载逐目标几何合同；V1–V7 语义保持不变。
- Flutter 保存并传递最多三个按稳定序号排列的 `FaceGeometryTarget` 和 `BodyGeometryTarget` 以及各自选中索引；不保存人脸框、关键点、人体姿态、分割图或特征向量。
- 原生按规范化画面中从左到右、再从上到下的确定性顺序分配目标序号；原生会话持有人脸关键点、人体姿态、人物分割、背景风险和形变场，这些数据不得进入项目 JSON、Flutter、普通日志或遥测。
- 预览缓存分析结果，滑杆只更新形变参数；原图导出从原始文件重新分析并应用同一版本化算法。
- 每个参数的 `0` 必须绕过对应形变并与关闭结果保持像素等价；未知版本、未知字段、非法数值、目标超限或能力不适用必须 fail closed。

## 5. iOS 实现候选

- 分析：Vision 人脸关键点、人体姿态与人物分割。
- 渲染：Core Image/Metal 自定义 inverse warp；不以全图 `CIPinchDistortion` 作为生产实现。
- 背景保护：在形变影响区检测人物边界外的高对比长边；无法将位移限制在冻结预算内时拒绝启用。
- 处理顺序：方向规范化 → 人像分析 → 逐目标面部/身体几何 → 基础光色 → 肤色与面部光线 → 质感磨皮 → 瑕疵减弱 → 构图 → 预览或 JPEG/HEIF 导出。

该路线是待验证候选，不因系统 API 存在就视为质量完成。

## 6. 用户交互

- 人像编辑首层显示 `一键自然美化`、`瘦脸`、`瘦身`；进入三个入口后分别展开真实子参数；检测到多个可塑形目标时显示确定性目标选择器。
- 对应人脸或身体目标适用时才显示几何入口；不可用工具不显示死入口。
- 每个工具显示当前数值与归零能力，连续滑动只形成一个撤销步骤。
- 长按前后对比必须同时关闭全部人像效果的预览，但不修改已保存配方。
- 项目恢复、撤销/重做和原图导出必须保留三个非几何参数以及逐目标几何参数与选中索引的独立语义。

## 7. 自动正确性门

- 参数解析：V8 配方接受最多三个完整人脸目标和三个完整身体目标；旧版瘦脸/瘦身值只迁移到对应首目标，其他新增参数保持零；越界、布尔值、非有限值、数量超限和未知字段拒绝。
- 零强度：每个面部与身体几何参数单独为 `0` 时必须绕过该项；全部为零时像素恒等。
- 可见幅度：在各自产品最大安全档，冻结正样片的人脸下颌宽度应收窄 `7.5%...11%`，躯干中段宽度应收窄 `2%...6%`；瘦脸低档保持克制，中高档必须形成无需反复切换才能辨认的轮廓变化；低于下限等同“入口存在但无效果”，高于上限视为身份或比例风险。
- 单调性：冻结正样片在安全区间内，目标轮廓宽度随强度单调不增；合成轮廓测试必须直接断言渲染后的主体宽度，不能只断言参数、位移纹理或像素差异。
- 局部语义：每个五官参数只改变目标区域的声明方向；非目标五官中心漂移不超过人脸宽度的 `0.5%`。
- 背景保护：人物外冻结线段的最大位移不超过输出短边的 `0.25%`，不得出现折线、重复纹理、裂缝或透明像素。
- 身体保护：头部中心、肩髋纵向位置和四肢端点纵向漂移不超过输出高度的 `0.5%`。
- 多目标隔离：调整目标 N 时，其他人脸或身体目标的关键结构和轮廓逐像素保持；无人、全部遮挡、低置信度和背景高风险输入保持原图。
- 预览/导出：方向、形变区域、强度趋势与最终尺寸一致，原图 SHA-256 不变。

## 8. 人工质量门

- 至少 5 名评审者，原图/一键自然美化/低强度塑形/高安全强度/竞品结果匿名随机。
- `更好看`、`自然`、`身份保持`、`背景完整`分别评分；任一明显五官漂移、背景弯曲、身体比例异常或身份变化均为灾难性失败。
- 可改善样片对原图成对偏好率不低于 `65%`；自然、身份和背景维度中位数均不低于 `4/5`。
- 每个 P0 几何子参数分别报告自然度、结构保持和背景完整；瘦脸与整体瘦身继续单独执行竞品门，不能用肤质或其他几何项得分掩盖失败。

## 9. 性能与安全门

- 复用 iOS 三档 Profile/Release 设备证据；滑杆 P95、预览帧率、峰值附加内存和温控必须满足现有设备预算。
- 分析缓存仅限当前原图与能力版本，换图、删除项目、前后台失效或内存压力后不得复用旧关键点/形变场。
- 默认离线、零云端图片任务、诊断关闭时零人脸/人体数据遥测。

## 10. 完成定义

- 同一签名 iOS 候选在真实单人、多人和多主体照片上，从已有图片导入到选择目标、独立面部/身体塑形预览、撤销、项目恢复和原像素导出完整可见。
- 自动正确性、人工盲评、三档物理设备和隐私门全部通过。
- 任一塑形子能力未通过时保持该参数关闭并明确标记 `validation incomplete`，不得用一键自然美化或其他人像能力替代。
