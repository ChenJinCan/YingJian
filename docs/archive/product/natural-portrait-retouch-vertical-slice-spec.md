# 非几何人像自然美化纵切 Spec

> 状态：implementation-complete / validation-incomplete；版本：3.0；日期：2026-08-10。

本文件只定义一键自然美化、质感磨皮、肤色与面部光线、瑕疵减弱的独特产品与处理合同。总体人像范围见 [MVP Spec](mvp-spec.md)，共同质量阈值见 [MVP 质量基线](../quality/mvp-quality-baseline.md)，历史候选研究见[端侧人像技术研究](../research/portrait-retouch-foundation-research-2026-08-04.md)与[候选 Spike 结果](../quality/portrait-core-spike-results.md)。

## 用户结果

用户导入已有成人肖像后，可以先得到一个克制、自然、仍然像本人的结果，再展开三个真实参数继续调整：

1. **质感磨皮**：减少局部粗糙和不均匀，保留毛孔趋势、五官、发际线、胡须和身份纹理。
2. **肤色与面部光线**：改善色偏、暗沉和阴影，保持原有肤色身份与场景光线关系。
3. **瑕疵减弱**：保守减弱高置信度、孤立、短期性的小范围痘印和色斑，不删除身份细节。

入口“一键自然美化”只是一次把安全推荐值写入上述三个参数的可撤销操作，不是额外渲染层。三个参数全部归零后必须没有隐藏残余效果，也不得自动开启瘦脸、瘦身或其他几何能力。

## 参数与多人合同

- 三个参数均为 `0...100`，`0` 严格关闭。
- 每个参数可独立调整、归零、撤销、重做、持久化和迁移。
- 一键操作写入当前冻结的安全推荐值，并作为一次完整历史操作撤销。
- 非几何处理最多覆盖三张高置信度人脸，按脸独立计算适用性和安全上限。
- 首版不为不同人脸提供不同的非几何用户强度；同一参数值仍受每张脸自身安全上限约束。
- 单个低置信度、过小、遮挡或关键点不足的人脸只关闭自身处理，不阻断其他人物、基础编辑或导出。
- 四张以上人脸时必须稳定降级，不允许静默处理不确定目标。
- 应用不推断年龄或性别；适用性依据结构置信度和处理安全性。

## 处理顺序

同一版本化本地管线按以下顺序执行：

1. 解码、方向规范化和工作色彩空间转换。
2. 人脸与结构分析，生成每张脸的适用性和安全区域。
3. 计算皮肤候选区域，并排除眼、眉、鼻孔、嘴唇、牙齿、发际线、胡须、眼镜和高置信度永久边缘。
4. 质感磨皮只调整受保护区域的局部低频与细碎纹理。
5. 肤色与面部光线调整低频色彩和明暗关系。
6. 瑕疵减弱只修复高置信度局部异常。
7. 与未处理区域软融合，再进入其他配方层和最终色彩输出。

预览和原图导出必须使用相同的参数含义、处理顺序、安全判断和算法版本。

## 安全边界

### 必须保留

- 人物身份、脸型和五官结构。
- 毛孔趋势、正常皱纹、雀斑、痣、妆容、胡须和稳定身份细节。
- 眼、眉、唇、牙齿、头发、眼镜、饰品和遮挡物边缘。
- 原有场景光线方向、肤色身份和非目标人物。

### 必须避免

- 塑料皮肤、蜡感、局部糊片和纹理方向突变。
- 脸部漂白、灰黄、泛红、阴影全部抹平或高光溢出。
- 把痣、雀斑、皱纹、胡须、妆容或遮挡当成瑕疵删除。
- 发际线、眼镜、五官或脸部边缘出现 halo、漏抹或硬边。
- 为了产生可见效果而绕过低置信度安全门。

无法可靠区分暂时性瑕疵与身份细节时，瑕疵减弱必须跳过对应区域，不得退化为全脸模糊。

## 工程边界

- Flutter 只保存配方、会话状态和用户操作；原生层执行分析、保护区域、Texture 预览和原图导出。
- Flutter 与原生层只传文件路径、参数、有限区域和稳定状态，不传人脸位图或供应商对象。
- 系统 API、自建算法、许可清晰的开源模型和商业 SDK 都必须位于供应商无关能力接口之后。
- 默认路径完全离线，不上传照片、人脸特征、蒙版或日志中的自由文本。
- 分析或人像引擎不可用时关闭对应人像能力，基础编辑、项目恢复和导出仍可完成。
- 供应商或算法升级必须改变能力版本，并重新运行固定样片、迁移和候选质量门。

本 Spec 不指定 Apple Vision、MediaPipe、ML Kit、商业 SDK 或具体滤波算法为永久实现。选型依据是最终结果、安全、性能、许可、隐私、包体和可维护性，而不是竞品 APK 中出现的库名。

## 自动正确性门

固定样片必须证明：

- 三个参数为 0 时与关闭基线等价。
- 单人适用输入的默认档产生克制但可测变化，高安全档变化更强且方向一致。
- 多人和无人脸负样片按声明安全保持，不出现半生效状态。
- 面部阴影优先改善，高光、五官、永久边缘和背景受保护。
- 预览与最终 JPEG 在方向、尺寸、处理区域和强度趋势上保持一致。
- 保存、恢复、撤销、重做和再次导出不会重复叠加处理。
- 未知版本、越界值和不完整参数被拒绝或安全迁移。

自动门只允许候选进入人工评审，不证明自然度、身份感或“更好看”。具体 fixture、容差和命令由质量基线及 `scripts/test_portrait_*` 维护。

## 人工质量门

正式结果使用同一冻结候选、同一原图和匿名随机化分别评价一键自然美化及三个子能力：

- 身份保持必须全部通过。
- 肤色自然、纹理保护和默认克制程度中位数至少 4/5。
- 头发、眼镜、遮挡和多人边缘中位数至少 3.5/5。
- 可改善样片相对原图的成对偏好率每项至少 65%。
- 相对醒图的胜出或持平比例每项至少 50%。
- 深浅肤色、胡须、眼镜、雀斑/痣、妆容、侧脸和低照度子集分别报告。
- 身份改变、五官损坏、整脸塑料化或灾难性局部错误必须为 0。

正式样片、盲码和评分结构见[六项人像竞品工作流](../quality/portrait-core-parity-workflow.md)。

## 性能与隐私门

- 性能、内存和温控使用质量基线中的 low/mid/high iOS 物理设备预算。
- Profile/Release 或精确 TestFlight build 才能填写最终设备证据；Development 窄测试只能证明真机可执行。
- 默认断网可运行，未上传照片或面部数据。
- 许可允许目标分发方式，模型与 SDK 版本、失败行为和包体均有记录。

## 完成定义

### 功能实现完成

- 一键入口和三个独立参数贯通正式导入、预览、撤销/恢复、项目持久化和原图导出。
- 多脸适用性、安全降级和旧项目迁移闭环。
- 窄自动回归通过。

### 模拟器验证通过

- 通过生产导航进入编辑页并完成一键、展开精调、归零、前后对比、恢复和导出路径。
- 固定工程样片与 iOS Simulator 集成门通过。

### 真机验收通过

- 同一冻结候选通过三档物理设备、性能与完整主旅程。
- 一键自然美化及三个子能力分别通过同图竞品和五人盲评。
- 所有证据绑定同一源码、版本、build、IPA 和哈希。

当前状态只允许表述为“功能实现完成、最终质量验收待完成”，不得写成已经达到或超过竞品。

## 停止条件

以下任一情况阻断候选验收或受影响能力继续扩展：

- 只有高强度全脸模糊才能得到可见改善。
- 多脸保护不能独立关闭不确定对象。
- 瑕疵减弱不能区分暂时性异常与身份细节。
- 深色肤色、胡须、雀斑/痣、妆容或眼镜子集持续失败。
- 预览与导出不能保持同一效果语义。
- 达到最低质量必须上传照片或面部数据。
- 许可、隐私、包体、离线行为或目标设备预算不可接受。
