# 静态任务与风格执行

## 目的

静态 `apply` 页面承载首页的优化照片、换风格和去背景 / 去杂物三个 `CreationTask`。它们都在选图前固定任务身份，选图后以固定顺序展示当前任务的 `CreationCapability`，且初始没有默认选择。只有用户点击的能力才能进入对应执行链；`creationIntent=apply` 不是用户可见的任务名，也不是能力或执行授权。旧 `apply` 草稿必须迁移为 `CreationTask.style`，以保留其风格语义。

本文重点定义本地确定性执行，尤其是用户在日系、胶片和电影感上的单次点击路径。用户点击某个具名结果时，该次动作同时确定风格身份并授权本地执行；系统在同一工作区内完成预览校验、最终渲染和原子提交，不再进入说明页或显示第二个“应用风格” CTA。优化和清理的本地能力可复用同一安全、预览、持久化与恢复边界，但不伪装成风格任务。

本路径只生成确定性静态结果，不展示动态能力。AI 修复、老照片修复、插画和生成式清理等静态生成能力，以及动态任务的云端能力，都由用户点击各自具名结果后进入[独立生成管线](generation-pipeline.md)，不得塞入 `EditRecipe`。云端路径仅在必要的上传与权益确认后创建任务；失败时不能由本地近似效果冒充。

## 核心对象

### StyleDefinition

`StyleDefinition` 是“换风格”任务中确定性应用与静态风格生成共享的合同。静态应用只读取它的确定性应用投影；AI 风格重绘等静态风格生成只读取它的生成投影，两者不得互相嵌入执行状态。动态生成不读取 `StyleDefinition`，只绑定用户明确选择的动态方向。它至少包含：

- 稳定 ID、schema 版本和展示名称；
- 来源类型：内置、用户保存或 AI 提案；
- 有界、可序列化的语义效果集合；
- 支持的静态风格执行分支及各分支所需能力；
- 适用条件、所需平台能力和明确拒绝规则；
- 风格层替换身份；
- 定义来源与引擎兼容版本。

它不包含任意脚本、shader、自由提示词、`EditRecipe`、远程任务 ID、生成媒体或供应商对象。用户原始文字可以作为本地历史说明保留，但不能成为静态应用或静态风格生成结果的唯一执行依据。

插画在 presentation 层使用版本化、受约束的 `illustration-v1` 定义，并以 `origin=aiRedraw` 保持旧项目兼容。它不读取自由文本、语音或参考图，也不做运行时语义改写、补全或推荐。用户点击插画后直接进入必要的云端同意 sheet；生成快照只从该固定定义的生成投影和内容摘要构建。

### StyleProposal

内置目录只从用户点击的日系、胶片或电影感产生对应 `StyleProposal`；插画直接使用固定生成定义。图片分析只能验证当前已选风格能否执行。AI 不能直接返回任意渲染计划或供应商 payload，不能绕过目录增加风格，也不能推荐、排序、组合、替换或降级到另一风格。历史文字、语音或参考图提案只用于无损恢复旧项目，不进入新建创作的主路径。

提案绑定来源内容身份、当前风格基线、目录版本和幂等身份。任一身份过期时必须重新解析，不能自动合并到新状态。在“换风格”任务中，确定性应用投影还必须绑定当前编辑状态版本并进入 `EditingCore`。动态任务使用用户单独选择的动态方向，不读取或推导当前 `StyleDefinition`；静态应用会话也不负责切换任务或创建生成快照。

### StyleCommit

`StyleCommit` 记录已接受的定义、规范化编辑状态、稳定 `RenderPlan` 身份和来源状态版本。它只属于本地“应用风格”路径，是恢复、撤销、对比和静态导出的依据。AI 风格重绘等静态生成能力从同一 `SourcePhoto`、用户已选能力和已确认输入创建自己的来源快照，不要求存在 `StyleCommit`；动态生成另行绑定用户选择的动态方向。

## 执行流程

```text
home: choose 换风格
  → select image
  → tap 日系 / 胶片 / 电影感
  → bind the exact StyleDefinition and selection generation
  → validate, render, and atomically commit
  → show the result in the same workspace

or

  → tap 插画
  → bind illustration-v1
  → confirm required upload and credit boundaries
  → create exactly one cloud task
  → show non-blocking progress and the final result
```

1. 用户先在首页选择“换风格”；presentation 固定 `CreationTask.style` 和 `creationIntent=apply`，再导入应用自有、只读来源及内容身份。进入页面时没有默认能力或默认风格。
2. 用户点击日系、胶片或电影感时，系统立即绑定对应内置定义并开始本地应用；点击插画时绑定 `illustration-v1` 并打开必要云端确认。
3. `EditingCore` 依据唯一元操作目录完成参数、目标、能力、冲突和状态版本校验。
4. 原生渲染器以版本化计划执行真实预览与最终渲染；占位图、静态缩略图或仅更新选中态不算成功。
5. 预览和最终渲染属于同一次点击授权的执行链；不询问第二次应用。连续点击其他风格时，只有最新选择世代的结果可以提交。
6. 最终渲染与持久化成功后一次性创建 `StyleCommit`；失败保持最后一个安全状态并返回结构化原因。
7. 云任务的队列、运行、失败或待对账状态以图片上的紧凑状态呈现，不替换底部风格栏；用户要创作动态作品时仍从首页进入独立“做动态效果”任务。

## 替换与撤销语义

- 用户点击另一个风格时，原子替换上一风格拥有的操作地址，不把两个完整风格连续叠加。
- 风格之外、明确属于来源安全或兼容迁移的状态只能按目录规则保留，不由页面猜测合并。
- 一次风格应用形成一个撤销步骤；AI 风格定义和临时预览本身不进入静态历史。
- 撤销恢复上一个完整风格状态；长按或等价入口比较只读原图，不创建历史。
- 归零、中性风格和恢复原图必须严格可复现。

## AI 与隐私

- 用户点击日系、胶片或电影感时不调用 AI，也不上传原图。
- 插画只使用固定、受约束定义；在云端任务创建前明确上传范围、删除边界和成本合同，未确认不发送。
- 云端输出必须绑定当前源图、插画定义版本、请求 ID 和选择世代；迟到或不匹配结果不得进入当前画布。

## 失败与拒绝

- 不支持的能力、未知 schema、越界参数、目标失效和过期提案全部 fail closed。
- 用户已选择的 AI 能力不可用时，明确说明不可用并保留当前状态；不得自动切换为内置风格。
- 图片分析失败时拒绝当前执行并说明原因；不得自动改用所谓安全风格、中性结果或其他能力，也不得从文件名、路径或自由元数据猜测内容。
- 预览或持久化失败不得发布半应用状态；最后一个安全提交继续可见、可撤销、可导出。

## 验证合同

- 同一来源、编辑基线、`StyleDefinition`、目录版本和引擎能力生成稳定编辑状态与 `RenderPlan` ID。
- 依次应用不同风格时证明替换而非叠加，撤销恢复完整前态，重启恢复同一结果。
- AI 对抗测试覆盖未知能力、越界值、重复地址、提示注入、过期状态、取消、去重和日志隐私。
- 固定样片验证中性恒等、预览/导出同义、目标保护和不支持能力严格拒绝。
- 集成测试必须从生产首页“换风格”入口进入，证明进入时没有默认风格、选择前没有分析后执行或上传；页面固定展示日系、胶片、插画和电影感，点击本地风格即产生真实结果，没有第二个应用按钮；插画只进入必要云端确认。测试还必须覆盖风格切换时迟到结果不覆盖新选择、云状态不阻塞底部选项，以及优化和清理各自的直达执行、真实可用性与静态结果。
