# 静态风格执行

## 目的

静态应用路径始于首页“图片应用”入口。presentation 在选图和定风格前已确定 `creationIntent=apply`，选择或定义风格只形成 `StyleDefinition` 和临时预览，不创建静态提交；进入 `applyStyleReady` 后只显示“应用风格”这一个主 CTA。用户明确应用后，系统才把确定性投影解析为不可见参数配方并原子提交。用户不需要理解曝光、HSL、磨皮、塑形或渲染阶段。

本路径只生成确定性静态结果，不展示“让图片动起来”入口。图片动效和其他派生媒体必须从首页“动起来”任务进入[独立生成管线](generation-pipeline.md)，不得塞入 `EditRecipe`。

## 核心对象

### StyleDefinition

`StyleDefinition` 是“定风格”的分支无关合同。静态应用只读取它的确定性应用投影；生成管线读取同一定义的生成投影，两者不得互相嵌入执行状态。它至少包含：

- 稳定 ID、schema 版本和展示名称；
- 来源类型：内置、用户保存或 AI 提案；
- 有界、可序列化的语义效果集合；
- 支持的执行分支及各分支所需能力；
- 适用条件、所需平台能力和安全降级规则；
- 风格层替换身份；
- 定义来源与引擎兼容版本。

它不包含任意脚本、shader、自由提示词、`EditRecipe`、远程任务 ID、生成媒体或供应商对象。用户原始文字可以作为本地历史说明保留，但不能成为应用或生成结果的唯一执行依据。

### StyleProposal

内置目录和 AI 都只产生 `StyleProposal`。AI 可以把文字意图与有限、结构化的端侧图片分析翻译为提案，但不能直接返回像素、任意渲染计划、供应商 payload 或绕过目录的新能力。

提案绑定来源内容身份、当前风格基线、目录版本和幂等身份。任一身份过期时必须重新解析，不能自动合并到新状态。在“图片应用”任务中，确定性应用投影还必须绑定当前编辑状态版本并进入 `EditingCore`。同一 `StyleDefinition` 可以被“动起来”任务读取，但静态应用会话不负责切换任务或创建生成快照。

### StyleCommit

`StyleCommit` 记录已接受的定义、规范化编辑状态、稳定 `RenderPlan` 身份和来源状态版本。它只属于“应用”分支，是恢复、撤销、对比和静态导出的依据。生成分支直接从同一 `SourcePhoto` 与已确定的 `StyleDefinition` 创建自己的来源快照，不要求存在 `StyleCommit`。

## 执行流程

```text
home: choose 图片应用
  → select image
  → choose or define style
  → resolve proposal
  → validate application projection
  → render temporary preview
  → applyStyleReady
  → 应用风格
  → validate transaction and compile RenderPlan
  → render final result
  → commit or reject
```

1. 用户先在首页选择“图片应用”；presentation 固定 `creationIntent=apply`，再导入应用自有、只读来源及内容身份。
2. 现成风格直接产生提案；AI 风格定义只产生结构化提案。
3. `EditingCore` 依据唯一元操作目录完成参数、目标、能力、冲突和状态版本校验。
4. 原生渲染器以版本化临时计划执行真实预览；占位图、静态缩略图或仅更新选中态不算成功，预览成功只进入 `applyStyleReady`。
5. `applyStyleReady` 只显示“应用风格”。用户明确选择后，确定性投影才绑定当前编辑状态，校验为事务并编译最终 `RenderPlan`。
6. 最终渲染与持久化成功后一次性创建 `StyleCommit`；失败保持最后一个安全状态并返回结构化原因。
7. 本流程不显示或处理生成 CTA；用户要创作动态作品时从首页进入独立“动起来”任务，静态会话不会因此创建事务或 `StyleCommit`。

## 替换与撤销语义

- 用户选择“应用”另一个风格时，原子替换上一风格拥有的操作地址，不把两个完整风格连续叠加。
- 风格之外、明确属于来源安全或兼容迁移的状态只能按目录规则保留，不由页面猜测合并。
- 一次风格应用形成一个撤销步骤；AI 风格定义和临时预览本身不进入静态历史。
- 撤销恢复上一个完整风格状态；长按或等价入口比较只读原图，不创建历史。
- 归零、中性风格和恢复原图必须严格可复现。

## AI 与隐私

- 优先使用内置风格与本地解释能力；云端 Planner 只在真实需求存在时作为可替换 Adapter。
- 默认只发送用户文字、有限结构化分析、目录能力和状态版本；不上传原图、蒙版、人脸特征或本地路径。
- 若未来某类 AI 风格定义必须读取原图，必须另设明确授权、上传范围、删除和成本合同，不能复用静态应用的默认权限。
- AI 输出先经过与内置风格相同的定义校验和真实临时预览；只有用户选择“应用”后才进入确定性校验与原子提交。

## 失败与降级

- 不支持的能力、未知 schema、越界参数、目标失效和过期提案全部 fail closed。
- AI 不可用时仍可选择内置风格并完成静态应用与导出。
- 端侧分析失败时只允许使用明确标记为安全的风格或中性结果，不从文件名、路径或自由元数据猜测内容。
- 预览或持久化失败不得发布半应用状态；最后一个安全提交继续可见、可撤销、可导出。

## 验证合同

- 同一来源、编辑基线、`StyleDefinition`、目录版本和引擎能力生成稳定编辑状态与 `RenderPlan` ID。
- 依次应用不同风格时证明替换而非叠加，撤销恢复完整前态，重启恢复同一结果。
- AI 对抗测试覆盖未知能力、越界值、重复地址、提示注入、过期状态、取消、去重和日志隐私。
- 固定样片验证中性恒等、预览/导出同义、目标保护和不支持能力严格拒绝。
- 集成测试必须从生产首页“图片应用”入口进入，证明选图和定风格期间保持 `creationIntent=apply`、`applyStyleReady` 只显示“应用风格”，并至少完成一次真实应用、风格切换与撤销。
