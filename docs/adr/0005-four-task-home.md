# ADR 0005：四任务首页与执行分支分离

- 状态：Accepted
- 日期：2026-09-01
- 取代范围：部分取代 [ADR 0004](0004-style-first-creation.md) 中“首页只有图片应用和动起来两个入口”的 presentation 决定；ADR 0004 的静态/生成隔离继续有效。

## 背景

“图片应用”把三种不同的用户目的混成了抽象入口：想调亮清晰的人、想换审美风格的人、想处理背景或杂物的人，都要先猜测产品内部的下一步。它不利于首次选择、草稿恢复和任务级验收。

另一方面，静态本地工作和动态生成仍有不同的隐私、成本、失败和恢复语义。把四个用户任务直接等同于两个执行分支，会再次丢失用户原始目的。

## 决定

首页在选图前展示四个同级、整卡可点的任务：

| `CreationTask` | 首页文案 | 副文案 | 执行分支 |
|---|---|---|---|
| `optimize` | 优化照片 | 调亮、清晰、增强质感 | `CreationIntent.apply` |
| `style` | 换风格 | 日系、胶片、插画、电影感 | `CreationIntent.apply` |
| `cleanup` | 去背景 / 去杂物 | 抠图、白底、清理路人杂物 | `CreationIntent.apply` |
| `motion` | 做动态效果 | 让静态照片自然动起来 | `CreationIntent.motion` |

`CreationTask` 是项目持久化的用户任务身份、恢复路由和测试断言来源。`CreationIntent=apply|motion` 不再承担用户任务命名；它只决定静态本地执行和独立生成管线。任务选择必须在系统选图前固定，任务切换只能回首页。

三个静态任务共享原图只读、本地优先、非破坏、可撤销、可恢复的边界，但不共享一个笼统的用户入口：

- 优化照片只显示受支持的本地质量操作。
- 换风格使用 `StyleDefinition`、预览和“应用风格”。
- 去背景 / 去杂物当前只显示语义白底/背景处理和局部本地擦除；不声明透明 alpha 抠图，也不声明无限制生成式去物。

做动态效果继续保持独立生成任务。当前生成服务未接入，因此该路径必须显示明确不可用状态，且不得上传图片、创建远端任务、显示虚假进度或消耗额度。服务接入时另按 [派生媒体生成管线](../architecture/generation-pipeline.md) 补齐确认、成本、取消、重试和产物验证。

## 迁移

历史项目没有 `CreationTask` 时：

- `creationIntent=apply` 显式迁移为 `CreationTask.style`；
- `creationIntent=motion` 显式迁移为 `CreationTask.motion`；
- 未知或不兼容数据 fail closed，不依据图片内容、结果或用户历史猜测优化/清理任务。

迁移不得改写源图、风格快照、编辑历史、结果或生成任务身份。

## 后果

- 首页、路由、持久化、恢复、无障碍标签、Widget 测试和 `integration_test` 均以 `CreationTask` 为观察对象。
- 每个新增任务路由必须通过生产首页导航进入，并验证稳定地标、一次主操作和可见结果或不可用状态。
- 旧 `creationIntent` 的执行分支隔离继续有效：静态任务不创建生成任务；动态失败或不可用不阻断静态任务。
- 文档和发布说明不得把“做动态效果”入口写成已接入的生成服务，也不得把清理入口写成已经支持 alpha 抠图或无边界生成式移除。

## 验收

1. 首页同时显示四个清晰任务及其副文案，且任务身份在选图前固定。
2. 优化、换风格和清理分别通过生产导航得到受支持的本地静态状态；清理拒绝未支持语义。
3. 动态入口显示真实不可用且没有上传、任务或成本。
4. 冷启动恢复保留 `CreationTask`；旧 `apply` 草稿恢复为换风格。
