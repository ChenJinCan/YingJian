# ADR 0005：四任务首页、明确能力选择与执行分支分离

- 状态：Accepted
- 日期：2026-09-01
- 取代范围：取代 [ADR 0004](0004-style-first-creation.md) 中“首页只有图片应用和动起来两个入口”以及动态任务复用风格定义的 presentation 决定；ADR 0004 的本地应用/派生生成隔离继续有效。

## 背景

“图片应用”把三种不同的用户目的混成了抽象入口：想调亮清晰的人、想换审美风格的人、想处理背景或杂物的人，都要先猜测产品内部的下一步。它不利于首次选择、草稿恢复和任务级验收。

另一方面，静态本地工作和动态生成仍有不同的隐私、成本、失败和恢复语义。把四个用户任务直接等同于两个执行分支，会再次丢失用户原始目的。

## 决定

首页在选图前展示四个同级、整卡可点的任务：

| `CreationTask` | 首页文案 | 副文案 | 执行分支 |
|---|---|---|---|
| `optimize` | 优化照片 | 调亮、清晰、增强质感 | `CreationIntent.apply` |
| `style` | 换风格 | 日系、胶片、插画、电影感 | `CreationIntent.apply` |
| `cleanup` | 去背景 / 去杂物 | 抠图、白底、清理路人杂物 | `CreationIntent.apply` |
| `motion` | 做动态效果 | 让静态照片自然动起来 | `CreationIntent.motion` |

`CreationTask` 是项目持久化的用户任务身份、恢复路由和测试断言来源。`CreationIntent=apply|motion` 不再承担用户任务命名；它只决定静态或动态页面，不表示本地/云端，也不构成能力、上传、生成或费用授权。任务选择必须在系统选图前固定，任务切换只能回首页。

选图后，每个任务以固定产品顺序完整展示自己的具名 `CreationCapability`，初始没有默认选择：

- 优化照片：自然优化、AI 修复、高清放大、老照片修复；
- 换风格：官方风格、文字定风格、语音定风格、参考图风格、AI 风格重绘；
- 去背景 / 去杂物：人物白底、透明抠图、替换背景、去路人、涂抹去物；
- 做动态效果：轻微动态、镜头推进、光影流动。

四张卡片只确定任务。只有用户点击的 `CreationCapability` 才授权进入该能力的后续路径；图片分析、AI、历史、设备或供应商状态不得替用户预选、推荐、排序、突出、组合、替换、降级或执行能力。分析和质量门只能批准或拒绝用户已选能力；拒绝时保留当前状态，由用户决定下一步。

三个静态任务共享原图只读、非破坏、可恢复的结果边界，但不共享一个笼统入口，也不都等同于本地执行。生成式静态能力必须在自身路径再次确认上传、成本、取消与删除；未实现能力保持独立不可用，不能由本地近似结果冒充。

做动态效果继续保持独立生成任务，不要求先定风格或完成静态结果。当前生成服务未接入，因此三个动态方向都必须显示明确不可用状态，且不得上传图片、创建远端任务、显示虚假进度或消耗额度。服务接入后，用户先选择一个方向，再由“生成动态照片”和后续确认创建任务；具体按 [派生媒体生成管线](../architecture/generation-pipeline.md)执行。

## 迁移

历史项目没有 `CreationTask` 时：

- `creationIntent=apply` 显式迁移为 `CreationTask.style`；
- `creationIntent=motion` 显式迁移为 `CreationTask.motion`；
- 未知或不兼容数据 fail closed，不依据图片内容、结果或用户历史猜测优化/清理任务。

迁移不得改写源图、风格快照、编辑历史、结果或生成任务身份。

## 后果

- 首页、路由、持久化、恢复、无障碍标签、Widget 测试和 `integration_test` 均同时观察 `CreationTask` 与用户点击后才存在的 `CreationCapability`。
- 每个新增任务路由必须通过生产首页导航进入，并验证稳定地标、一次主操作和可见结果或不可用状态。
- 旧 `creationIntent` 的页面分支隔离继续有效；只有用户明确选择并确认的生成式能力可以创建任务，任一失败或不可用不阻断其他独立能力。
- 文档和发布说明必须分开陈述目标能力与当前可用性，不得把能力入口或近似效果写成已经交付。

## 验收

1. 首页同时显示四个清晰任务及其副文案，且任务身份在选图前固定。
2. 选图后每个任务显示固定、完整的能力列表，进入时没有默认选中项。
3. 用户选择前没有分析后执行、上传、任务或成本；选择后只进入该能力，不自动改走其他能力。
4. 当前未实现能力显示真实不可用；三个动态方向没有上传、任务或成本。
5. 冷启动恢复保留 `CreationTask` 与已经由用户选择的能力；旧 `apply` 草稿恢复为换风格，但不得猜测具体新能力。
