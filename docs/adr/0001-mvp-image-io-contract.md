# ADR 0001：MVP 图像输入与导出合同

- 状态：Accepted
- 日期：2026-08-04
- 影响范围：照片导入、预览、原生渲染、项目恢复、导出和质量测试

## 背景

映见的核心承诺依赖预览与导出一致、原图只读和创作可恢复。当前实现复制任意选择文件，并在双端将整图解码后写成 JPEG，但没有冻结格式、尺寸、色彩和元数据语义。继续扩展图像能力会把这些差异固化到项目状态和原生接口中。

## 决策

### 输入

- 双平台必须支持 JPEG 和无动画 PNG。
- iOS 必须支持 HEIC/HEIF；Android API 28 及以上必须支持，API 24–27 不支持时提供明确的单图错误，不让项目崩溃。
- MVP 不支持 RAW、动画图片、Live Photo 和视频。
- 单张上限为 48 MP、最长边 12,000 px、文件大小 100 MB；超过任一限制时在复制和完整解码前拒绝。
- 原始输入复制到应用目录后保持只读，项目只保存相对引用和内容身份。

### 预览

- 预览从原始输入生成受控尺寸代理图，标准最长边 2,048 px，低档设备可降至 1,280 px。
- Flutter 与原生渲染边界传文件引用、版本化执行计划、区域和状态，不在实时预览交互中传完整图片字节。
- 预览和导出使用同一参数语义、方向和裁剪坐标。

### 导出

- MVP 输出为 sRGB JPEG，默认编码质量 95。
- 输出从原始输入重新执行有效静态计划，不从预览或上次导出继续处理。
- 除裁剪和用户明确变换外，保持原始像素尺寸和长宽比。
- 像素方向规范化，输出方向标记为正常。
- 保留可用的原始拍摄时间；默认移除 GPS、嵌入缩略图、设备 MakerNote、人脸区域和应用内部编辑信息。
- 透明 PNG 输入在 JPEG 导出时以白色背景合成；预览必须呈现相同结果。
- 一次导出失败不撤销此前已经成功写入系统相册的结果。

### 色彩

- sRGB 是 MVP 保证支持的输入和输出闭环。
- Display P3 输入必须被识别并正确转换到 sRGB 后才能进入正式 MVP；在固定样片验证完成前，广色域保真状态为 `待验证`，不得宣称支持 P3 高保真导出。

## 取舍

- 统一 sRGB JPEG 降低双端差异和首版测试范围，但不提供无损导出、透明输出或广色域输出。
- 48 MP 能覆盖现代手机照片，但要求预览降采样、导出受控内存或分块处理；当前 Android 整图双 Bitmap 路径不满足该合同。
- 默认剥离敏感元数据提高隐私安全，但需要明确保留拍摄时间的跨端实现和测试。

## 被拒绝的方案

- **沿用任意输入、JPEG 100 输出**：没有明确兼容和隐私语义，且 JPEG 100 仍不是无损。
- **MVP 同时输出 HEIF/P3/PNG**：显著扩大跨端编码、元数据和商店设备验证范围，不能帮助验证核心用户任务。
- **从预览截图导出**：无法满足原像素尺寸和预览/导出一致性。

## 验证要求

- 固定样片覆盖 JPEG、PNG、HEIC/HEIF、EXIF 旋转、sRGB、Display P3、12 MP 和 48 MP。
- 双端 Profile/Release 物理设备验证方向、尺寸、色彩、元数据、内存和耗时。
- 在合同通过前，现有导出只能视为开发演示。
