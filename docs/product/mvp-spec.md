# 映见 MVP Spec

> 状态：engineering-candidate / acceptance-pending；版本：1.6；日期：2026-08-10；首发平台：iOS / TestFlight。

本文件是 MVP 用户行为、P0 范围和验收条件的唯一规范源。稳定产品策略见[产品上下文](product-context.md)，领域术语见 [`CONTEXT.md`](../../CONTEXT.md)，开发时序见[功能优先工作流](../agents/development-validation-workflow.md)，当前候选身份和开放门禁见[状态快照](mvp-session-handoff-2026-08-10.md)。

## 产品结果

映见帮助用户把一张或一组已有照片修得自然、统一、适合发布，而不要求用户先学习专业工具。

核心承诺是：

> 一张精修，整组好看。

用户无需登录即可导入 1–6 张照片。应用在本地分析基础质量、主体、人脸和光线，给出三套差异明确的本地推荐。用户先选择方向，再调整整组强度，或进入重点照片完成构图、光色、滤镜、画质改善、人像精修、塑形和简单局部处理，最后从只读原图批量导出。

默认闭环完全本地执行，不上传照片、不创建云端图片任务、不依赖生成式 AI，也不因 Android 尚未验证而阻断 iOS MVP。

## 主旅程

```text
导入 1–6 张已有图片
    → 本地分析或安全回退
    → 查看并选择三套本地推荐
    → 调整整组共享风格
    → 精修重点照片
    → 逐张检查
    → 从原图批量导出
```

一次成功会话必须满足：

1. 至少一张有效照片完成导入。
2. 显示三套可用推荐，分析失败时显示三套安全回退方案。
3. 用户主动选择一个方向，并可继续手动调整。
4. 编辑可撤销、重做、归零并在项目恢复后保持语义。
5. 至少一张照片从原图成功导出，且不覆盖原图。
6. 默认流程创建的云端图片任务为零。

## 首发边界

- 首发只验收 iOS 和 TestFlight；Flutter 领域模型保持跨平台，Android 代码保留但不计入本轮完成门。
- 输入以相册中的已有静态图片为主；相机、视频和实时美化不阻断本轮 MVP。
- 生成式 AI、账号和付费基础设施不属于默认闭环。
- MVP 输出改善已有像素，不承诺生成原图中不存在的细节。

## P0 功能范围

### 照片项目

- 导入 1–6 张受支持图片，为每张创建应用自有只读副本。
- 支持删除、排序、重点照片选择、项目删除和应用重启恢复。
- 单项损坏或不支持时隔离失败，不让整个项目崩溃。
- 项目保存版本化配方、共享风格、逐张补偿、单张覆盖、蒙版和导出状态，不保存重复完整原图。

### 本地分析与三套推荐

- 端侧分析方向、尺寸、曝光、白平衡、清晰度、主体和人像适用性。
- 分析失败时稳定回退，不阻断编辑和导出。
- 从 12–18 套人工调校配方中生成“自然干净、氛围色彩、质感风格”三个可区分方向，不能只是同一效果的强弱版本。
- 推荐只写入已声明、范围合法的配方参数，不执行任意脚本或隐藏效果。

### 构图、光色、滤镜与 HSL

- 构图：自由/比例裁剪、旋转、水平与垂直翻转、水平校正、克制的水平/垂直透视和恢复原始构图。
- 光色：曝光、高光、阴影、对比度、色温、色调、饱和度和清晰度。
- 滤镜：至少 12 套冻结预设，结果可预览、强度可调、可归零；滤镜不是推荐方案的别名。
- HSL：红、橙、黄、绿、青、蓝、紫、洋红八个通道的色相、饱和度和明度。
- 每项参数都有合法范围和中性值，并支持序列化、撤销、恢复和预览/导出同义性。

### 画质改善

- 结果入口“一键改善画质”只把安全推荐值写入去噪、暗光提亮、去灰和细节锐化四个真实参数。
- 四项均为 `0...100`，`0` 严格关闭，可独立调整、归零和撤销。
- 去噪保护边缘；暗光提亮保护高光；去灰避免明显压黑或过饱和；锐化避免白边、黑边和噪声放大。
- 首版不做超分辨率、生成式细节重建或人脸生成修复。

### 人像自然美化

- 首层提供“一键自然美化”，并可展开为质感磨皮、肤色与面部光线、瑕疵减弱三个真实参数。
- 一键操作只写入这三个参数，不形成隐藏渲染层，也不自动开启几何塑形。
- 质感磨皮减少粗糙和不均匀，同时保留毛孔趋势、五官、发际线、胡须和身份纹理。
- 肤色与面部光线改善色偏、暗沉和阴影，但不漂白或破坏场景光线。
- 瑕疵减弱只处理高置信度、孤立、短期性的小范围痘印和色斑；无法区分痣、雀斑、皱纹、妆容或身份细节时跳过。
- 非几何处理最多覆盖三张高置信度人脸；单个低置信度对象只关闭自身能力，不阻断其他人物、基础编辑或导出。

### 面部与身体塑形

- 最多三张可用人脸支持画面内逐脸选择，并独立保存瘦脸、小头、下颌、下巴、大眼、鼻形和嘴形参数。
- 可用身体主体支持目标选择，并独立保存整体瘦身、增高、肩、腰和腿部参数。
- 所有几何参数默认值为 `0`，只在用户显式操作后改变；应用不做年龄或性别推断。
- 几何处理必须约束目标区域，保护非目标人物、五官、四肢和背景；不适用时关闭对应工具，不阻断其他编辑或导出。

### 局部与背景

- 提供端侧主体分割、背景虚化、纯色/用户图片背景、局部光色和传统消除。
- 主体与局部蒙版可见、可添加、可擦除、可恢复、可撤销并随项目保存。
- 空蒙版严格无效果；首版不承诺发丝级 Alpha Matting、复杂内容生成或无痕文字重绘。

### 整组一致性

- 整组共享审美方向，每张照片根据自身曝光、白平衡、肤色和安全性计算逐张补偿。
- 用户始终知道当前编辑作用于“整组”还是“当前照片”。
- 单张覆盖叠加在共享风格和逐张补偿之上；同步或重置不能意外破坏其他层。
- 用户可以往返重点照片精修与整组检查，不丢失位置或状态。

### 导出

- 从每张只读原图重放有效配方，不连续重编码，也不把预览截图作为结果。
- 使用有界并发，显示逐张进度和 saved/failed/cancelled 等独立终态。
- 取消只阻止尚未进入不可逆平台保存的任务；部分成功保留，失败项可独立重试。
- 输出格式、尺寸、方向、色彩、压缩和隐私元数据遵守图像 I/O 合同。

### 信任与无障碍

- 首次导出无需账号，不把基础编辑锁在登录或付费墙之后。
- 默认不上传照片、人脸特征、蒙版或自由文本；普通日志和遥测不得包含这些内容。
- Analytics、Crashlytics 和 Performance 仅在用户开启匿名诊断后工作，关闭后立即停止。
- 关键控件满足 44pt 交互目标、VoiceOver 语义、动态字体和非颜色唯一表达。
- 加载、空态、错误、取消、恢复、权限和离线状态都有明确结果与下一步。

## 移动端体验合同

- 首页只突出“开始修图”和最近项目，不展示桌面式工具面板。
- 编辑页以照片为视觉中心，一级工具按构图、调色、滤镜、画质、人像、局部组织。
- 当前照片、总张数、整组/当前范围、撤销、重做、前后对比和导出持续可发现。
- 多人照片直接在画面中选择脸或身体目标，工具面板持续显示当前目标。
- 推荐、滤镜、背景和导出选项提供结果缩略预览，不只展示文字名称。
- 导出结束页区分全部成功、部分失败、取消和分享结果。

最终移动端结构仍需五名目标用户在同一冻结候选上完成无引导验证。自动测试或设计偏好不能代替该决策。

## 工程合同

- Flutter 负责 UI、项目状态、配方、撤销/恢复和任务编排；原生层负责高频像素处理、Texture 预览和原图导出。
- Flutter 与原生层只传路径、版本化参数、区域、进度和结果状态；滑块期间不往返传输完整图片字节。
- 所有效果进入同一套可序列化、可预览、可撤销、可复现的配方；`0` 对所有参数严格表示无效果。
- 预览与导出使用相同版本和参数语义，原图始终只读。
- 本地算法、系统 API、商业 SDK 和云端能力都位于供应商无关接口之后。

详细实现结构由 `docs/architecture/` 和 ADR 负责；图像阈值、样片、设备与人工量表由[质量基线](../quality/mvp-quality-baseline.md)负责。

## 验收条件

### 功能与状态

- 单张和 2–6 张项目都能完成同一主旅程。
- 三套推荐、安全回退、整组/单张层级、项目恢复和批量终态均可观察且可复现。
- 所有 P0 用户入口都连接真实配方、原生预览和原图导出，不以占位 UI 或测试替身宣称完成。

### 图像与人像

- 中性配方不产生可见修改，预览与导出保持同一语义。
- 固定样片通过方向、尺寸、裁剪、色彩、确定性、压缩和预览/导出回归。
- 画质改善四项和六项核心人像能力分别通过自身质量门；综合高分不能抵消任一失败。
- 人像结果保持身份、纹理、五官、非目标人物和背景；灾难性错误为零。
- 整组结果比机械复制同一绝对参数更一致，同时保留单张自然性。

### 性能、设备与真人

- Flutter UI 在预览和导出期间保持响应。
- 冻结候选通过要求的 Profile/Release 或 TestFlight 物理设备矩阵、性能、内存、温控、PhotoKit、分享和生命周期门。
- 同图竞品盲评、至少五人无引导可用性和最终人工签字全部绑定同一候选身份。
- 模拟器和自动工程门通过只表示工程验证完成，不替代最终真机与真人验收。

### 隐私与成本

- 默认主旅程断网可用，创建零个云端图片任务。
- 关闭匿名诊断后不再发送诊断事件。
- 删除项目会删除应用内副本、配方、蒙版和相关缓存。
- 云端失败或不可用不会破坏本地编辑结果。

## 不在本轮范围

- 相机拍摄、实时美化、视频、Live Photo 完整编辑和 Android 验收。
- 文字、贴纸、边框、涂鸦、拼图、长图、模板、曲线和 LUT 导入。
- 妆容、发型、发色、发量和自由液化。
- 超分、去模糊、人脸生成修复、AI 扩图、生成式消除和语义换装。
- 账号、订阅、权益、云端任务编排、App Review 和公开发布。

## 实施与退出顺序

1. 冻结当前功能切片的用户结果、参数语义和可观察验收条件。
2. 完整实现 domain、UI、原生执行、持久化、撤销/恢复和导出闭环，并补齐窄测试。
3. 功能切片完整后集中运行 iOS Simulator 正式导航和集成路径。
4. 重复上述过程，直到全部 P0 功能完成并通过完整自动工程门。
5. 冻结源码、版本、build、配置和产物身份。
6. 最后集中运行真机、同图竞品、盲评和无引导可用性验收。
7. 真机发现 P0/P1 时汇总修复，重新完成模拟器回归并冻结新候选，不逐微小改动重跑完整真机矩阵。

以下情况阻断候选验收或受影响能力扩展：预览/导出语义不一致、身份或背景灾难性损坏、核心能力无法达到可见且自然的结果、用户无法理解整组/当前照片范围、默认流程必须上传照片，或目标设备无法满足冻结预算。
