# 映见风格创作 MVP Spec

> 状态：目标 MVP 交付合同。文中单独标出的“当前二进制”只记录现状，不把目标能力写成已经交付。稳定产品方向见 [产品上下文](product-context.md)，风格语义见 [风格系统](style-system.md)。

## 1. 产品边界

MVP 从首页的四个清晰任务开始。用户先选择任务，再在任务内选择图片和完成当前任务所需的操作：

```text
首页
├─ 优化照片 → 选图片 → 用户选自然优化 / AI 修复 / 高清放大 / 老照片修复 → 静态结果
├─ 换风格 → 选图片 → 用户选官方风格 / 文字定风格 / 语音定风格 / 参考图风格 / AI 风格重绘 → 静态结果
├─ 去背景 / 去杂物 → 选图片 → 用户选人物白底 / 透明抠图 / 替换背景 / 去路人 / 涂抹去物 → 静态结果
└─ 做动态效果 → 选图片 → 用户选轻微动态 / 镜头推进 / 光影流动 → 生成动态照片
```

任务选择发生在选图前；具体能力选择发生在选图后、任何处理前。`CreationTask=optimize|style|cleanup|motion` 是持久化的用户任务身份；任务内还必须保存用户明确选择的稳定 `CreationCapability`。`CreationIntent=apply|motion` 只区分静态结果与动态结果，不代表本地或云端：`optimize`、`style`、`cleanup` 映射为静态 `apply`，`motion` 映射为独立 `motion`。旧 `apply` 草稿迁移为 `style`，不得重写它的来源、风格或结果。

四张卡片只确定任务，不授权任务内的任何具体能力。任务页按固定产品顺序完整展示该任务的明确选项，不预选、不推荐、不根据图片、分析、历史或设备改变顺序。图像分析、AI、Vision 与质量检查只能验证用户已选能力能否执行，不能替用户选择、组合、切换或触发能力。

目标 MVP 的任务内选择固定为：

| 任务 | 用户明确选择的能力 | 结果合同 |
|---|---|---|
| 优化照片 | 自然优化、AI 修复、高清放大、老照片修复 | 每次只执行一个明确选择的静态能力 |
| 换风格 | 官方风格、文字定风格、语音定风格、参考图风格、AI 风格重绘 | 用户先选输入或结果类型，再确认具体风格 |
| 去背景 / 去杂物 | 人物白底、透明抠图、替换背景、去路人、涂抹去物 | 每次只执行一个明确选择的清理能力 |
| 做动态效果 | 轻微动态、镜头推进、光影流动；“生成动态照片”是确认后的主操作 | 用户必须先选一个动态方向，再主动创建任务 |

“定风格”只属于换风格任务；文字、语音和参考图只是用户主动选择后的输入方式。做动态效果由用户明确选择动态方向。优化和清理使用结果导向的能力名称，不进入传统工具模式，也不会让用户在执行中重新选择任务。

用户界面只呈现图片、任务、结果与当前状态。传统通用编辑器、“自己调”、工具分类、参数滑杆、三套推荐、整组范围和批量任务不属于本产品合同，也不保留占位入口。底层参数只作为不可见、经过校验的执行语言。

当前代码交付以下本地路径：

- **优化照片**：调亮、清晰、增强质感；
- **高清放大**：iOS 本地 2×/4× 高质量重采样，从只读原图生成新文件；它保留已有细节，但不宣称生成不存在的 AI 细节；
- **换风格**：官方风格，以及用户明确选择后的有界本地文字、语音和参考图风格；
- **去背景 / 去杂物**：iOS 人物场景支持人物白底、透明抠图和用户选择本地图片替换背景；三项都必须先由用户明确选择，才分析人物适用性并显示对应预览和主操作。
- **做动态效果**：iOS 本地生成整图轻微平移缩放、镜头推进或光影流动的 H.264 MP4；另有用户独立选择并确认上传与费用后的云端“AI 自然动效”。云端能力不覆盖、不替代或回退到三项本地动态。

本地文字和已确认语音只解释已公布的有限风格词汇；语音转写严格要求 Apple 端侧识别，不支持时明确失败。参考图只在设备上从 48 × 48 缩略图提取有界色彩、明暗、对比和整体质感标量，不保留或复制人物、对象、文字和构图内容，也不等同完整风格迁移。

当前透明结果强制使用 PNG；iOS 缺少可靠的语义人物 matte 时明确失败，不以 body fallback 冒充透明结果。当前替换背景只使用用户单独选择、存入应用资源目录的本地图片，不生成背景、不上传原图，也不把参考内容当作风格。

六项云端能力已有固定的第一方网关合同：AI 修复使用百度 `image_definition_enhance`，AI 风格重绘使用阿里 `wan2.7-image`，去路人和涂抹去物使用用户手绘 Mask 驱动的阿里 `wanx2.1-imageedit`，老照片修复使用火山 `LensOpr`，AI 自然动效使用阿里 `wan2.6-i2v-flash` 生成 3 秒 H.264 MP4。网关部署在 Cloudflare Global Network，供应商调用位于中国大陆区域；这不等于 Cloudflare 中国大陆节点或大陆稳定性证明。App 不持有供应商密钥；只有安装认证、权益、配额和对应供应商配置完整后，该项能力才启用。完整参考图内容迁移、非人物通用透明抠图、生成式替换背景和任意提示词主体动画仍不在当前交付内，不能由近似能力冒充。

**做动态效果** 保留独立生成任务语义。iOS 本地编码器直接使用源图与用户明确选择的三个本地方向，不要求先定风格或完成任一静态任务；“AI 自然动效”是第四个独立能力，只有用户明确选择并再次确认上传与费用后才创建云端任务，不能自动替换本地动态。

## 2. 用户结果

用户无需理解修图术语即可：

1. 在首页一眼分辨优化照片、换风格、去背景 / 去杂物和做动态效果，并选择本次任务；
2. 从系统相册选择一张受支持图片；
3. 在任务页看到该任务完整、固定顺序的明确能力选项，且没有任何默认选择或个性化推荐；
4. 主动选择一个能力；换风格任务再由用户完成所选官方、文字、语音、参考图或 AI 重绘路径，动态任务则由用户选择一个明确方向；
5. 在当前任务画布看到所选能力的可信预览、执行确认或真实不可用状态；
6. 通过当前任务唯一主操作只执行本次所选能力；需要云端时先确认上传、费用与取消边界；
7. 保存或分享已成功产出的静态或动态结果；
8. 随时返回当前任务重新选择能力，或返回首页切换任务，不破坏原图和既有成功结果。

## 3. 稳定界面

### 3.1 首页

- 无创作记录时，品牌价值之后展示四个面积足够、同级清晰的大入口：**优化照片**（调亮、清晰、增强质感）、**换风格**（日系、胶片、插画、电影感）、**去背景 / 去杂物**（抠图、白底、清理路人杂物）和 **做动态效果**（让静态照片自然动起来）。
- 每个入口用结果名称和视觉示例说明会得到什么，不用工具名称解释实现方式；点击入口后才打开该任务的选图流程。
- 有创作记录时，最近记录明确标记所属任务；继续记录不会掩盖四个新建任务入口。
- 最近记录显示源图缩略图、任务类型、当前风格名（如适用）和明确状态，例如“换风格 · 待定风格”“优化完成”“清理完成”。
- 删除仅作用于用户确认的应用内创作及其应用内结果，不删除系统相册原图。

### 3.2 优化照片页

- 图片或结果始终占据主要视觉区域。
- 首层以固定顺序展示 **自然优化、AI 修复、高清放大、老照片修复**；进入页面时不选中任何项。
- 点选能力只固定本次选择并显示对应说明、可用性与主操作，不得自动执行、上传、扣费或串联其他优化。
- 自然优化和高清放大保持本地、原图只读；AI 修复和老照片修复只在第一方网关公布该能力可用时显示执行入口，未启用时保持不可用，不能由自然优化或本地放大代替。
- 顶部只保留返回、原图对比和结果去向；临时状态就地收起，不创建工具层级。

### 3.3 换风格页

- 图片或结果始终占据主要视觉区域。
- 首层以固定顺序展示 **官方风格、文字定风格、语音定风格、参考图风格、AI 风格重绘**；进入页面时不预选输入方式或风格。
- 官方风格以可辨认的视觉样例和名称展示，不按修图工具分类。
- 用户点选文字、语音或参考图后才打开对应输入；AI 风格重绘是独立的生成式静态能力，不能由浏览、输入或预览自动触发。
- 当前文字与语音确认文本只接受有界风格词汇；不能理解时停留在当前输入，不猜测或改走官方风格。当前参考图仅形成本地光色质感聚合，不复制参考内容。
- 当前风格必须有清晰选中状态、简短说明和预览状态。

### 3.4 去背景 / 去杂物页

- 图片或结果始终占据主要视觉区域。
- 首层以固定顺序展示 **人物白底、透明抠图、替换背景、去路人、涂抹去物**；进入页面时不选中任何项。
- 人物白底、透明抠图和替换背景使用当前 iOS 本地人物分割；只有用户明确选择其中一项后才分析人物适用性，不依据分析结果替用户切换能力。
- 透明抠图的保存与分享只输出 PNG；缺少语义人物 matte 时明确失败。替换背景还要求用户主动选择一张本地背景图，选择前不导入资源，选择后也不上传或生成背景。
- 去路人和涂抹去物只有在用户亲手涂抹并确认黑白 Mask 后才可继续；第一方网关未启用时保持独立不可用。系统不得自动识别人、扩展 Mask，旧编辑器的简单邻域纹理擦除也不能冒充。
- 不支持或质量门未通过的所选操作必须明确拒绝并保留上一个安全状态；不得推荐、降级或自动切换到另一个清理能力。
- 顶部只保留返回、原图对比和结果去向；临时状态就地收起，不创建工具层级。

### 3.5 做动态效果页

- 图片或动态结果始终占据主要视觉区域。
- 首层固定展示 **轻微动态、镜头推进、光影流动**，不根据照片或风格预选、排序或推导动态方向。
- 本地编码器可用时，用户必须先点选一个方向，才显示唯一主操作“生成动态照片”；本地执行不显示上传、费用或额度确认。
- 本地编码器不可用时，每个方向显示真实不可用状态；不得自动改走云端或其他动态方向。
- 页面不显示静态任务的主操作，也不把静态结果作为生成前置步骤。

### 3.6 结果状态

- 静态应用成功后，在当前页展示已应用结果以及保存、分享、重新选择当前任务能力。
- 动态生成服务接入并成功后，在当前页展示可播放结果以及播放/暂停、保存、分享、重新选择动态方向。
- 结果页直接回首页时使用明确关闭语义；返回箭头只能回到导航层级中的上一层，不得跳级回首页。
- 动态结果播放后中央控制约 1.5 秒自动收起，点按媒体重新显示；暂停态保持播放控制可见。
- 保存成功必须明确说明写入位置；分享成功、取消或失败不改变保存成功事实。
- 设置与法律详情保持独立入口，不进入创作主路径。

MVP 不使用 Tab Bar，也不为导入、语音、参考图、生成进度或结果建立额外长期一级页面。任务切换返回首页，不在任一任务页放置另一个任务的竞争入口。

## 4. 主流程

### 4.1 选择任务与图片

1. 用户在首页点击优化照片、换风格、去背景 / 去杂物或做动态效果，系统先固定 `CreationTask`，再从它派生 `CreationIntent`。
2. 系统照片选择器一次最多选择 1 张。
3. 用户取消时安静返回首页，不创建空创作，也不显示错误。
4. 选择后，所选任务入口原位显示“正在准备图片…”，另一个入口不响应本次准备状态。
5. 系统完成格式、尺寸、方向和可读性校验，创建只读源引用与应用工作副本，并原子保存创作。
6. 准备成功后进入对应任务页的“请选择能力”状态；系统不得依据校验或分析结果预选、推荐、排序或触发任何能力。
7. 准备失败则留在首页并在原入口给出可执行恢复操作。

完成条件：对应任务页显示方向正确的完整图片和固定顺序的能力选项，没有默认选中项；原图未被修改，`CreationTask`、`CreationIntent` 与创作可在冷启动后恢复。旧 `apply` 草稿恢复为 `CreationTask.style`。

### 4.2 选择官方风格

1. 用户在换风格任务页先明确选择“官方风格”，页面才按固定策展顺序加载静态官方风格视觉样例；做动态效果不复用这条路径。
2. 初始不选中任何官方风格。用户点选一个风格后，当前项才显示选中和预览中状态。
3. 系统读取该风格的固定版本，校验适用性，并编译不可见执行方案。
4. 预览成功后替换画布结果；预览失败时保留上一次成功画面并解释原因。
5. 用户可以继续切换风格；每次切换只保留最后一次有效请求，过期结果不得覆盖新选择。

完成条件：用户能仅凭名称和视觉结果辨认当前风格，并在一次点选后看到对应预览。

### 4.3 用文字定风格

1. 用户在换风格任务页明确选择“文字定风格”。
2. 用户用一句或数句自然语言说明目标并提交。
3. 系统显示正在理解的原文；本地解释不上传，云端解释必须先说明将发送的文字、费用与取消边界，用户确认后才创建风格定义任务。
4. AI 返回结构化 `StyleDefinition`；系统完成模式、安全、能力和版本校验。
5. 定义有效时显示风格名称、简短说明和图片预览。
6. 定义含糊或能力不支持时，只提出完成当前能力所需的最少一次澄清；用户也可以返回固定能力列表并亲自选择下一步。

完成条件：用户不需要补充任何参数名，即可从原始表达得到一个可预览、可保存的风格定义。

### 4.4 用语音定风格

1. 用户在换风格任务页明确选择“语音定风格”，再主动开始录音。
2. 界面清晰显示录音中、时长和停止操作；离开、来电或权限变化必须真实停止录音。
3. 录音结束后先显示转写文本，允许用户确认或重录；需要云端转写时必须在发送音频前取得该能力内的明确确认。
4. 用户确认的转写进入与文字完全相同的风格定义流程。
5. 麦克风不可用、权限拒绝或转写失败时，保留当前图片与输入并返回固定能力列表；只有用户亲自选择文字定风格后才进入文字路径。

完成条件：语音只是表达方式，不产生独立风格类型；相同确认文本进入相同定义与校验路径。

### 4.5 用参考图定风格

1. 用户在换风格任务页明确选择“参考图风格”。
2. 系统照片选择器单独选择 1 张参考图，并明确它不会替换当前源图。
3. 选择后显示源图与参考图的角色标识，允许移除或重新选择参考图。
4. 本地分析不上传参考图；需要云端 AI 时先说明源图与参考图的用途、费用和删除边界，用户确认后才提取可迁移的色彩、光线、质感和氛围意图并形成新的 `StyleDefinition`。
5. 人物身份、具体对象、文字、水印、构图内容和受保护素材不得被当作风格复制。
6. 参考图不可读、不适用或被策略拒绝时，保留当前源图和上一次成功风格；用户可以重选当前参考图，或返回固定能力列表亲自选择下一步。

完成条件：用户能看懂哪张是待处理图片、哪张只是风格参考，最终结果仍以源图内容为主体。

### 4.6 应用风格

1. 用户选择官方风格、文字定风格、语音定风格或参考图风格后，只有 `CreationTask=style`、`creationIntent=apply`、当前 `StyleDefinition` 已校验且预览成功时，“应用风格”才可执行。
2. 用户点击后，系统从只读原图和当前固定风格版本应用静态结果，不增添任何未选能力。
3. 执行期间显示明确进度和取消边界；短时本地操作不制造虚假进度。
4. 成功后原子保存风格快照和静态结果身份，再展示保存与分享操作。
5. 用户返回换风格时，原图和已成功静态结果仍可恢复。

用户明确选择“AI 风格重绘”时，进入独立的静态生成合同：先主动输入并确认目标风格，再预览已冻结的生成意图，然后确认上传、费用与内容变化边界，最后由“生成风格图片”创建一次幂等任务。文本框即时值不是生成输入；空白、超过 500 个可见字符或含隐藏/控制字符的草稿不能确认。确认后必须形成 `origin=aiRedraw` 且含 `visualIntent` 与版本身份的 `StyleDefinition`；任何后续编辑都要求用户重新确认，云端 `GenerationInput` 只从当前已确认定义构建。该路径不得由文字、语音、参考图或本地应用路径自动触发，失败时也不得降级成本地风格。

完成条件：保存的静态结果与用户确认的预览保持相同风格语义、方向和裁剪，且不包含任何未确认的生成内容。

### 4.7 优化与清理

1. `CreationTask=optimize` 进入后只展示自然优化、AI 修复、高清放大和老照片修复；用户必须先点选其中一项。
2. `CreationTask=cleanup` 进入后只展示人物白底、透明抠图、替换背景、去路人和涂抹去物；用户必须先点选其中一项。
3. 选择只固定能力身份，不自动执行。当前自然优化、iOS 2×/4× 高质量放大，以及 iOS 人物场景的人物白底、透明抠图和用户本地图替换背景已接入显式选择；透明输出固定为 PNG，替换背景还需要用户再次主动选择资源。去路人和涂抹去物必须由用户手绘 Mask；网关未启用时保持不可用，有限本地擦除不能冒充目标能力。
4. 所选能力需要云端时，必须在执行前单独确认原图或 mask 上传、处理目的、费用或权益、等待、取消与删除边界；一次确认只创建一次该能力的任务。
5. 图像分析和质量检查只能批准或拒绝所选能力，不能自动改走其他能力。拒绝、失败或取消保留源图和上一个成功状态。
6. 成功后原子保存用户选择的能力身份、执行版本和静态结果身份；重新选择另一能力必须由用户主动操作。

完成条件：用户能从任务入口主动选择并完成一项受支持能力，保存结果与可见结果一致，且不发生默认选择、隐式上传、自动串联、自动降级或重复扣费。

### 4.8 做动态效果

1. `CreationTask=motion` 固定展示轻微动态、镜头推进、光影流动和 AI 自然动效；进入时没有默认方向。
2. 用户必须主动点选一个动态方向；系统不得依据图片、风格、历史或模型能力预选、推荐或推导方向。
3. 三项本地动态只有在 `creationIntent=motion`、源图可用、本地编码器可用且用户已选该方向时才可执行；AI 自然动效还必须完成当前 Offer 的上传与费用确认。目标 MVP 不要求先定义或应用静态风格。
4. 点击后只执行所选能力并从只读原图生成新的 H.264 MP4；三项本地动态不上传、不创建云端任务或扣费，AI 自然动效只创建一次固定阿里图生视频任务，不得在失败时自动改走本地能力或其他供应商。
5. 重复点击或生命周期恢复不得同时创建多个本地结果；失败保留源图、用户选择和任何已有成功结果。
6. 成功后保存用户选择的动态方向、生成版本和本地动态结果身份，再提供预览或分享入口。

完成条件：四项能力都只由用户点击产生对应 MP4；失败不会破坏源图、用户选择的动态能力或任何已有结果。任一执行环境不可用时只禁用对应能力，不自动替代。

### 4.9 保存与分享

- 静态和动态结果分别保存，使用明确的媒体类型和系统权限说明。
- 第一次写入前解释照片权限用途；拒绝后保留结果并提供前往设置和返回创作。
- 保存过程区分可取消的结果准备与不可取消的短暂系统写入。
- 保存成功后显示“已保存到系统相册”；再次保存不得误写成仍在首次处理中。
- 分享是保存之外的独立动作；分享取消或失败不改变结果状态。

## 5. 状态模型

| 状态 | 画布 | 主操作 | 允许恢复到 |
|---|---|---|---|
| `home` | 四个任务视觉入口 | 优化、换风格、清理或动态效果 | 最近成功状态 |
| `preparingSource` | 所选任务与源图占位或缩略图 | 取消准备 | 首页 |
| `capabilityAwaitingChoice` | 原图与当前任务的固定能力列表；无默认选中项 | 用户选择一项能力 | 首页、最近成功状态 |
| `localTaskReady` | 优化或清理任务的原图与用户已选本地能力 | 执行所选本地操作 | 能力选择、最近静态成功状态 |
| `cloudStaticAwaitingConsent` | 原图、用户已选云端静态能力与费用/上传说明 | 确认或取消 | 能力选择、最近静态成功状态 |
| `styleAwaitingStyle` | 换风格任务的原图与用户已选风格输入方式 | 选择或描述静态风格 | 能力选择、最近静态成功状态 |
| `definingStyle` | 上一次成功画面 | 取消定义 | 当前任务的 awaiting 状态或上一个风格 |
| `previewingStyle` | 上一次成功画面 | 取消预览 | 当前任务的上一个风格 |
| `applyStyleReady` | 当前静态风格预览 | 应用风格 | 原图、其他静态风格 |
| `motionUnavailable` | 动态任务的当前图片、用户已选方向与不可用说明 | 返回能力列表或稍后再试当前方向 | 能力选择、首页 |
| `motionDirectionReady` | 当前动态方向说明与源图 | 服务接入后生成动态照片 | 原图、其他动态方向 |
| `applyingStyle` | 当前静态风格预览 | 按真实能力取消 | `applyStyleReady` |
| `staticReady` | 静态应用或生成结果 | 保存、分享、重新选择当前任务能力 | 能力选择、上一个静态成功状态 |
| `confirmingGeneration` | 源图、当前动态方向与任务说明 | 确认生成 | `motionDirectionReady` |
| `generatingMotion` | 生成前画面与真实进度 | 取消或后台继续 | 对应生成任务 |
| `motionReady` | 可播放动态结果 | 播放、保存、分享、换动态效果 | `motionDirectionReady` |
| `recoverableFailure` | 最后成功画面 | 重试当前能力或返回能力列表 | 失败前稳定状态 |

首页以四个同级大入口完成任务选择；进入任务后先由用户明确选择一项能力，任一时刻只突出该能力的一个主要操作。异步结果必须绑定创作 ID、`CreationTask`、`CreationCapability`、`creationIntent`、源图版本、当前能力输入版本和请求 ID；任何身份不匹配的迟到结果都不得进入当前画布或项目。

## 6. 返回、持久化与生命周期

- 返回一次只退出最内层临时状态：录音、参考图选择、风格描述、任务确认、结果播放，最后才离开当前任务页；切换任务必须返回首页重新选择。
- `CreationTask` 与静态结果在成功后原子保存；只有用户明确选择后才保存 `CreationCapability`，风格定义和动态结果（服务接入后）分别保存。旧 schema 只有 `creationIntent=apply` 的草稿必须迁移为 `CreationTask.style`，但不得猜测具体新能力；临时输入和半成品不得冒充成功状态。
- 离开当前任务页前等待正在提交的本地原子写入；写入失败时恢复最后成功快照并提供重试。
- 冷启动落在首页。继续创作时只恢复最后成功画面、用户曾明确保存的能力、当前风格快照（如适用）和可验证的任务身份。
- 正在进行的云端任务按原任务 ID 查询或订阅，不自动创建新任务。
- 无法确认远端任务身份时显示“状态待确认”，保留本地结果并提供安全刷新；不得推断成功、失败或重新扣费。
- 删除创作时停止本地引用，并按生成服务合同处理可取消任务和本地缓存；系统相册中的已保存结果不随之删除。

## 7. 失败与恢复合同

| 失败 | 必须保留 | 用户可执行恢复 |
|---|---|---|
| 图片格式、尺寸或文件读取失败 | 首页和已有创作 | 重新选择、打开系统设置 |
| 官方风格资源缺失或版本不支持 | 原图、上一个成功风格 | 刷新当前列表、返回能力列表 |
| AI 风格定义超时或无效 | 用户确认的表达、上一个成功风格 | 重试当前输入、编辑当前输入、返回能力列表 |
| 麦克风权限或转写失败 | 当前图片、用户选择和输入 | 前往设置、重录、返回能力列表 |
| 参考图读取或策略失败 | 源图、用户选择和当前风格 | 重新选择、移除参考图、返回能力列表 |
| 用户所选优化或清理能力不支持 | 源图、明确选择和上一个成功结果 | 查看原因、返回能力列表、查看原图、返回首页；系统不推荐或自动替换能力 |
| 云端静态能力取消、超时或网络中断 | 源图、用户选择、任何已有结果、任务 ID | 查询原任务、重试原任务、稍后继续；不得自动创建其他能力任务 |
| 静态应用失败 | 原图、用户选择、风格定义、上一个结果 | 重试当前应用、返回能力列表 |
| 本地动态编码器不可用或编码失败 | 源图、用户选择和所有已有结果 | 重试当前方向、返回能力列表或首页；不上传、不自动切换方向 |
| 服务接入后的生成取消、超时或网络中断 | 原图、用户选择、任何已有结果、任务 ID | 查询原任务、重试同一任务、稍后继续 |
| 生成策略拒绝 | 用户选择和所有本地成功状态 | 编辑当前能力输入、返回能力列表、换图 |
| 保存权限、空间或系统写入失败 | 应用内成功结果 | 前往设置、释放空间、再次保存 |
| 分享失败或取消 | 已生成和已保存状态 | 再次分享、返回结果 |

反馈层级固定为：轻量成功提示、可自动恢复提示、需要用户操作的内联错误、阻断当前任务的状态面、涉及删除或付费的新确认。一个事件只使用一个主要反馈表面。

## 8. 隐私、费用与安全

- 自然优化、固定官方风格、人物白底和明确标为本地的受支持能力在本地执行，不上传原图。
- 任何静态云端能力都必须由用户先明确选择，再单独确认上传内容、处理目的、费用或权益、取消和删除边界；选择卡片、选图、浏览选项或查看预览均不构成上传授权。
- 文字和经用户确认的语音转写只发送定义风格所需内容；普通日志和遥测不记录完整自由文本。
- 参考图与源图只有在当前 AI 能力确实需要且用户确认后才上传；确认中区分两者用途。
- 当前本地动态不得上传、创建网络任务或消费权益；未来新增云端主体语义动画时，必须作为独立能力在任务创建前展示上传、处理方、预计等待、结果保存和删除边界。
- 任何费用或额度在创建任务前可见。取消、失败、策略拒绝、超时和重试的扣费行为必须可解释并可核验。
- AI 服务端密钥、签名 URL、人脸特征、原图字节和完整提示不得进入普通日志、文档、截图或遥测。
- 生成输出必须经过安全与完整性检查；不合格结果不覆盖源图、当前能力输入或任何已有结果，也不得被写成已完成。
- 分析、资格检查和质量门只能拒绝当前所选能力，不能据此自动推荐、切换、组合、降级或创建另一任务。

## 9. 无障碍与简约视觉合同

- iOS 正式界面使用系统文字样式、SF Pro 与 PingFang SC 回退、语义颜色、系统导航、`PhotosPicker` 和系统分享；不以 Web 式自绘导航或导出面板替代平台行为。
- 图片是任务页的最大视觉层；风格样例、表达入口和当前任务主操作形成清晰的次级层级。
- 首页的优化照片、换风格、去背景 / 去杂物和做动态效果使用四个可独立理解、面积足够且同级清晰的大入口，不能只靠图标区分。
- 进入任一任务后，同一状态只使用一个强调主操作；静态任务页不显示动态生成操作，动态任务页不显示静态任务操作。
- 任务内能力按固定产品顺序完整展示，不根据照片、分析、用户历史、设备或服务状态重新排序；未实现项保留明确不可用状态，不隐藏后自动替换。
- 照片、任务入口和风格样例属于内容层；Liquid Glass 只用于导航、连续控制层和临时 Sheet，不铺满内容卡片。
- 点击区域至少 44×44pt；常用主操作至少 52pt 高，并有清晰按压、禁用与进行中状态。
- 支持 Dynamic Type 到最大辅助字号；浏览器原型以 2×字体近似验证。不缩小文字强塞，风格列表、说明和操作区可独立滚动，但不得遮住主要结果与返回路径。
- VoiceOver 先朗读首页四个任务入口及结果差异；进入任务后朗读任务、风格名（如适用）、选中状态、预览状态、当前唯一主操作、真实进度、不可用状态、播放状态和保存结果。
- 临时 Sheet 打开时，背景工作区不可交互，辅助功能焦点进入 Sheet；关闭后焦点回到来源控制。
- 风格选中、成功、失败和生成状态同时使用文字或形状，不只依赖颜色。
- 语音不是唯一入口；所有语音任务都有文字等价路径。参考图也不是完成任务的前置条件。
- Reduce Motion 开启时关闭非必要界面动效和动态结果自动播放；用户主动点击播放后仍可查看自己生成的动态内容。
- Reduce Transparency 开启时使用不透明、层级明确的表面。
- 生成进度通过节制的 live region 更新，不按每个百分点打断辅助技术用户。

## 10. 验收标准

### 10.1 核心旅程

- 通过生产首页分别选择四个任务，再选择一张图片并进入各自任务页；每页完整显示已确认的固定能力列表，进入时没有默认选中项、推荐槽位或自动执行。
- 用户能在优化页主动选择自然优化、AI 修复、高清放大或老照片修复；未实现项显示独立不可用，不能由自然优化代替。
- 用户能在清理页主动选择人物白底、透明抠图、替换背景、去路人或涂抹去物；两项去物要求用户手绘 Mask 和云端确认，不能由白底、自动选区或本地纹理擦除冒充。
- 透明抠图在选择前不分析图片；用户明确选择后看到本地预览并主动应用，保存与分享使用 PNG。缺少语义人物 matte 时明确失败，不能输出伪透明结果。
- 替换背景在选择前不分析或导入；用户明确选择能力后才分析人物，再主动选择本地背景图、查看预览并应用。结果保留原源图身份和所选应用资源，不创建云端任务。
- 用户在换风格页先选择“官方风格”，再点选一个具体官方风格后看到对应预览，并能通过唯一主操作应用、保存和分享静态结果。
- 用户能明确选择“文字定风格”，看到不受支持描述被拒绝，再用受支持的有界描述形成预览并通过唯一主操作应用；定义前不修改编辑结果。
- 用户先主动选择官方、文字、语音、参考图或 AI 风格重绘，再进入对应路径；任何输入方式都不会自动触发其他风格能力。
- 用户可从生产首页独立选择“做动态效果”，再选图并看到轻微动态、镜头推进、光影流动和 AI 自然动效四项固定能力；没有默认方向。三项本地能力不上传、不创建云端任务或产生成本；AI 自然动效在单独确认后只调用固定阿里模型，不支持时显示真实不可用。
- 用户在任一任务内继续操作、返回首页切换任务和冷启动恢复时，原图、`CreationTask`、用户曾明确保存的 `CreationCapability`、`creationIntent`、最后成功风格（如适用）、任何已有结果和动态任务身份（如有）保持正确；旧 `apply` 草稿恢复为换风格，但不猜测具体新能力。

### 10.2 产品边界

- 用户可见界面不存在传统通用编辑器、“自己调”、工具分类、参数滑杆、三套推荐、照片条、整组范围或批量任务；任务专属本地优化和清理不等于通用工具矩阵。
- 底层参数、能力 ID、供应商和模型信息不出现在用户文案、无障碍标签或结果状态中。
- 静态任务只有在用户明确选择 AI 修复、老照片修复、AI 风格重绘、云端清理等生成式能力并完成该项确认后，才能创建对应云端任务；其他静态能力不得创建生成任务。本地“生成动态照片”不上传、不扣费，也不覆盖原图或任何已有结果。
- 任一任务页都不显示另一个任务的主操作；切换任务只能返回首页。
- 任何分析、AI、Vision、质量评分、历史或设备能力都不能改变用户选择；能力不支持时只允许拒绝并返回能力列表，不得自动推荐、组合、降级或切换。

### 10.3 自动化与设备门

- 每个新增或替换的用户可见页面都通过正式生产导航接入同一变更的 `integration_test`。
- 集成旅程至少覆盖自然优化、高清放大、官方风格、文字定风格、人物白底、透明抠图、替换背景和一项本地动态成功路径；语音、参考图、云端确认、蒙版、取消、失败、权限与恢复通过最窄公开接缝测试。
- Widget 测试覆盖窄宽、2×字体、VoiceOver 语义、Reduce Motion 和 Reduce Transparency 的关键状态。
- 风格定义、请求身份、迟到结果、原子持久化、重复点击和重试使用确定性单元测试。
- 自动化必须证明四个任务进入时无默认能力、点击前无处理/上传/扣费、选中后只执行该能力，以及不可用时不会自动改走其他能力。
- `flutter analyze`、相关 Flutter 测试、iOS Simulator 正式导航旅程和 `git diff --check` 通过。
- 冻结候选后，Profile/Release 或精确 TestFlight build 仍需通过物理设备上的照片权限、静态任务结果、保存、分享、前后台、网络变化、性能和最终视觉验收；动态播放验收在服务接入的候选中补齐。模拟器结果不能替代该证据。
