# 映见风格创作 MVP Spec

> 状态：当前产品交付合同。稳定产品方向见 [产品上下文](product-context.md)，风格语义见 [风格系统](style-system.md)。

## 1. 产品边界

MVP 从首页的四个清晰任务开始。用户先选择任务，再在任务内选择图片和完成当前任务所需的操作：

```text
首页
├─ 优化照片 → 选图片 → 本地优化 → 静态结果 → 保存或分享
├─ 换风格 → 选图片 → 定静态风格 → 应用风格 → 静态结果 → 保存或分享
├─ 去背景 / 去杂物 → 选图片 → 语义背景或本地擦除 → 静态结果 → 保存或分享
└─ 做动态效果 → 选图片 → 定动态方向与风格 → 服务可用时确认生成 → 动态结果 → 保存或分享
```

任务选择发生在选图前。`CreationTask=optimize|style|cleanup|motion` 是持久化的用户任务身份；`CreationIntent=apply|motion` 仅是执行分支，`optimize`、`style`、`cleanup` 映射为本地 `apply`，`motion` 映射为独立 `motion`。旧 `apply` 草稿迁移为 `style`，不得重写它的来源、风格或结果。

“定风格”只属于换风格与做动态效果任务，表达方式为官方风格、文字、语音和参考图，且都生成同一种 `StyleDefinition`。优化和清理使用结果导向的本地操作，不进入不同工具模式，也不会让用户在执行中重新选择任务。

用户界面只呈现图片、任务、结果与当前状态。传统通用编辑器、“自己调”、工具分类、参数滑杆、三套推荐、整组范围和批量任务不属于本产品合同，也不保留占位入口。底层参数只作为不可见、经过校验的执行语言。

当前二进制交付三条可用的本地静态路径：

- **优化照片**：调亮、清晰、增强质感；
- **换风格**：生成可复现的静态风格结果；
- **去背景 / 去杂物**：仅限语义白底/背景处理和本地擦除，不承诺透明 alpha 抠图或无限制的生成式去物。

**做动态效果** 保留独立生成任务语义，但当前生成服务未接入：入口必须说明不可用，且不得上传图片、创建远端任务、显示虚假进度或扣费。服务接入后，它直接使用动态任务内的源图与当前风格，不要求先完成任一静态任务。

## 2. 用户结果

用户无需理解修图术语即可：

1. 在首页一眼分辨优化照片、换风格、去背景 / 去杂物和做动态效果，并选择本次任务；
2. 从系统相册选择一张受支持图片；
3. 根据任务看到本地优化、风格选择、受支持清理操作或诚实的动态服务状态；
4. 在换风格或动态任务中用点选、输入、说话或参考图确定一个风格；
5. 在当前任务画布看到可信预览或真实不可用状态；
6. 通过当前任务唯一主操作得到可用的静态结果，或在动态服务未接入时不产生任何上传与成本；
7. 保存或分享已成功产出的静态结果；
8. 随时返回当前任务继续操作，或返回首页切换任务，不破坏原图和既有成功结果。

## 3. 稳定界面

### 3.1 首页

- 无创作记录时，品牌价值之后展示四个面积足够、同级清晰的大入口：**优化照片**（调亮、清晰、增强质感）、**换风格**（日系、胶片、插画、电影感）、**去背景 / 去杂物**（抠图、白底、清理路人杂物）和 **做动态效果**（让静态照片自然动起来）。
- 每个入口用结果名称和视觉示例说明会得到什么，不用工具名称解释实现方式；点击入口后才打开该任务的选图流程。
- 有创作记录时，最近记录明确标记所属任务；继续记录不会掩盖四个新建任务入口。
- 最近记录显示源图缩略图、任务类型、当前风格名（如适用）和明确状态，例如“换风格 · 待定风格”“优化完成”“清理完成”。
- 删除仅作用于用户确认的应用内创作及其应用内结果，不删除系统相册原图。

### 3.2 优化照片页

- 图片或结果始终占据主要视觉区域。
- 首层只展示结果导向的本地质量优化和唯一主操作；不展开通用参数矩阵。
- 优化只改变亮度、清晰和质感等受支持本地语义，保持原图只读、可撤销与可恢复。
- 顶部只保留返回、原图对比和结果去向；临时状态就地收起，不创建工具层级。

### 3.3 换风格页

- 图片或结果始终占据主要视觉区域。
- 首层只展示静态风格选择、风格描述入口，以及唯一主操作“应用风格”。
- 官方风格以可辨认的视觉样例和名称展示，不按修图工具分类。
- 文字、语音和参考图共享一个首次进入即可看见的“AI 定风格”入口；用户进入后选择表达方式，不依赖横向滚动发现。
- 当前风格必须有清晰选中状态、简短说明和预览状态。

### 3.4 去背景 / 去杂物页

- 图片或结果始终占据主要视觉区域。
- 首层只提供受支持的语义白底/背景处理和局部本地擦除；它不是透明 alpha 导出、全自动抠图承诺或任意对象的生成式移除。
- 不支持或低置信度的操作必须明确拒绝或保留上一个安全状态，不能伪造清理结果。
- 顶部只保留返回、原图对比和结果去向；临时状态就地收起，不创建工具层级。

### 3.5 做动态效果页

- 图片或动态结果始终占据主要视觉区域。
- 当前服务未接入时，首层显示清晰不可用状态；不得提供可触发上传、确认、费用或额度的主操作。
- 服务接入后，首层展示适用于动态结果的方向与风格选择、描述入口，以及唯一主操作“让图片动起来”；创建任务前以紧凑确认说明上传、等待、费用或额度、取消和失败边界。
- 页面不显示静态任务的主操作，也不把静态结果作为生成前置步骤。

### 3.6 结果状态

- 静态应用成功后，在当前页展示已应用结果以及保存、分享、重新定风格。
- 动态生成服务接入并成功后，在当前页展示可播放结果以及播放/暂停、保存、分享、重新定风格。
- 结果页直接回首页时使用明确关闭语义；返回箭头只能回到导航层级中的上一层，不得跳级回首页。
- 动态结果播放后中央控制约 1.5 秒自动收起，点按媒体重新显示；暂停态保持播放控制可见。
- 保存成功必须明确说明写入位置；分享成功、取消或失败不改变保存成功事实。
- 设置与法律详情保持独立入口，不进入创作主路径。

MVP 不使用 Tab Bar，也不为导入、语音、参考图、生成进度或结果建立额外长期一级页面。任务切换返回首页，不在任一任务页放置另一个任务的竞争入口。

## 4. 主流程

### 4.1 选择任务与图片

1. 用户在首页点击优化照片、换风格、去背景 / 去杂物或做动态效果，系统先固定 `CreationTask`，再从它派生 `CreationIntent`。
2. 系统照片选择器一次最多选择 1 张。
3. 用户取消时安静返回首页，不创建空创作，也不显示错误。
4. 选择后，所选任务入口原位显示“正在准备图片…”，另一个入口不响应本次准备状态。
5. 系统完成格式、尺寸、方向和可读性校验，创建只读源引用与应用工作副本，并原子保存创作。
6. 准备成功后进入对应任务页；准备失败则留在首页并在原入口给出可执行恢复操作。

完成条件：对应任务页显示方向正确的完整图片，原图未被修改，`CreationTask`、`CreationIntent` 与创作可在冷启动后恢复。旧 `apply` 草稿恢复为 `CreationTask.style`。

### 4.2 选择官方风格

1. 换风格或做动态效果任务页加载与 `creationIntent` 兼容的官方风格视觉样例。
2. 用户点选一个风格；当前项立即显示选中和预览中状态。
3. 系统读取该风格的固定版本，校验适用性，并编译不可见执行方案。
4. 预览成功后替换画布结果；预览失败时保留上一次成功画面并解释原因。
5. 用户可以继续切换风格；每次切换只保留最后一次有效请求，过期结果不得覆盖新选择。

完成条件：用户能仅凭名称和视觉结果辨认当前风格，并在一次点选后看到对应预览。

### 4.3 用文字定风格

1. 用户打开“描述你的风格”，选择文字。
2. 用户用一句或数句自然语言说明目标并提交。
3. 系统显示正在理解的原文，创建风格定义任务。
4. AI 返回结构化 `StyleDefinition`；系统完成模式、安全、能力和版本校验。
5. 定义有效时显示风格名称、简短说明和图片预览。
6. 定义含糊或能力不支持时，只提出完成任务所需的最少一次澄清；用户也可以直接返回官方风格。

完成条件：用户不需要补充任何参数名，即可从原始表达得到一个可预览、可保存的风格定义。

### 4.4 用语音定风格

1. 用户选择语音并主动开始录音。
2. 界面清晰显示录音中、时长和停止操作；离开、来电或权限变化必须真实停止录音。
3. 录音结束后先显示转写文本，允许用户确认或重录。
4. 用户确认的转写进入与文字完全相同的风格定义流程。
5. 麦克风不可用、权限拒绝或转写失败时，保留当前图片并就地提供文字入口。

完成条件：语音只是表达方式，不产生独立风格类型；相同确认文本进入相同定义与校验路径。

### 4.5 用参考图定风格

1. 用户选择参考图方式。
2. 系统照片选择器单独选择 1 张参考图，并明确它不会替换当前源图。
3. 选择后显示源图与参考图的角色标识，允许移除或重新选择参考图。
4. AI 提取可迁移的色彩、光线、质感和氛围意图，形成新的 `StyleDefinition`。
5. 人物身份、具体对象、文字、水印、构图内容和受保护素材不得被当作风格复制。
6. 参考图不可读、不适用或被策略拒绝时，保留当前源图和上一次成功风格，并提供重新选择或改用文字。

完成条件：用户能看懂哪张是待处理图片、哪张只是风格参考，最终结果仍以源图内容为主体。

### 4.6 应用风格

1. 只有 `CreationTask=style`、`creationIntent=apply`、当前 `StyleDefinition` 已校验且预览成功时，“应用风格”才可执行。
2. 用户点击后，系统从只读原图和当前固定风格版本生成静态结果。
3. 执行期间显示明确进度和取消边界；短时本地操作不制造虚假进度。
4. 成功后原子保存风格快照和静态结果身份，再展示保存与分享操作。
5. 用户返回换风格时，原图和已成功静态结果仍可恢复。

完成条件：保存的静态结果与用户确认的预览保持相同风格语义、方向和裁剪，且不包含任何未确认的生成内容。

### 4.7 优化与清理

1. 只有 `CreationTask=optimize` 时，本地质量优化才可执行；它使用受支持的亮度、清晰和质感语义，不上传原图。
2. 只有 `CreationTask=cleanup` 时，语义背景处理或局部本地擦除才可执行；当前可用范围是语义白底/背景处理和本地擦除。
3. 清理不产生透明 alpha 抠图，也不承诺无边界的对象识别、路人移除或生成式补全；能力不支持时保持最后安全结果并解释可用替代。
4. 成功后原子保存静态结果身份；失败或取消保留源图和上一个成功状态。

完成条件：用户能从任务入口完成受支持的本地操作，保存结果与可见结果一致，且不发生隐式上传或生成。

### 4.8 做动态效果的可用性与后续合同

1. 当前生成服务未接入。`CreationTask=motion` 只能进入清楚的不可用状态，不能显示确认生成、上传、进度、费用或额度扣除。
2. 服务接入后，只有 `creationIntent=motion`、源图可用且当前 `StyleDefinition` 已校验时，“让图片动起来”才可执行。
3. 点击后先显示一次简洁任务确认，明确结果类型、预计等待、是否上传、费用或额度、取消和失败规则。
4. 用户确认后才创建唯一生成任务；重复点击、重试或生命周期恢复不得创建重复扣费任务。
5. 任务依次进入准备、上传、生成、结果处理和完成状态；不适用阶段不得伪造进度。
6. 成功后保存任务 ID、输入版本、风格版本、供应商结果身份和本地动态结果，再进入播放状态；失败或取消保留源图、当前风格和任何已有成功结果。

服务接入后的完成条件：动态结果可播放、暂停、保存和分享；失败或取消不会破坏源图、当前风格或任何已有结果，也不会静默消耗第二次额度。

### 4.9 保存与分享

- 静态和动态结果分别保存，使用明确的媒体类型和系统权限说明。
- 第一次写入前解释照片权限用途；拒绝后保留结果并提供前往设置和返回创作。
- 保存过程区分可取消的结果准备与不可取消的短暂系统写入。
- 保存成功后显示“已保存到系统相册”；再次保存不得误写成仍在首次处理中。
- 分享是保存之外的独立动作；分享取消或失败不改变结果状态。

## 5. 状态模型

| 状态 | 画布 | 主操作 | 允许恢复到 |
|---|---|---|---|
| `home` | 四个任务视觉入口 | 优化、换风格、清理或动态效果 | 最近成功状态 |
| `preparingSource` | 所选任务与源图占位或缩略图 | 取消准备 | 首页 |
| `localTaskReady` | 优化或清理任务的原图 | 执行当前本地操作 | 首页、最近静态成功状态 |
| `styleAwaitingStyle` | 换风格任务的原图 | 选择或描述静态风格 | 首页、最近静态成功状态 |
| `motionAwaitingStyle` | 动态任务的原图 | 选择或描述动态方向与风格 | 首页、最近动态成功状态 |
| `definingStyle` | 上一次成功画面 | 取消定义 | 当前任务的 awaiting 状态或上一个风格 |
| `previewingStyle` | 上一次成功画面 | 取消预览 | 当前任务的上一个风格 |
| `applyStyleReady` | 当前静态风格预览 | 应用风格 | 原图、其他静态风格 |
| `motionUnavailable` | 动态任务的当前图片与不可用说明 | 返回首页或稍后再试 | 首页 |
| `motionStyleReady` | 当前动态方向与风格预览 | 服务接入后让图片动起来 | 原图、其他动态方向或风格 |
| `applyingStyle` | 当前静态风格预览 | 按真实能力取消 | `applyStyleReady` |
| `staticReady` | 静态应用结果 | 保存、分享、重新定风格 | `applyStyleReady` |
| `confirmingGeneration` | 源图或当前动态风格预览 | 确认生成 | `motionStyleReady` |
| `generatingMotion` | 生成前画面与真实进度 | 取消或后台继续 | 对应生成任务 |
| `motionReady` | 可播放动态结果 | 播放、保存、分享、重新定风格 | `motionStyleReady` |
| `recoverableFailure` | 最后成功画面 | 重试或替代路径 | 失败前稳定状态 |

首页以四个同级大入口完成任务选择；进入任务后任一时刻只突出一个主要操作。异步结果必须绑定创作 ID、`CreationTask`、`creationIntent`、源图版本、风格版本和请求 ID；任何身份不匹配的迟到结果都不得进入当前画布或项目。

## 6. 返回、持久化与生命周期

- 返回一次只退出最内层临时状态：录音、参考图选择、风格描述、任务确认、结果播放，最后才离开当前任务页；切换任务必须返回首页重新选择。
- `CreationTask` 与静态结果在成功后原子保存；风格定义和动态结果（服务接入后）分别保存。旧 schema 只有 `creationIntent=apply` 的草稿必须迁移为 `CreationTask.style`；临时输入和半成品不得冒充成功状态。
- 离开当前任务页前等待正在提交的本地原子写入；写入失败时恢复最后成功快照并提供重试。
- 冷启动落在首页。继续创作时只恢复最后成功画面、当前风格快照和可验证的任务身份。
- 正在进行的云端任务按原任务 ID 查询或订阅，不自动创建新任务。
- 无法确认远端任务身份时显示“状态待确认”，保留本地结果并提供安全刷新；不得推断成功、失败或重新扣费。
- 删除创作时停止本地引用，并按生成服务合同处理可取消任务和本地缓存；系统相册中的已保存结果不随之删除。

## 7. 失败与恢复合同

| 失败 | 必须保留 | 用户可执行恢复 |
|---|---|---|
| 图片格式、尺寸或文件读取失败 | 首页和已有创作 | 重新选择、打开系统设置 |
| 官方风格资源缺失或版本不支持 | 原图、上一个成功风格 | 刷新风格、选择其他风格 |
| AI 风格定义超时或无效 | 用户确认的表达、上一个成功风格 | 重试、简化表达、改用官方风格 |
| 麦克风权限或转写失败 | 当前图片和风格 | 改用文字、前往设置、重录 |
| 参考图读取或策略失败 | 源图和当前风格 | 重新选择、移除参考图、改用文字 |
| 本地优化或清理能力不支持 | 源图、上一个成功结果 | 选择受支持操作、查看原图、返回首页 |
| 静态应用失败 | 原图、风格定义、上一个结果 | 重试应用、换风格 |
| 动态服务未接入 | 源图、风格和所有已有结果 | 返回首页、稍后再试；不上传、不创建任务、不扣费 |
| 服务接入后的生成取消、超时或网络中断 | 原图、风格、任何已有结果、任务 ID | 查询原任务、重试同一任务、稍后继续 |
| 生成策略拒绝 | 所有本地成功状态 | 修改风格描述、换图、保留当前风格与已有结果 |
| 保存权限、空间或系统写入失败 | 应用内成功结果 | 前往设置、释放空间、再次保存 |
| 分享失败或取消 | 已生成和已保存状态 | 再次分享、返回结果 |

反馈层级固定为：轻量成功提示、可自动恢复提示、需要用户操作的内联错误、阻断当前任务的状态面、涉及删除或付费的新确认。一个事件只使用一个主要反馈表面。

## 8. 隐私、费用与安全

- 优化照片、换风格和去背景 / 去杂物的受支持本地操作默认本地执行，不上传原图。
- 文字和经用户确认的语音转写只发送定义风格所需内容；普通日志和遥测不记录完整自由文本。
- 参考图与源图只有在当前 AI 能力确实需要且用户确认后才上传；确认中区分两者用途。
- 当前动态服务未接入，入口不得上传、创建任务或消费权益；服务接入后才在任务创建前展示上传、处理方、预计等待、结果保存和删除边界。
- 任何费用或额度在创建任务前可见。取消、失败、策略拒绝、超时和重试的扣费行为必须可解释并可核验。
- AI 服务端密钥、签名 URL、人脸特征、原图字节和完整提示不得进入普通日志、文档、截图或遥测。
- 生成输出必须经过安全与完整性检查；不合格结果不覆盖源图、当前风格或任何已有结果，也不得被写成已完成。

## 9. 无障碍与简约视觉合同

- iOS 正式界面使用系统文字样式、SF Pro 与 PingFang SC 回退、语义颜色、系统导航、`PhotosPicker` 和系统分享；不以 Web 式自绘导航或导出面板替代平台行为。
- 图片是任务页的最大视觉层；风格样例、表达入口和当前任务主操作形成清晰的次级层级。
- 首页的优化照片、换风格、去背景 / 去杂物和做动态效果使用四个可独立理解、面积足够且同级清晰的大入口，不能只靠图标区分。
- 进入任一任务后，同一状态只使用一个强调主操作；静态任务页不显示动态生成操作，动态任务页不显示静态任务操作。
- 照片、任务入口和风格样例属于内容层；Liquid Glass 只用于导航、连续控制层和临时 Sheet，不铺满内容卡片。
- 点击区域至少 44×44pt；常用主操作至少 52pt 高，并有清晰按压、禁用与进行中状态。
- 支持 Dynamic Type 到最大辅助字号；浏览器原型以 2×字体近似验证。不缩小文字强塞，风格列表、说明和操作区可独立滚动，但不得遮住主要结果与返回路径。
- VoiceOver 先朗读首页四个任务入口及结果差异；进入任务后朗读任务、风格名（如适用）、选中状态、预览状态、当前唯一主操作、真实进度、不可用状态、播放状态和保存结果。
- 临时 Sheet 打开时，背景工作区不可交互，辅助功能焦点进入 Sheet；关闭后焦点回到来源控制。
- 风格选中、成功、失败和生成状态同时使用文字或形状，不只依赖颜色。
- 语音不是唯一入口；所有语音任务都有文字等价路径。参考图也不是完成任务的前置条件。
- Reduce Motion 开启时关闭非必要界面动效和动态结果自动播放；用户主动点击播放后仍可查看自己生成的动态内容。
- Reduce Transparency 开启时使用不透明、层级明确的表面。
- 生成进度通过节制的 live region 更新，不按每个百分点打断辅助技术用户。

## 10. 验收标准

### 10.1 核心旅程

- 通过生产首页分别选择优化照片、换风格和去背景 / 去杂物，再选择一张图片并进入各自任务页，没有中间推荐选择或工具分类页面。
- 用户能完成本地优化和受支持的清理操作；清理验证必须确认不生成透明 alpha 或未支持的生成式去物结果。
- 用户在换风格页点选一个官方风格后看到对应预览，并能通过唯一主操作应用、保存和分享静态结果。
- 用户可分别通过文字、确认后的语音转写和参考图得到有效 `StyleDefinition` 与预览。
- 用户可从生产首页独立选择“做动态效果”，再选图并看到真实的服务未接入状态；该路径证明没有上传、任务创建或成本。服务接入后再补齐创建、取消、完成、播放、保存与分享旅程。
- 用户在任一任务内继续操作、返回首页切换任务和冷启动恢复时，原图、`CreationTask`、`creationIntent`、最后成功风格、任何已有结果和动态任务身份（如有）保持正确；旧 `apply` 草稿恢复为换风格。

### 10.2 产品边界

- 用户可见界面不存在传统通用编辑器、“自己调”、工具分类、参数滑杆、三套推荐、照片条、整组范围或批量任务；任务专属本地优化和清理不等于通用工具矩阵。
- 底层参数、能力 ID、供应商和模型信息不出现在用户文案、无障碍标签或结果状态中。
- 静态任务不创建生成任务；动态服务未接入时不创建任务、不上传、不扣费；服务接入后的“让图片动起来”不覆盖原图、当前风格或任何已有结果。
- 任一任务页都不显示另一个任务的主操作；切换任务只能返回首页。

### 10.3 自动化与设备门

- 每个新增或替换的用户可见页面都通过正式生产导航接入同一变更的 `integration_test`。
- 集成旅程至少覆盖优化、换风格、清理三个静态任务和动态服务未接入状态；文字、语音、参考图、取消、失败、权限与恢复通过最窄公开接缝测试。动态生成成功路径在服务接入同一变更中补齐。
- Widget 测试覆盖窄宽、2×字体、VoiceOver 语义、Reduce Motion 和 Reduce Transparency 的关键状态。
- 风格定义、请求身份、迟到结果、原子持久化、重复点击和重试使用确定性单元测试。
- `flutter analyze`、相关 Flutter 测试、iOS Simulator 正式导航旅程和 `git diff --check` 通过。
- 冻结候选后，Profile/Release 或精确 TestFlight build 仍需通过物理设备上的照片权限、静态任务结果、保存、分享、前后台、网络变化、性能和最终视觉验收；动态播放验收在服务接入的候选中补齐。模拟器结果不能替代该证据。

## 11. 第一阶段不包含

- 传统通用编辑器、手动参数、局部工具分类和参数教学；
- 三套推荐、按分析替换推荐槽位或推荐比较页；
- 多图项目、整组一致性、批量同步和批量导出；
- 通用静态生成、透明 alpha 抠图、无限制生成式去杂物、扩图、换场景、换脸、写真和文字生图；
- 多段视频时间线、剪辑、配乐、字幕和模板工程；
- 应用内拍摄、实时美颜、直播和社区内容流；
- 让生成任务失败后静默回退为另一种结果。
