# 人像塑形纵切 Spec

Status: validation-incomplete

> 工程状态：iOS V3 配方、Vision 单脸/人体适用性、局部形变、背景保护、移动端控制、撤销/恢复以及预览/导出链路已进入 `main`。后续验证发现灰度位移纹理不能证明输出轮廓变窄，候选已改为 Metal `CIWarpKernel` 的 source-coordinate inverse warp，并新增输出轮廓回归测试。该状态只表示实现已贯通；在真实 iPhone 效果、冻结样片轮廓量化、五人盲评和三档设备门全部通过前，不得标记为质量完成。

> 决策日期：2026-08-06。用户明确指出仅有克制肤质处理不足以构成“让用户变美”的 MVP；瘦脸与瘦身从原 MVP 的排除项变更为 iOS 首发 P0。本文只定义确定性的本地几何塑形，不包含生成式换脸、妆容或五官任意重塑。

## 1. 用户结果

已有图片中的单个成人主体在满足安全条件时，可以分别调整：

- `自然精修`：肤质、肤色和面部光线，不改变几何；
- `瘦脸`：克制收窄下颌与面颊，不移动眼、鼻、嘴中心；
- `瘦身`：克制收窄躯干轮廓，不改变头部、四肢长度或身体比例。

三个能力必须是独立、可归零、可撤销的单张覆盖。三套推荐不得自动设置瘦脸或瘦身；只有用户显式操作才产生非零几何参数。

## 2. P0 范围

### 2.1 瘦脸

- 单个高置信度成人脸；正脸与轻侧脸。
- 一个 `0...100` 滑杆，默认 `0`；首轮产品最大安全强度不高于 `50`。
- 使用人脸框、轮廓和五官关键点建立局部形变场。
- 眼睛、瞳孔、鼻尖、嘴角中心不得作为收窄目标移动。
- 多人、明显侧脸、严重遮挡、关键点缺失、脸过小或背景保护失败时不可用。

### 2.2 瘦身

- 单个高置信度成人主体；肩、髋和躯干可见，人体分割与姿态结果一致。
- 一个 `0...100` 滑杆，默认 `0`；首轮产品最大安全强度不高于 `35`。
- 只调整肩以下、髋以上的躯干宽度；不改变头部、四肢长度、胸腰比例或身高。
- 多人、坐姿/遮挡导致躯干边界不完整、宽松衣物无法确定轮廓、姿态点缺失、人物分割失败或背景保护失败时不可用。

## 3. 明确不做

- 大眼、鼻形、嘴形、下巴长度、头身比和身高调整。
- 肌肉、胸部、臀部或局部部位重塑。
- 多人逐个选择、手工推脸/推身材画笔。
- 儿童塑形、年龄推断、性别推断。
- 云端人脸/人体上传、生成式补背景或身份迁移。

## 4. 版本化配方与边界

- 新增 `ImagePipelineV3`；V1/V2 语义保持不变。
- Flutter 只保存并传递 `faceSlimStrength` 与 `bodySlimStrength`，均为有限 `0...1` 数值。
- 原生会话持有人脸关键点、人体姿态、人物分割、背景风险和形变场；这些数据不得进入项目 JSON、Flutter、普通日志或遥测。
- 预览缓存分析结果，滑杆只更新形变参数；原图导出从原始文件重新分析并应用同一版本化算法。
- `0` 必须绕过对应形变并与关闭结果保持像素等价；未知版本、非法数值或能力不适用必须 fail closed。

## 5. iOS 实现候选

- 分析：Vision 人脸关键点、人体姿态与人物分割。
- 渲染：Core Image/Metal 自定义 inverse warp；不以全图 `CIPinchDistortion` 作为生产实现。
- 背景保护：在形变影响区检测人物边界外的高对比长边；无法将位移限制在冻结预算内时拒绝启用。
- 处理顺序：方向规范化 → 人像分析 → 瘦脸/瘦身几何 → 基础光色 → 自然精修 → 构图 → 预览或 JPEG 导出。

该路线是待验证候选，不因系统 API 存在就视为质量完成。

## 6. 用户交互

- 单人人脸适用时，编辑工具首屏显示 `自然精修` 与 `瘦脸`。
- 单人体态适用时显示 `瘦身`；不可用工具不显示死入口。
- 每个工具显示当前数值与归零能力，连续滑动只形成一个撤销步骤。
- 长按前后对比必须同时关闭自然精修、瘦脸和瘦身的预览效果，但不修改已保存配方。
- 项目恢复、撤销/重做和原图导出必须保留三个参数的独立语义。

## 7. 自动正确性门

- 参数解析：V3 接受三个独立人像参数；V1/V2 不改变；越界、布尔值、非有限值和未知字段拒绝。
- 零强度：`faceSlimStrength=0` 与 `bodySlimStrength=0` 分别像素恒等。
- 可见幅度：在各自产品最大安全档，冻结正样片的人脸下颌宽度应收窄 `3%...8%`，躯干中段宽度应收窄 `2%...6%`；低于下限等同“入口存在但无效果”，高于上限视为身份或比例风险。
- 单调性：冻结正样片在安全区间内，目标轮廓宽度随强度单调不增；合成轮廓测试必须直接断言渲染后的主体宽度，不能只断言参数、位移纹理或像素差异。
- 五官保护：眼中心、鼻尖和嘴中心的输出位置漂移不超过人脸宽度的 `0.5%`。
- 背景保护：人物外冻结线段的最大位移不超过输出短边的 `0.25%`，不得出现折线、重复纹理、裂缝或透明像素。
- 身体保护：头部中心、肩髋纵向位置和四肢端点纵向漂移不超过输出高度的 `0.5%`。
- 负向输入：多人、无人、遮挡、低置信度和背景高风险样片逐像素保持。
- 预览/导出：方向、形变区域、强度趋势与最终尺寸一致，原图 SHA-256 不变。

## 8. 人工质量门

- 至少 5 名评审者，原图/自然精修/低强度塑形/高安全强度/竞品结果匿名随机。
- `更好看`、`自然`、`身份保持`、`背景完整`分别评分；任一明显五官漂移、背景弯曲、身体比例异常或身份变化均为灾难性失败。
- 可改善样片对原图成对偏好率不低于 `65%`；自然、身份和背景维度中位数均不低于 `4/5`。
- 瘦脸与瘦身分别判定，不能用肤质得分掩盖几何失败。

## 9. 性能与安全门

- 复用 iOS 三档 Profile/Release 设备证据；滑杆 P95、预览帧率、峰值附加内存和温控必须满足现有设备预算。
- 分析缓存仅限当前原图与能力版本，换图、删除项目、前后台失效或内存压力后不得复用旧关键点/形变场。
- 默认离线、零云端图片任务、诊断关闭时零人脸/人体数据遥测。

## 10. 完成定义

- 同一签名 iOS 候选在真实单人人像和单人体态照片上，从已有图片导入到瘦脸/瘦身预览、撤销、项目恢复和原像素导出完整可见。
- 自动正确性、人工盲评、三档物理设备和隐私门全部通过。
- 任一塑形能力未通过时保持参数关闭并明确标记 `validation incomplete`，不得用自然精修替代。
