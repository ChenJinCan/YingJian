# 映见竞品任务基线

> 状态：当前产品决策输入；证据复核日：2026-08-31。商店功能、价格和可用性在正式对照前必须重新核验。

## 比较对象

映见不再比较工具数量，而分别比较两个从首页开始的完整创作任务：

```text
首页 → 图片应用 → 选图片 → 定静态风格 → 应用 → 得到可发布静态结果
首页 → 动起来   → 选图片 → 定动态方向与风格 → 生成 → 得到可发布动态结果
```

| 产品 | 观察角色 | 主要比较内容 |
|---|---|---|
| [醒图](https://apps.apple.com/cn/app/id1500526240) | 一键结果与全能工具基准 | 用户能否在不进入工具海洋的情况下获得可靠第一结果 |
| [Picchi](https://apps.apple.com/cn/app/id6749844980) | AI 修图师与风格基准 | 对话、风格化、批处理承诺是否真的减少决策 |
| [RoboNeo](https://apps.apple.com/cn/app/id6746737125) | 一句话图片/视频生成基准 | 生成意图、任务状态、结果恢复和费用透明度 |
| [美图秀秀](https://apps.apple.com/cn/app/id416048305) | 静态、Live 与视频综合基准 | 静态到动态的能力分层与用户心智成本 |
| Berry | 少量强风格基准 | 风格辨识、切换速度与结果稳定性 |

官方页面只能证明公开承诺，不能证明当前账号、设备、会员状态、实际质量或底层实现。正式结论必须来自同版本、同设备、同输入的实际操作。

## 五项比较任务

### 1. 选择任务入口

- 用户能否在首页一眼区分“图片应用”和“动起来”的结果差异；
- 两个入口是否具有足够面积和清晰结果示例，而不是挤在同一个操作栏；
- 进入任务后是否只出现当前任务的主操作，切换任务是否回到首页。

### 2. 选图片

- 从启动到成功选择照片需要多少决策；
- 取消、权限拒绝和导入失败是否可恢复；
- 用户是否被模板、社区、工具或营销入口分流。

### 3. 定风格

- 用户能否从官方风格、自然语言、语音或参考图快速表达想要的感觉；
- 风格是否有清楚名称、差异和适用范围；
- AI 是否只返回聊天文字，还是形成可预览、可复用的稳定风格定义。

### 4. 图片应用

- 用户是否理解应用会保留源照片内容与结构；
- 第一结果是否可以直接发布；
- 切换风格是否替换结果，而不是累积未知效果；
- 是否仍需进入传统工具补救。

### 5. 动起来

- 用户是否在执行前理解会创建新作品、需要等待并可能消耗权益；
- 图片动起来后，身份、主体、风格与时间连续性是否稳定；
- 取消、失败、后台恢复和旧结果管理是否可信；
- 生成失败后，源图、当前风格和任何已有结果是否完整保留。

## 映见的竞争命题

“一键”“AI 修图”和“照片动起来”都已经是常见功能名称，单独存在不构成优势。映见要验证的是一个更窄的命题：

> 用户先在首页选择“图片应用”或“动起来”，再在一条没有竞争任务的路径中用风格语言得到结果；整个过程中无需学习传统修图工具。

因此映见必须同时做到：

1. 首页以两个大入口清楚区分静态与动态结果任务；
2. 每条路径独立完成选图、定风格和结果，只保留一个当前主操作；
3. 风格定义在内部可复用官方风格、用户描述和参考图语义，但不会让用户在定风格后再次选择任务；
4. 静态应用即时、稳定、可复现；
5. 动态生成保持人物、主体与风格连续；
6. 用户始终只需要理解任务、照片、风格和结果。

## 当前不竞争

- 曝光、曲线、HSL、图层、蒙版等专业工具覆盖；
- 海量贴纸、字体、模板、社区和内容运营规模；
- 完整视频剪辑、时间线、音频和直播；
- RAW 工作流和桌面级精修；
- 以换脸、身份替换或批量生成素材为默认入口。

这些能力可以作为内部执行材料或未来独立任务存在，但不能重新成为主导航。

## 正式对照

- 使用同一冻结映见候选、同一源照片、同一物理设备和相同风格任务；
- 记录竞品身份、版本、会员状态、路径、等待、费用、导出规格和文件哈希；
- 静态结果与动态结果分别匿名评审；
- 比较首次正确点击、任务完成时间、结果偏好、身份保持、风格连续和失败恢复；
- 没有实测时保持 `数据缺失`，不以商店截图或功能名称推断胜负。

正式门槛见 [MVP 质量基线](../quality/mvp-quality-baseline.md)。
