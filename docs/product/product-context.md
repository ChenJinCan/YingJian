# 映见产品上下文

> 状态：稳定产品策略；具体术语以 [`CONTEXT.md`](../../CONTEXT.md) 为准，MVP 范围以 [MVP Spec](mvp-spec.md) 为准，当前工程与候选状态以 [状态快照](mvp-session-handoff-2026-08-10.md) 为准。

## 产品身份

- 品牌：映见。
- Slogan：让变美更容易。
- 品类：以本地图像处理引擎为核心的移动端智能修图应用。
- 核心承诺：一张精修，整组好看。
- 产品优先级：本地修图质量、单张精修、整组一致性、智能配方、可选生成式 AI。

## 用户问题

目标用户准备发布一张或一组照片时，知道自己想要自然、干净、有氛围的结果，但不想学习专业修图流程，也不想对每张照片重复试工具和参数。

映见完成的是“选择方向、精修重点照片、统一整组、可靠导出”的完整任务。三套推荐只是低决策入口，不是产品本身；传统参数、文字和语音必须汇入同一套可序列化、可撤销、可复现的编辑配方。

## 第一目标用户与场景

目标用户资格定义版本：`first-target-user-v1`

正式无引导可用性证据中的参与者必须由观察者确认同时满足：

- 经常使用手机拍照；
- 会一次发布多张照片；
- 希望获得高质量结果，但不想学习专业修图流程；
- 愿意从可靠结果开始做少量微调。

- 经常使用手机拍照并一次发布多张照片。
- 对结果有要求，但希望从可靠结果开始，只做少量微调。
- 旅行、聚会、探店后整理 2–6 张照片。
- 同组照片光线不同，需要统一氛围，同时精修其中一张重点照片。

上述资格定义用于选择验证对象，不代表相关市场需求已经成立；需求仍由冻结候选上的无引导可用性测试验证。

## 固定产品原则

### 最高交互原则

用户真正要完成的任务只有：

```text
提供图片 → 说明修改方向 → 看见修改结果
```

所有 UI、页面、弹窗和功能入口都必须优先缩短这条路径：

1. 尽量减少用户操作、选择、确认和专业概念；能由系统安全推断的内容不要求用户先配置。
2. 图片始终是界面视觉主体；修改方向优先用自然语言、直接结果和少量高频建议表达。
3. 过程必须清晰且高可见：当前照片、处理中状态、修改是否生效、修改后的结果、撤销和保存必须容易发现。
4. 专业参数、人物目标、整组范围和异常细节只在当前任务确实需要时渐进展开，不与主任务争夺注意力。
5. 任何新增 UI 若不能让用户更快、更清楚地完成“给图、说方向、得结果”，默认不进入主流程。

### 质量与工程原则

1. 本地修图质量优先于功能数量。
2. 单张精修是竞争入场能力，整组一致性是差异化能力。
3. 用户先看到结果，再按需展开工具。
4. 自动处理必须可理解、可减弱、可归零、可撤销和可复现。
5. 原图只读，最终结果从原图重放有效配方。
6. 整组共享审美方向，每张照片保留独立补偿和单张覆盖。
7. 默认推荐完全本地执行，不上传照片或创建云端生成任务。
8. 生成式 AI 只能作为用户主动选择的增强层，失败不得破坏本地编辑结果。
9. 导出、项目恢复、隐私和图像保真属于核心闭环。

## 当前不服务

- 专业图层、通道、RAW 和复杂曲线工作流。
- 实时直播美颜和视频剪辑。
- 以 AI 写真、换脸或虚拟角色生成为核心的产品路径。
- 当前 iOS MVP 之外的 Android 交付、相机实时预览和视频处理。
