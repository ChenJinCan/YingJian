# 映见产品上下文

> 状态：稳定产品北极星。当前交付范围与验收以 [MVP Spec](mvp-spec.md) 为准，风格定义与执行语义以 [风格系统](style-system.md) 为准。

## 产品身份

- 品牌：映见。
- Slogan：让变美更容易。
- 品类：以风格为核心的 AI 图片创作应用。
- 唯一心智：**先选任务，再完成任务**。首页有四个直接可理解的入口。
- 优化照片：**优化照片 → 选图片 → 本地优化 → 静态结果**（调亮、清晰、增强质感）。
- 换风格：**换风格 → 选图片 → 定风格 → 应用风格 → 静态结果**（日系、胶片、插画、电影感）。
- 去背景 / 去杂物：**去背景 / 去杂物 → 选图片 → 语义背景或本地擦除 → 静态结果**。
- 做动态效果：**做动态效果 → 选图片 → 定动态方向与风格 → 确认生成 → 动态结果**。
- 核心承诺：用户不需要学习修图，只需先说明要得到哪种结果，再表达或选择想要的风格，就能直接完成当前任务。

进入任务后，映见把风格作为唯一创作对象。官方风格、文字、语音和参考图都用于回答当前任务里的同一个问题：“这张图片要呈现什么感觉？”用户界面只展示任务、图片、风格、结果和当前状态；底层图像参数只是不可见的执行语言。

## 用户问题

用户通常知道自己想要“更有氛围”“更清透”“像这张参考图”或“让它动起来”，但不知道该选择哪个工具，也不愿意反复试参数。传统图片应用把实现方式暴露给用户，迫使用户先理解工具，再接近想要的结果。

映见直接完成四类结果任务：

1. 用户在首页先选择优化照片、换风格、去背景 / 去杂物或做动态效果。
2. 用户在所选任务内提供一张图片。
3. 优化、风格和清理走可撤销的本地静态执行；风格任务可通过官方风格、文字、语音或参考图形成 `StyleDefinition`。
4. 动态任务使用独立的风格与生成确认路径，不以静态结果为前置条件。
5. 每个任务只展示完成该任务所需的主操作；不把执行分支或内部工具暴露为用户选择。

## 第一目标用户与场景

目标用户资格定义版本：`first-target-user-v2`

正式无引导可用性验证中的参与者应同时满足：

- 经常使用手机拍照或保存图片；
- 希望图片具有明确、好看的风格；
- 不愿学习工具分类和专业参数；
- 能用简短语言、语音或参考图表达审美方向；
- 愿意等待一次明确、可取消的动态生成任务。

首要场景包括：

- 给日常照片快速换一种完整风格；
- 看到喜欢的视觉参考后，把它转成适合自己图片的风格；
- 用一句话或一段语音说明想要的氛围；
- 从首页进入“做动态效果”后，在生成服务可用时让图片产生自然、克制的动态效果；
- 保存或分享静态图片与动态结果。

这些场景是待验证的产品假设，不代表市场需求已经成立。需求结论必须来自冻结候选上的无引导用户验证。

## 固定产品原则

### 1. 任务先行，风格是任务内的创作语言

产品先按用户想要的结果组织，而不是按实现工具组织。首页的优化照片、换风格、去背景 / 去杂物和做动态效果是四个一级创作入口。`CreationTask` 保存这项用户选择；`CreationIntent` 只表达静态 `apply` 或生成 `motion` 的执行分支，前三项都映射为 `apply`。

任务内不提供通用传统编辑器、“自己调”、工具分类、参数面板、参数滑杆、三套推荐或整组作用域。优化和清理可以使用任务专属、结果导向的本地操作，但不变成泛用工具矩阵。用户想改变结果时，可以在当前任务内继续操作或重新定风格；想改变任务时返回首页。旧 `apply` 草稿恢复为“换风格”，以保护其原有风格语义。

### 2. 图片始终是视觉主体

每个创作状态都围绕当前图片和当前结果展开。一个屏幕只突出一个主要任务；状态、确认和恢复操作就地出现，不建立层层工具导航。

### 3. AI 定义风格，执行系统守住边界

AI 负责理解用户意图和参考视觉，形成结构化风格定义。确定性图像能力负责把适用风格稳定应用到原图；生成能力负责创建原图中不存在的新像素或时间内容。

AI 不能直接绕过风格合同修改图片，也不能把底层参数、供应商对象或不可解释效果暴露为产品功能。

### 4. 四个用户任务，两个执行分支

- **优化照片**：在原图内容不变的前提下完成本地质量优化，优先即时、可撤销。
- **换风格**：把已确认的风格稳定应用为可复现的静态结果。
- **去背景 / 去杂物**：执行受支持的语义背景处理或局部擦除；范围受能力合同约束。
- **做动态效果**：创建原图中不存在的时间内容，需要用户主动触发，并明确等待、隐私、费用、取消和失败边界。

前三项是静态本地 `apply` 分支，做动态效果是独立 `motion` 分支。任务选择发生在选图前，后续页面只显示当前任务的主操作，不在定风格后重新提供应用/生成二选一。静态与生成可以复用来源和风格语义，但页面、任务、结果和失败状态相互独立。生成失败不得破坏源图、当前风格或任何已有结果。

“做动态效果”直接从其任务内的当前图片和风格发起生成，不需要先完成静态任务、应用风格或保存静态结果。任务切换只通过返回首页发生。

### 5. 动态效果是后续可激活的一等能力

生成能力激活后的首个完整闭环是把一张静态图片生成可播放、可保存、可分享的动态结果。静态扩图、换场景、写真、换脸和通用文字生图属于后续扩展，不与首个动态闭环竞争资源。当前二进制的可用性由 MVP Spec 和运行时状态如实声明；入口存在不等于已经接入上传、任务或计费服务。

### 6. 简单来自选择收敛

- 首页以四个大入口开始优化、换风格、清理或动态效果，并继续明确归属某个任务的创作。
- 优化、换风格和清理页只负责各自的本地静态操作和查看结果。
- 做动态效果页只负责确定动态方向与风格、确认生成和查看动态结果。
- 除首页的四个任务入口外，每个下游状态只突出一个主操作。
- 结果状态只负责预览、保存、分享或返回换风格。
- 系统只在当前操作确实需要时请求权限、费用确认或最少一次澄清。
- 新增界面必须缩短“选图片、定风格、得结果”的路径，或解决该路径中的真实失败。

### 7. 原图和用户决定始终可恢复

原图只读。风格定义、静态应用结果和生成结果分别保存；任一任务都不能覆盖原图或静默替换另一路径的结果。用户可以返回原图、切换风格、取消生成并恢复最后一次成功状态。

### 8. 隐私、成本和质量是产品行为

- 可在本地完成的风格应用默认不上传原图。
- 需要上传图片或参考图时，在任务创建前说明用途、处理方、保存边界和删除策略。
- 需要云端额度或付费时，在任务创建前展示成本；取消、失败和重试遵守明确的扣费合同。
- AI、网络或供应商失败时保留当前图片、风格定义和已成功结果。
- 预览、保存和分享必须对应用户看到并确认的同一结果版本。

## 产品优先级

产品能力按以下顺序投入：

1. 优化、换风格和清理这三个静态任务的结果质量与可恢复性；
2. 文字、语音和参考图定义风格的速度与准确性；
3. 静态图片生成自然动态结果的完整闭环；
4. 风格资产复用、收藏和持续供给；
5. 其他静态或动态生成扩展。

底层参数覆盖数量、工具入口数量和模型数量不构成产品进展指标。完成率、首次满意结果时间、风格辨识度、生成成功率和可保存结果质量才是核心验证指标。

## 当前不服务

- 传统图片编辑器、专业图层、通道、曲线和参数工具箱；
- “美化、人像、调色、滤镜、画质”等泛用工具分类导航；
- 多图整组、批量同步、照片排序和范围切换主线；
- 相机拍摄、实时直播美颜和完整视频剪辑；
- 以换脸、虚拟身份或通用文字生图为核心的产品路径；
- 在第一阶段同时扩展多种静态生成任务。
