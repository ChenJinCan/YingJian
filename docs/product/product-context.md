# 映见产品上下文

> 状态：稳定产品北极星。当前交付范围与验收以 [MVP Spec](mvp-spec.md) 为准，风格定义与执行语义以 [风格系统](style-system.md) 为准。

## 产品身份

- 品牌：映见。
- Slogan：让变美更容易。
- 品类：以风格为核心的 AI 图片创作应用。
- 唯一心智：**先选任务，再选图，点一个想要的结果，直接看效果**。首页有四个直接可理解的入口。
- 优化照片：**优化照片 → 选图片 → 选自然优化 / AI 修复 / 高清放大 / 老照片修复 → 静态结果**。
- 换风格：**换风格 → 选图片 → 点日系 / 胶片 / 插画 / 电影感 → 静态结果**。
- 去背景 / 去杂物：**去背景 / 去杂物 → 选图片 → 选人物白底 / 透明抠图 / 替换背景 / 去路人 / 涂抹去物 → 静态结果**。
- 做动态效果：**做动态效果 → 选图片 → 点轻微动态 / 镜头推进 / 光影流动 / AI 自然动效 → 动态结果**。
- 核心承诺：用户不需要学习专业参数或理解实现方式；四张卡片只确定任务，任务内点击哪个具名结果，就只执行那一项。

进入任务后，映见按固定顺序完整展示该任务的具名结果选项，不默认选中，也不依据图片、分析、历史或设备推荐、排序、组合、替换或降级。选项本身就是操作：本地能力直接执行，云端能力只补上传和权益所必需的确认。换风格只展示日系、胶片、插画和电影感，不把官方、文字、语音、参考图或 AI 重绘等实现来源暴露为主路径。用户界面只展示任务、图片、结果选项、结果和当前状态；底层图像参数只是不可见的执行语言。

## 用户问题

用户通常知道自己想要“更有氛围”“更清透”“像这张参考图”或“让它动起来”，但不知道该选择哪个工具，也不愿意反复试参数。传统图片应用把实现方式暴露给用户，迫使用户先理解工具，再接近想要的结果。

映见直接完成四类结果任务：

1. 用户在首页先选择优化照片、换风格、去背景 / 去杂物或做动态效果。
2. 用户在所选任务内提供一张图片。
3. 用户从固定列表中明确选择一个具体能力；选择之前不分析后执行、不上传、不创建任务、不扣费。
4. 该次点击同时固定选择与执行授权；本地能力直接产生结果，云端能力在必要确认后进入静态或动态生成合同。
5. 动态任务由用户选择一个明确动态方向，不以风格或静态结果为前置条件。
6. 图片与选项栏始终保持在同一工作区；短暂加载、云任务状态和失败提示不跳转说明页，也不遮挡其他选项。

## 第一目标用户与场景

目标用户资格定义版本：`first-target-user-v2`

正式无引导可用性验证中的参与者应同时满足：

- 经常使用手机拍照或保存图片；
- 希望图片具有明确、好看的风格；
- 不愿学习工具分类和专业参数；
- 能从少量、结果导向的名称中选出想要的审美方向；
- 愿意等待一次明确、可取消的动态生成任务。

首要场景包括：

- 给日常照片快速换一种完整风格；
- 在日系、胶片、插画和电影感之间快速点选并对比结果；
- 从首页进入“做动态效果”后，在生成服务可用时让图片产生自然、克制的动态效果；
- 保存或分享静态图片与动态结果。

这些场景是待验证的产品假设，不代表市场需求已经成立。需求结论必须来自冻结候选上的无引导用户验证。

## 固定产品原则

### 1. 任务先行，具体能力由用户决定

产品先按用户想要的结果组织，而不是按实现工具组织。首页的优化照片、换风格、去背景 / 去杂物和做动态效果是四个一级创作入口。`CreationTask` 只保存任务；任务内必须另存用户明确选择的 `CreationCapability`。`CreationIntent` 只表达静态 `apply` 或动态 `motion` 的页面分支，前三项都映射为 `apply`，但它不能代替能力选择或执行授权。

任务内不提供通用传统编辑器、“自己调”、工具分类、参数面板、参数滑杆、三套推荐或整组作用域。用户想改变结果时，在当前任务内直接点击另一个具名结果选项；想改变任务时返回首页。系统不能代选、推荐、组合、替换、降级或在没有点击的情况下自动执行。旧 `apply` 草稿恢复为“换风格”，以保护其原有风格语义。

### 2. 图片始终是视觉主体

每个创作状态都围绕当前图片和当前结果展开。一个屏幕只突出一个主要任务；状态、确认和恢复操作就地出现，不建立层层工具导航。

### 3. AI 只解释并执行用户已经作出的选择

用户明确点击插画或其他生成式结果后，系统才能读取该选项固定、受约束的定义，并在再次确认上传、费用和取消边界后创建原图中不存在的新像素或时间内容。

AI 和图片分析只能批准或拒绝用户已经选择的能力，不能直接绕过能力合同修改图片，也不能推荐、排序、组合、替换、降级或触发另一项能力。

### 4. 四个用户任务，两个执行分支

- **优化照片**：由用户选择自然优化、AI 修复、高清放大或老照片修复。
- **换风格**：由用户直接选择日系、胶片、插画或电影感。
- **去背景 / 去杂物**：由用户选择人物白底、透明抠图、替换背景、去路人或涂抹去物。
- **做动态效果**：由用户点击轻微动态、镜头推进、光影流动或 AI 自然动效，选项本身就是该方向的执行动作。

前三项进入静态 `apply` 页面分支，其中既可包含本地应用，也可包含用户明确选择并确认的静态生成；做动态效果进入独立 `motion` 分支。任务选择发生在选图前，能力选择发生在选图后、任何处理前。静态与动态页面、任务、结果和失败状态相互独立。任一能力失败不得破坏源图或已有结果，也不得自动改走另一项能力。

“做动态效果”直接从任务内的当前图片和用户选择的动态方向发起生成，不需要先完成静态任务、定风格、应用风格或保存静态结果。任务切换只通过返回首页发生。

### 5. 动态效果是后续可激活的一等能力

生成能力激活后的首个完整闭环是把一张静态图片生成可播放、可保存、可分享的动态结果。静态扩图、换场景、写真、换脸和通用文字生图属于后续扩展，不与首个动态闭环竞争资源。当前二进制的可用性由 MVP Spec 和运行时状态如实声明；入口存在不等于已经接入上传、任务或计费服务。

### 6. 简单来自选择收敛

- 首页以四个大入口开始优化、换风格、清理或动态效果，并继续明确归属某个任务的创作。
- 优化、换风格和清理页按固定顺序展示各自的具名能力，进入时没有默认选择。
- 做动态效果页的具名动态方向本身就是执行动作，成功后原地查看动态结果。
- 任务工作区持续保留图片与当前任务的直达选项，不用说明卡或全屏状态替换它们。
- 结果状态只负责预览、保存和分享；要换效果时直接点另一个选项。
- 系统只在当前操作确实需要时请求权限、费用确认或最少一次澄清。
- 新增界面必须缩短“选图片、选能力、得结果”的路径，或解决该路径中的真实失败。

### 7. 原图和用户决定始终可恢复

原图只读。能力选择、风格定义、静态应用结果和生成结果分别保存；任一任务都不能覆盖原图或静默替换另一路径的结果。用户可以返回原图、重新选择能力、取消生成并恢复最后一次成功状态。

### 8. 隐私、成本和质量是产品行为

- 用户选择可在本地完成的风格应用时不上传原图。
- 需要上传图片或参考图时，在任务创建前说明用途、处理方、保存边界和删除策略。
- 需要云端额度或付费时，在任务创建前展示成本；取消、失败和重试遵守明确的扣费合同。
- AI、网络或供应商失败时保留当前图片、能力选择、风格定义和已成功结果；不得自动降级或切换能力。
- 预览、保存和分享必须对应用户看到并确认的同一结果版本。

## 产品优先级

产品能力按以下顺序投入：

1. 四个任务内已确认能力的完整选择界面、真实可用性与零自动判断合同；
2. 优化、换风格和清理能力的结果质量与可恢复性；
3. 轻微动态、镜头推进和光影流动的完整生成闭环；
4. 风格资产复用、收藏和持续供给；
5. 其他静态或动态生成扩展。

底层参数覆盖数量、工具入口数量和模型数量不构成产品进展指标。完成率、首次满意结果时间、风格辨识度、生成成功率和可保存结果质量才是核心验证指标。

## 当前不服务

- 传统图片编辑器、专业图层、通道、曲线和参数工具箱；
- “美化、人像、调色、滤镜、画质”等泛用工具分类导航；
- 多图整组、批量同步、照片排序和范围切换主线；
- 相机拍摄、实时直播美颜和完整视频剪辑；
- 以换脸、虚拟身份或通用文字生图为核心的产品路径；
- 能力目录之外的无限制静态或动态生成任务。
