# 映见风格系统

> 状态：产品与领域合同。本文定义 `CreationCapability`、风格来源、`StyleDefinition`、不可见执行语言，以及四个用户任务和两个结果分支的边界。首阶段页面、状态和验收见 [MVP Spec](mvp-spec.md)。

## 1. 核心模型

`CreationTask` 只确定首页四张卡片；`CreationCapability` 才是用户进入任务后通过名称明确的控件主动选择、并单项授权执行的结果能力。任何任务进入时都没有默认能力；系统不得依据图片、分析、历史、设备或 AI 推荐、排序、组合、替换或选择能力。

风格只属于换风格任务。优化照片和去背景 / 去杂物使用任务专属能力；做动态效果使用用户明确选择的运动方向。它们都不得被伪装成风格。

产品与风格执行使用以下层次：

| 层次 | 含义 | 用户是否可见 |
|---|---|---|
| `CreationTask` | 用户在首页选择的四张任务卡片身份 | 可见 |
| `CreationCapability` | 用户在任务内明确选择的一项结果能力，也是本次唯一执行授权 | 结果名称和可用性可见 |
| `StyleDefinition` | 每个结果风格背后的结构化、版本化合同 | 只显示结果风格名；来源不构成用户选择 |
| `StyleRecipe` | 把风格定义编译为当前设备可执行的确定性参数与能力计划 | 不可见 |
| `GenerationRequest` | 用源图、用户已选能力和该能力的确认输入创建新内容的异步任务 | 状态、成本和结果可见 |

用户界面围绕结果选项与图片本身沟通。`StyleDefinition`、`StyleRecipe`、参数范围、模型和供应商只属于执行系统。`CreationTask=optimize|style|cleanup|motion` 保存用户任务；`CreationIntent=apply|motion` 只区分静态页面与动态页面，不能表示用户选择了哪项能力，也不构成上传、生成或费用授权。

每项能力另有不可见的 `executionKind=localApply|cloudApply|staticGenerate|motionGenerate`。它只描述如何执行用户已经选择的能力，不能被系统用来改选另一能力；当前代码尚未完整实现这一属性，未接通的能力必须保持不可用。

## 2. StyleDefinition

`StyleDefinition` 是日系、胶片、插画、电影感及历史风格快照共同使用的唯一规范对象。每个定义至少包含：

| 字段 | 合同 |
|---|---|
| `schemaVersion` | 定义结构版本；未知版本拒绝执行或显式迁移 |
| `styleId` | 风格稳定身份；用户定义风格也必须有本地唯一 ID |
| `revision` | 当前风格内容版本；已保存创作固定使用当时版本 |
| `origin` | `official`、`text`、`voice`、`reference` 或 `aiRedraw` |
| `title` | 简短、结果导向、可本地化的风格名 |
| `summary` | 一句话说明整体感觉，不列举工具和参数 |
| `visualIntent` | 结构化描述色彩关系、光线、氛围、质感、主体呈现和背景关系 |
| `contentPolicy` | 身份保持、允许变化、禁止变化和不适用条件 |
| `applicationPolicy` | 是否支持确定性静态应用及所需能力版本 |
| `generationPolicy` | 是否支持 AI 风格重绘等静态生成，以及允许的有界生成意图 |
| `provenance` | 官方资产版本或用户确认输入的本地来源引用；不写入遥测 |
| `createdAt` | 用于项目恢复和审计的本地创建时间 |

`StyleDefinition` 不包含用户可调参数、滑杆值或供应商专用对象。它描述“结果应该是什么”，执行系统再根据当前图片和设备能力编译 `StyleRecipe`。

### 2.1 风格定义完成条件

首页先确定 `CreationTask`，用户在换风格任务中直接选择日系、胶片、插画或电影感。只有换风格任务需要 `StyleDefinition`；做动态效果使用独立的明确运动方向。满足以下条件后，本地风格才可直接应用，插画才可进入云端确认：

1. 结构符合当前 schema；
2. 用户点击的结果风格与定义身份完全对应；
3. 视觉意图来自固定版本，不依赖运行时自由文本；
4. 内容和身份安全边界完整；
5. 当前图片支持已经选择的任务路径；
6. 所需能力和版本可解析；
7. 预览已绑定正确的源图与风格版本并成功显示。

任一条件失败时，系统保留上一个成功风格，不生成部分生效结果。

## 3. 结果风格 V1

首批主路径固定展示四个少而强的结果方向。顺序人工策划且固定，不根据照片、最近使用、历史或模型判断自动排序、突出或隐藏：

| `styleId` | 展示名 | 执行 | 视觉意图 |
|---|---|---|---|
| `japanese-v1` | 日系 | 本地应用 | 明亮、低反差、轻淡色彩和干净空气感 |
| `film-v1` | 胶片 | 本地应用 | 温润色彩、柔和高光、克制反差和胶片质感 |
| `illustration-v1` | 插画 | 固定云端生成 | 将源图转为受约束插画表现，保持主体身份和构图边界 |
| `cinematic-v1` | 电影感 | 本地应用 | 更明确的明暗层次、克制饱和度和电影色彩关系 |

每个风格必须具备固定 `styleId`、`revision`、名称、缩略预览、身份保持/内容变化边界、执行版本和失败行为。日系、胶片和电影感在用户点击后直接应用；插画在点击后直接打开必要的上传与权益确认，并只从冻结的 `illustration-v1` 定义创建一次任务。主路径不显示“官方风格、文字定风格、语音定风格、参考图风格、AI 风格重绘”，也不显示提示词、模型或供应商。

## 4. 历史兼容与隐藏来源

旧项目可能保存 `origin=text|voice|reference|aiRedraw` 或旧风格 ID。它们只用于无损恢复既有结果和来源审计，不重新出现在新建创作的主选项栏，也不能借恢复过程触发上传、生成或改写结果。

新建创作的用户授权来自点击四个结果风格之一。内部仍可使用 `origin=official` 表达三个本地固定定义，使用 `origin=aiRedraw` 表达固定插画定义；这些来源只是持久化和执行兼容信息，不是用户的第二次选择。

## 5. 风格编译与不可见执行语言

`StyleRecipe` 是 `StyleDefinition` 针对当前图片、平台能力和安全条件编译出的执行计划。它可以使用现有光色、质感、人像保护、画质和其他确定性参数，但必须满足：

- 参数和能力只来自版本化合法目录；
- 图片适用性只用于安全编译，不自动改变用户选择的风格身份；
- 只能执行用户已经选择的 `CreationCapability`，不得增添、组合、替换或触发其他能力；
- 同一源图、风格版本、编译器版本和平台能力产生可复现结果；
- 预览和最终静态输出使用相同语义与处理顺序；
- 不支持或低置信度能力被明确拒绝并保留当前状态，不自动降级；
- 编译失败不产生半风格结果；
- UI、文案、无障碍和遥测不暴露内部参数。

用户想改变效果时，系统创建新风格定义或切换风格；产品不提供参数滑杆、工具面板或“高级编辑”逃生口。

## 6. 四个任务、明确能力与两个结果分支

首页以四个任务先确定用户要得到的结果；任务选择发生在选图前。选图后显示固定顺序的直达选项且不默认选中，选项本身就是本地执行动作或云端必要确认入口，不再另显示通用主操作。

### 6.1 目标 MVP 能力目录

| `CreationTask` | `CreationIntent` | 稳定能力 ID | 用户名称 |
|---|---|---|---|
| `optimize` | `apply` | `optimize.natural` | 自然优化 |
| `optimize` | `apply` | `optimize.aiRepair` | AI 修复 |
| `optimize` | `apply` | `optimize.upscale` | 高清放大 |
| `optimize` | `apply` | `optimize.oldPhoto` | 老照片修复 |
| `style` | `apply` | `style.official` + `japanese-v1` | 日系 |
| `style` | `apply` | `style.official` + `film-v1` | 胶片 |
| `style` | `apply` | `style.aiRedraw` + `illustration-v1` | 插画 |
| `style` | `apply` | `style.official` + `cinematic-v1` | 电影感 |
| `cleanup` | `apply` | `cleanup.white` | 人物白底 |
| `cleanup` | `apply` | `cleanup.transparent` | 透明抠图 |
| `cleanup` | `apply` | `cleanup.replaceBackground` | 替换背景 |
| `cleanup` | `apply` | `cleanup.removePasserby` | 去路人 |
| `cleanup` | `apply` | `cleanup.brushRemove` | 涂抹去物 |
| `motion` | `motion` | `motion.subtle` | 轻微动态 |
| `motion` | `motion` | `motion.cameraPush` | 镜头推进 |
| `motion` | `motion` | `motion.lightFlow` | 光影流动 |
| `motion` | `motion` | `motion.aiNatural` | AI 自然动效 |

用户点击动态方向即启动该方向的本地执行或必要云端确认；没有第二个“生成动态照片”按钮。

### 6.2 当前运行时可用性

| 能力 | 当前真实状态 |
|---|---|
| `optimize.natural` | iOS 已有固定本地配方；用户点击后直接应用并显示结果 |
| `optimize.aiRepair` | 已实现百度 `image_definition_enhance` 的第一方网关合同；只有运行环境完成认证、权益和供应商配置后才启用 |
| `optimize.upscale` | iOS 已接通点击后默认 2× 的本地高质量重采样；不宣称生成不存在的 AI 细节，也不自动改走云端 |
| `optimize.oldPhoto` | 已实现阿里 `wanx2.1-imageedit` 网关合同；用户点击后固定保留原色并直接进入必要云端确认，旧客户端显式的上色输入仅作兼容 |
| `style.official` | 日系、胶片、电影感三个本地结果风格点击即应用；没有“官方风格”前置入口 |
| `style.aiRedraw` | 插画使用固定 `illustration-v1` 定义与阿里 `wan2.7-image` 合同；用户点击后直接进入必要云端确认，不收集自由文本 |
| `style.text` / `style.voice` / `style.reference` | 仅保留旧项目恢复兼容，不出现在新建创作主路径 |
| `cleanup.white` | iOS 人物场景已有；用户点击后分析适用性并直接应用 |
| `cleanup.transparent` | iOS 人物场景已接通点击后本地预览与应用；保存和分享强制 PNG；缺少语义人物 matte 时明确失败，不使用 body fallback 冒充透明结果 |
| `cleanup.replaceBackground` | iOS 人物场景已接通；点击后分析并直接打开本地背景选择，选定后应用；不上传或生成背景 |
| `cleanup.removePasserby` / `cleanup.brushRemove` | 已实现用户手绘黑白 Mask 与阿里 `wanx2.1-imageedit` 第一方网关合同；不自动识别人、扩展选区或改用旧纹理擦除 |
| 三项动态能力 | iOS 已实现用户显式选择后的本地 H.264 MP4：整图克制平移缩放、镜头推进、光影流动；不上传、不扣费，也不冒充主体语义动画 |

优化、换风格和清理共享静态结果安全边界，但不因此变成一个笼统的“图片应用”入口。AI 风格重绘等静态生成仍属于 `CreationIntent=apply` 的静态页面，其生成属性由已选能力的 `executionKind` 表达。做动态效果直接使用源图与用户选择的运动方向，静态结果不是前置输入。旧 `creationIntent=apply` 草稿迁移为 `CreationTask.style`，保存原有风格含义。

硬边界：

- 未选择 `CreationCapability` 时不得分析照片后自动执行、上传、创建任务或扣费。
- 一次选择只授权并执行一项本地能力，或打开一项云端能力的必要确认；不可用、失败或质量拒绝时说明原因并保留当前状态，不推荐、不降级、不自动切换或组合其他能力。
- 云端能力必须在该能力内再次确认上传、费用、取消和删除边界；点击选项本身不构成上传、生成或扣费授权。
- 三个静态任务不得静默创建生成任务或上传原图；只有用户明确选择生成式静态能力并确认后才能创建对应任务。
- 做动态效果的本地选项点击后直接执行；不支持的平台保持不可用。生成不得覆盖原图或任何已有结果，也不得显示上传或云端费用确认。
- 静态预览不得扣除动态生成额度。
- 四个任务以及所选能力的成功、失败、保存和分享状态分别记录；切换任务必须返回首页。

## 7. 动态生成合同

当前 iOS 使用本地编码器执行三项明确方向；未来若增加云端主体语义动画，必须作为新的、由用户明确选择和确认的能力，不能静默替换当前本地结果。动态任务的输入为：

- 一张只读源图；
- 一个由用户明确选择的 `motion.subtle`、`motion.cameraPush` 或 `motion.lightFlow`；
- 当前本地生成策略和版本；
- 固定的 MP4 输出合同。当前本地能力没有上传和云端成本。

运动意图必须由用户从名称明确的动态能力中选择；图片分析只验证所选能力能否安全执行，不得生成默认运动意图、排序或推荐方向。产品不要求用户配置时间线、镜头参数、运动强度或关键帧；用户需要改变方向时返回固定能力列表重新选择。

### 7.1 动态安全边界

- 保持主体身份、数量和基本结构；
- 避免无意的脸型、身体、手指、文字和背景结构漂移；
- 不自动创建说话、对口型、暴力、裸露或身份冒用内容；
- 静态输入不适合安全动画时，在创建任务前明确拒绝；
- 生成完成后检查文件完整性、时长、方向、可播放性和明显灾难性错误；
- 未通过结果不得进入 `motionReady` 或扣为成功交付。

### 7.2 动态任务合同

- 同一确认动作只创建一个幂等任务；
- 任务以稳定 ID 追踪准备、上传、生成、结果处理和完成状态；
- 可取消阶段必须真实取消，不能只关闭界面；
- 网络或生命周期变化后重新关联原任务，不自动复制任务；
- 超时、失败、策略拒绝和用户取消分别记录；
- 成功结果与源图、用户选择的动态方向、生成版本和文件摘要绑定；
- 动态结果可播放、暂停、保存、分享和从项目中删除。

静态扩图、换场景、写真、通用文字生图和完整视频编辑属于后续生成类型；它们必须另行定义结果、成本和安全合同，不能复用“动起来”名称模糊上线。

## 8. 持久化与版本

- 项目先保存 `CreationTask`；`CreationIntent` 只作为从任务派生的静态/生成执行边界。历史只有 `apply` 的项目显式迁移为 `style`，不重新分类为优化或清理。
- 只有用户明确选择后才保存 `CreationCapability`；恢复时只恢复曾保存的能力，不从任务、图片、分析、配方或设备能力推断。
- 项目保存当前 `StyleDefinition` 的完整冻结快照，不只保存结果风格 ID。
- 结果风格发布新 revision 时，已有项目继续使用旧快照；用户主动再次选择后才创建新版本。
- 历史文字、语音、参考图和 AI 重绘定义继续使用其稳定 ID 与 revision，仅用于恢复兼容。
- `StyleRecipe` 缓存可以重建，不是风格事实源；缓存版本不匹配时重新编译。
- 动态服务接入后的任务和结果引用确切源图、用户选择的动态方向、生成策略版本和任务 ID；服务未接入时不能写入虚构任务身份。
- 历史原始语音、临时上传文件和参考图只在仍被旧任务合法引用时保留，引用结束后按隐私合同回收。
- 未知 schema、缺失字段、越界能力或不兼容版本必须拒绝或显式迁移，不能静默套用近似风格。

## 9. 质量门

### 9.1 风格质量

- 同时展示的日系、胶片、插画和电影感在盲评中能够被稳定区分，而不是只存在轻微参数差异。
- 风格名称、说明、视觉样例和实际结果表达同一方向。
- 插画固定定义产生的结果能被用户辨认为插画，并遵守身份和构图边界。
- 预览、最终静态输出和项目恢复保持同一风格身份。
- 风格应用不产生身份变化、明显局部错误或隐藏生成内容。

### 9.2 系统正确性

- 四个结果风格使用的 `StyleDefinition` 通过同一 schema、安全和能力校验。
- 过期 AI、预览和生成响应不能覆盖较新的风格版本。
- 优化、换风格和清理只有在用户点击对应云端能力并完成该项确认后才能创建网络任务；本地能力和未选择状态永远不创建。当前本地动态只在用户点击方向后编码，不创建网络任务。
- 服务接入后的生成取消、失败和恢复不会修改源图、当前风格或任何已有结果，也不会重复扣费。
- 项目冷启动能恢复确切 `CreationTask`、用户曾明确保存的 `CreationCapability`、风格快照和原生成任务身份（如有）；不得从图片或配方猜测能力。

### 9.3 完成定义

风格系统首阶段完成必须同时证明：

1. 日系、胶片、插画和电影感都能产出统一 `StyleDefinition`，且主路径不暴露执行来源；
2. `StyleDefinition` 能编译或生成、保存、恢复和版本迁移；
3. 四个任务进入后均显示固定顺序的完整直达选项且没有默认选择；用户点击一项后只执行该项或打开该项必要确认，不自动推荐、组合、替换或降级；
4. 优化、换风格和清理从原图得到可保存的受支持静态结果，且不暴露底层参数；
5. 四个任务及所选能力从 UI、状态、持久化、隐私、费用、失败和结果身份上分离；旧 `apply` 草稿安全迁移为换风格；
6. 三项本地动态均证明只有用户点击的方向会编码成 MP4，且没有上传或云端成本；不支持本地编码器的平台证明真实不可用；
7. 自动化、iOS Simulator、冻结候选真机和人工视觉质量门按 [MVP Spec](mvp-spec.md)完成。

任一选项只能显示说明却不能产生并保存结果时，均不属于完整闭环。
