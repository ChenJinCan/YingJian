# 映见风格系统

> 状态：产品与领域合同。本文定义 `CreationCapability`、风格来源、`StyleDefinition`、不可见执行语言，以及四个用户任务和两个结果分支的边界。首阶段页面、状态和验收见 [MVP Spec](mvp-spec.md)。

## 1. 核心模型

`CreationTask` 只确定首页四张卡片；`CreationCapability` 才是用户进入任务后通过名称明确的控件主动选择、并单项授权执行的结果能力。任何任务进入时都没有默认能力；系统不得依据图片、分析、历史、设备或 AI 推荐、排序、组合、替换或选择能力。

风格只属于换风格任务。优化照片和去背景 / 去杂物使用任务专属能力；做动态效果使用用户明确选择的运动方向。它们都不得被伪装成风格。

产品与风格执行使用以下层次：

| 层次 | 含义 | 用户是否可见 |
|---|---|---|
| `CreationTask` | 用户在首页选择的四张任务卡片身份 | 可见 |
| `CreationCapability` | 用户在任务内明确选择的一项结果能力，也是本次唯一执行授权 | 名称、说明、可用性可见 |
| `StyleBrief` | 用户选择的官方风格，或确认后的文字、语音转写、参考图、AI 重绘意图 | 可见、可修改 |
| `StyleDefinition` | AI 或官方资产产出的结构化、版本化风格合同 | 名称、说明和来源可见 |
| `StyleRecipe` | 把风格定义编译为当前设备可执行的确定性参数与能力计划 | 不可见 |
| `GenerationRequest` | 用源图、用户已选能力和该能力的确认输入创建新内容的异步任务 | 状态、成本和结果可见 |

用户界面围绕 `CreationCapability`、必要时的 `StyleBrief` / `StyleDefinition` 和结果沟通。`StyleRecipe`、参数范围、模型和供应商只属于执行系统。`CreationTask=optimize|style|cleanup|motion` 保存用户任务；`CreationIntent=apply|motion` 只区分静态页面与动态页面，不能表示用户选择了哪项能力，也不构成上传、生成或费用授权。

每项能力另有不可见的 `executionKind=localApply|cloudApply|staticGenerate|motionGenerate`。它只描述如何执行用户已经选择的能力，不能被系统用来改选另一能力；当前代码尚未完整实现这一属性，未接通的能力必须保持不可用。

## 2. StyleDefinition

`StyleDefinition` 是官方风格、文字、语音、参考图和 AI 风格重绘共同使用的唯一规范对象。每个定义至少包含：

| 字段 | 合同 |
|---|---|
| `schemaVersion` | 定义结构版本；未知版本拒绝执行或显式迁移 |
| `styleId` | 风格稳定身份；用户定义风格也必须有本地唯一 ID |
| `revision` | 当前风格内容版本；已保存创作固定使用当时版本 |
| `origin` | `official`、`text`、`voice`、`reference` 或 `aiRedraw` |
| `title` | 简短、结果导向、可本地化的风格名 |
| `summary` | 一句话说明整体感觉，不列举工具和参数 |
| `visualIntent` | 结构化描述色彩关系、光线、氛围、质感、主体呈现和背景关系 |
| `contentPolicy` | 身份保持、允许变化、禁止变化和不适用条件 |
| `applicationPolicy` | 是否支持确定性静态应用及所需能力版本 |
| `generationPolicy` | 是否支持 AI 风格重绘等静态生成，以及允许的有界生成意图 |
| `provenance` | 官方资产版本或用户确认输入的本地来源引用；不写入遥测 |
| `createdAt` | 用于项目恢复和审计的本地创建时间 |

`StyleDefinition` 不包含用户可调参数、滑杆值或供应商专用对象。它描述“结果应该是什么”，执行系统再根据当前图片和设备能力编译 `StyleRecipe`。

### 2.1 风格定义完成条件

首页先确定 `CreationTask`，用户在换风格任务中再明确选择官方、文字、语音、参考图或 AI 风格重绘。只有换风格任务需要 `StyleDefinition`；做动态效果使用独立的明确运动方向。满足以下条件后，风格才进入 `applyStyleReady` 或 AI 风格重绘确认状态：

1. 结构符合当前 schema；
2. 来源输入已由用户确认；
3. 视觉意图足够明确，不依赖隐藏自由文本；
4. 内容和身份安全边界完整；
5. 当前图片支持已经选择的任务路径；
6. 所需能力和版本可解析；
7. 预览已绑定正确的源图与风格版本并成功显示。

任一条件失败时，系统保留上一个成功风格，不生成部分生效结果。

## 3. 官方风格

官方风格是人工策划、固定版本、经过样片和设备验证的 `StyleDefinition`。它们提供最快的“定风格”路径，不构成推荐算法或固定三选一。

每个官方风格必须具备：

- 独立名称、视觉样例和一句审美说明；
- 与其他同时展示风格足够明显的结果差异；
- 明确适用和不适用输入；
- 固定的 `styleId`、`revision`、能力版本和拒绝行为；
- 静态应用或静态生成的独立质量证据；
- 预览、保存和恢复使用同一风格语义；
- 下架或升级后，旧项目仍能识别并恢复其冻结版本。

官方风格使用固定的人工策展顺序展示。只有用户主动执行排序或筛选时顺序才可改变；不得根据照片、最近使用、收藏、历史或模型判断自动排序、突出或隐藏风格。

### 3.1 首批官方风格 V1

首批风格使用少而强的六个方向验证“用户是否能一眼区分，并在一次点选后得到可用结果”。它们不是六个固定 UI 槽位，也不是推荐排名。

![映见官方风格 V1 视觉母版](../design/yingjian-official-style-library-v1.png)

| `styleId` | 展示名 | 静态视觉意图 |
|---|---|---|
| `official.natural_clear.v1` | 自然通透 | 中性白、柔和自然光、真实肤色、清楚细节 |
| `official.soft_film.v1` | 柔光胶片 | 奶油高光、柔和反差、轻微晕光与细颗粒 |
| `official.cinematic_night.v1` | 电影夜色 | 深青蓝暗部、克制暖色光源、浓郁但不死黑 |
| `official.cool_after_rain.v1` | 雨后清冷 | 银蓝空气感、湿润反光、低饱和与安静情绪 |
| `official.golden_diary.v1` | 暖阳日记 | 午后金色逆光、通透阴影、轻怀旧日记感 |
| `official.monochrome_portrait.v1` | 黑白肖像 | 中性黑白、丰富中间调、轻颗粒与克制黑位 |

视觉母版只冻结方向，不代表已经交付。每个风格必须先用同一组源照片验证身份保持、差异度、预览/导出一致和静态执行安全；未通过时保持 `待验证`，不能仅凭方向图进入生产目录。

## 4. 用户定义风格

### 4.1 文字

文字入口接受用户自然表达，例如氛围、时代感、色彩倾向、光线感觉和质感。系统执行：

1. 保存用户当前确认的 `StyleBrief`；
2. AI 把表达归一化为结构化视觉意图；
3. 内容策略明确标注并拒绝不能安全执行的要求，不静默改写用户目标；
4. 风格校验器验证 schema、能力和版本；
5. 编译预览并返回风格名、说明和结果。

用户无需使用专业词汇。系统不得要求用户先选择工具或填写参数；确需澄清时，只询问一个会改变最终方向的问题。

### 4.2 语音

语音是输入 `StyleBrief` 的另一种方式，不是独立风格系统：

- 只在用户主动操作后录音；
- 先转写，再由用户确认或重录；
- 确认文本进入与文字相同的定义、策略、校验和编译流程；
- 录音、转写或权限失败时保留当前状态并返回能力列表；用户可亲自选择文字定风格；
- 普通日志和遥测不保存音频或完整转写。

### 4.3 参考图

参考图用于提取可迁移的视觉风格，不用于复制其具体内容。系统可以提取：

- 色彩关系与综合色温；
- 明暗、对比和光线气质；
- 颗粒、柔和、清晰等整体质感；
- 主体与背景的视觉层次；
- 可用文字概括的氛围与时代感。

系统不得把以下内容转成风格：

- 人物身份、人脸、身体或生物特征；
- 具体对象、场景布局和构图位置；
- 文字、签名、Logo、水印和可识别品牌元素；
- 明确受保护角色、作品或要求一比一复制的内容；
- 参考图中的隐私信息和元数据。

参考图生成的 `StyleDefinition` 必须显示新的风格名和说明，并保持源图内容为结果主体。参考图被移除后，已确认的定义可按其冻结版本继续存在；原参考文件按项目引用与隐私合同回收。

### 4.4 AI 风格重绘

AI 风格重绘的文本框只是待确认草稿，不是任务输入。用户必须主动输入并点击“确认生成意图”；系统只能归一化首尾、连续空格和换行等排版空白，不得改写意思、补齐风格、选择方向或加入未输入的内容。空白、超过 500 个可见字符、隐藏方向控制符或其他不安全控制字符必须 fail closed，保留草稿供用户自行修改。

确认动作冻结一份 `origin=aiRedraw` 的 `StyleDefinition`：`visualIntent` 显示规范化后但未被语义改写的用户意图，`schemaVersion + styleId + revision` 形成版本化身份，内容摘要使相同视觉意图可重现地绑定同一执行投影。页面先展示这份生成意图和 revision，然后才允许进入上传与权益的第二次云端确认。用户再次编辑文本会立即使页面中的已确认定义失效；`GenerationInput` 只能从当前冻结定义的 `visualIntent` 和内容摘要构建，不得读取 `TextField` 的即时值。

### 4.5 不混合能力

官方、文字、语音、参考图和 AI 风格重绘是五个相互独立的用户选择。目标 MVP 不把两种输入方式自动或隐式合并；用户要改变路径时返回固定能力列表并亲自选择，上一份成功风格和结果继续保留。

## 5. 风格编译与不可见执行语言

`StyleRecipe` 是 `StyleDefinition` 针对当前图片、平台能力和安全条件编译出的执行计划。它可以使用现有光色、质感、人像保护、画质和其他确定性参数，但必须满足：

- 参数和能力只来自版本化合法目录；
- 图片适用性只用于安全编译，不自动改变用户选择的风格身份；
- 只能执行用户已经选择的 `CreationCapability`，不得增添、组合、替换或触发其他能力；
- 同一源图、风格版本、编译器版本和平台能力产生可复现结果；
- 预览和最终静态输出使用相同语义与处理顺序；
- 不支持或低置信度能力被明确拒绝并保留当前状态，不自动降级；
- 编译失败不产生半风格结果；
- UI、文案、无障碍和遥测不暴露内部参数。

用户想改变效果时，系统创建新风格定义或切换风格；产品不提供参数滑杆、工具面板或“高级编辑”逃生口。

## 6. 四个任务、明确能力与两个结果分支

首页以四个任务先确定用户要得到的结果；任务选择发生在选图前。选图后先显示固定顺序的能力列表且不默认选中，只有用户点选一项后才显示该能力的主操作。

### 6.1 目标 MVP 能力目录

| `CreationTask` | `CreationIntent` | 稳定能力 ID | 用户名称 |
|---|---|---|---|
| `optimize` | `apply` | `optimize.natural` | 自然优化 |
| `optimize` | `apply` | `optimize.aiRepair` | AI 修复 |
| `optimize` | `apply` | `optimize.upscale` | 高清放大 |
| `optimize` | `apply` | `optimize.oldPhoto` | 老照片修复 |
| `style` | `apply` | `style.official` | 官方风格 |
| `style` | `apply` | `style.text` | 文字定风格 |
| `style` | `apply` | `style.voice` | 语音定风格 |
| `style` | `apply` | `style.reference` | 参考图风格 |
| `style` | `apply` | `style.aiRedraw` | AI 风格重绘 |
| `cleanup` | `apply` | `cleanup.white` | 人物白底 |
| `cleanup` | `apply` | `cleanup.transparent` | 透明抠图 |
| `cleanup` | `apply` | `cleanup.replaceBackground` | 替换背景 |
| `cleanup` | `apply` | `cleanup.removePasserby` | 去路人 |

### 6.2 当前运行时可用性

| 能力 | 当前真实状态 |
|---|---|
| `optimize.natural` | iOS 已有固定本地配方；用户显式选择后才显示预览和主操作 |
| `optimize.aiRepair` | 已实现百度 `image_definition_enhance` 的第一方网关合同；只有运行环境完成认证、权益和供应商配置后才启用 |
| `optimize.upscale` | iOS 已接通用户显式选择的本地 2×/4× 高质量重采样；不宣称生成不存在的 AI 细节，也不自动改走云端 |
| `optimize.oldPhoto` | 已实现火山 `LensOpr` 网关合同，但默认关闭；必须由用户明确选择保留原色或上色，生产启用仍需账号、价格和样片验收 |
| `style.official` | 已有六个本地风格；用户先选官方风格，再亲自选择具体风格，没有默认项 |
| `style.text` / `style.voice` | 已接通有界本地定义、预览与应用；只解释已公布风格词汇，语音仅允许 Apple 端侧转写，不支持时明确失败，不自动改走文字或官方风格 |
| `style.reference` | 已接通 48 × 48 本地光色质感聚合、预览与应用；只冻结色彩、明暗、对比和整体质感标量，不保留或复制参考图内容，不冒充完整风格迁移 |
| `style.aiRedraw` | 已实现阿里 `wan2.7-image` 第一方网关合同；用户必须输入并确认风格定义，运行环境未配置时保持不可用 |
| `cleanup.white` | iOS 人物场景已有；仅在用户显式选择人物白底后分析适用性、预览并应用 |
| `cleanup.transparent` | iOS 人物场景已接通本地预览与应用；选择前不分析，保存和分享强制 PNG；缺少语义人物 matte 时明确失败，不使用 body fallback 冒充透明结果 |
| `cleanup.replaceBackground` | iOS 人物场景已接通；用户先明确选择能力，再主动选择一张存入应用资源目录的本地背景图，随后预览与应用；不上传或生成背景 |
| `cleanup.removePasserby` / `cleanup.brushRemove` | 已实现用户手绘黑白 Mask 与阿里 `wanx2.1-imageedit` 第一方网关合同；不自动识别人、扩展选区或改用旧纹理擦除 |
| 三项动态能力 | iOS 已实现用户显式选择后的本地 H.264 MP4：整图克制平移缩放、镜头推进、光影流动；不上传、不扣费，也不冒充主体语义动画 |

优化、换风格和清理共享静态结果安全边界，但不因此变成一个笼统的“图片应用”入口。AI 风格重绘等静态生成仍属于 `CreationIntent=apply` 的静态页面，其生成属性由已选能力的 `executionKind` 表达。做动态效果直接使用源图与用户选择的运动方向，静态结果不是前置输入。旧 `creationIntent=apply` 草稿迁移为 `CreationTask.style`，保存原有风格含义。

硬边界：

- 未选择 `CreationCapability` 时不得分析照片后自动执行、上传、创建任务或扣费。
- 一次选择只授权一项能力；不可用、失败或质量拒绝时说明原因并保留当前状态，不推荐、不降级、不自动切换或组合其他能力。
- 云端能力必须在该能力内再次确认上传、费用、取消和删除边界；选择能力本身不构成云端授权。
- 三个静态任务不得静默创建生成任务或上传原图；只有用户明确选择生成式静态能力并确认后才能创建对应任务。
- 做动态效果只在本地编码器可用时显示生成 CTA；不支持的平台保持不可用。生成不得覆盖原图或任何已有结果，也不得显示上传或云端费用确认。
- 静态预览不得扣除动态生成额度。
- 四个任务以及所选能力的成功、失败、保存和分享状态分别记录；切换任务必须返回首页。

## 7. 动态生成合同

当前 iOS 使用本地编码器执行三项明确方向；未来若增加云端主体语义动画，必须作为新的、由用户明确选择和确认的能力，不能静默替换当前本地结果。动态任务的输入为：

- 一张只读源图；
- 一个由用户明确选择的 `motion.subtle`、`motion.cameraPush` 或 `motion.lightFlow`；
- 当前本地生成策略和版本；
- 固定的 MP4 输出合同。当前本地能力没有上传和云端成本。

运动意图必须由用户从名称明确的动态能力中选择；图片分析只验证所选能力能否安全执行，不得生成默认运动意图、排序或推荐方向。产品不要求用户配置时间线、镜头参数、运动强度或关键帧；用户需要改变方向时返回固定能力列表重新选择。

### 7.1 动态安全边界

- 保持主体身份、数量和基本结构；
- 避免无意的脸型、身体、手指、文字和背景结构漂移；
- 不自动创建说话、对口型、暴力、裸露或身份冒用内容；
- 静态输入不适合安全动画时，在创建任务前明确拒绝；
- 生成完成后检查文件完整性、时长、方向、可播放性和明显灾难性错误；
- 未通过结果不得进入 `motionReady` 或扣为成功交付。

### 7.2 动态任务合同

- 同一确认动作只创建一个幂等任务；
- 任务以稳定 ID 追踪准备、上传、生成、结果处理和完成状态；
- 可取消阶段必须真实取消，不能只关闭界面；
- 网络或生命周期变化后重新关联原任务，不自动复制任务；
- 超时、失败、策略拒绝和用户取消分别记录；
- 成功结果与源图、用户选择的动态方向、生成版本和文件摘要绑定；
- 动态结果可播放、暂停、保存、分享和从项目中删除。

静态扩图、换场景、写真、通用文字生图和完整视频编辑属于后续生成类型；它们必须另行定义结果、成本和安全合同，不能复用“动起来”名称模糊上线。

## 8. 持久化与版本

- 项目先保存 `CreationTask`；`CreationIntent` 只作为从任务派生的静态/生成执行边界。历史只有 `apply` 的项目显式迁移为 `style`，不重新分类为优化或清理。
- 只有用户明确选择后才保存 `CreationCapability`；恢复时只恢复曾保存的能力，不从任务、图片、分析、配方或设备能力推断。
- 项目保存当前 `StyleDefinition` 的完整冻结快照，不只保存官方风格 ID 或用户原始输入。
- 官方风格发布新 revision 时，已有项目继续使用旧快照；用户主动升级后才创建新版本。
- 文字、语音、参考图和 AI 风格重绘定义都使用稳定本地 ID 与递增 revision。
- `StyleRecipe` 缓存可以重建，不是风格事实源；缓存版本不匹配时重新编译。
- 动态服务接入后的任务和结果引用确切源图、用户选择的动态方向、生成策略版本和任务 ID；服务未接入时不能写入虚构任务身份。
- 原始语音、临时上传文件和参考图只在仍被当前任务合法引用时保留，引用结束后按隐私合同回收。
- 未知 schema、缺失字段、越界能力或不兼容版本必须拒绝或显式迁移，不能静默套用近似风格。

## 9. 质量门

### 9.1 风格质量

- 同时展示的官方风格在盲评中能够被稳定区分，而不是只存在轻微参数差异。
- 风格名称、说明、视觉样例和实际结果表达同一方向。
- 文字、语音确认文本和参考图产生的定义能被用户复述为其原意。
- 预览、最终静态输出和项目恢复保持同一风格身份。
- 风格应用不产生身份变化、明显局部错误或隐藏生成内容。

### 9.2 系统正确性

- 所有来源生成的 `StyleDefinition` 通过同一 schema、安全和能力校验。
- 相同确认文本通过文字和语音进入相同定义路径。
- 过期 AI、预览和生成响应不能覆盖较新的风格版本。
- 优化、换风格和清理只有在用户明确选择对应云端能力并完成该项确认后才能创建网络任务；本地能力和未选择状态永远不创建。当前本地动态只在用户明确选择方向并点击生成后编码，不创建网络任务。
- 服务接入后的生成取消、失败和恢复不会修改源图、当前风格或任何已有结果，也不会重复扣费。
- 项目冷启动能恢复确切 `CreationTask`、用户曾明确保存的 `CreationCapability`、风格快照和原生成任务身份（如有）；不得从图片或配方猜测能力。

### 9.3 完成定义

风格系统首阶段完成必须同时证明：

1. 官方风格、文字、语音、参考图和 AI 风格重绘都能产出统一 `StyleDefinition`；
2. `StyleDefinition` 能编译、预览、保存、恢复和版本迁移；
3. 四个任务进入后均显示固定顺序的完整能力列表且没有默认选择；用户选择一项后只执行该项，不自动推荐、组合、替换或降级；
4. 优化、换风格和清理从原图得到可保存的受支持静态结果，且不暴露底层参数；
5. 四个任务及所选能力从 UI、状态、持久化、隐私、费用、失败和结果身份上分离；旧 `apply` 草稿安全迁移为换风格；
6. 三项本地动态均证明只有用户明确选择的方向会编码成 MP4，且没有上传或云端成本；不支持本地编码器的平台证明真实不可用；
7. 自动化、iOS Simulator、冻结候选真机和人工视觉质量门按 [MVP Spec](mvp-spec.md)完成。

任一来源只能生成描述但不能预览，或任一路径只能显示入口却不能保存结果时，均不属于完整闭环。
