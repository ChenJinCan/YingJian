# 功能优先的实现与验证工作流

本文件是映见工作区开发与验证时序的唯一规范源。产品范围由 MVP Spec 决定，图像质量阈值由质量基线决定；本文件只决定何时实现、何时使用模拟器、何时进入真机验收。

## 核心规则

1. 先把一个可观察的功能切片完整实现，再集中验证；不得把每次小改动都拆成一次真机流程。
2. 单元、Widget、原生窄测试和静态检查与实现同行，用于尽早发现确定性错误。
3. 功能切片形成完整用户路径后，在 iOS Simulator 运行正式导航、核心交互和集成测试。
4. 所有本轮功能完成、模拟器与自动工程门通过并冻结候选身份后，才进入 Profile/Release 或 TestFlight 真机验收。
5. 模拟器证据不能替代最终真机的性能、色彩、PhotoKit、分享、生命周期和可用性证据；缺少这些证据表示“验收未完成”，不表示“禁止继续实现功能”。

## 四个状态

### 功能实现完成

一个功能切片只有同时满足以下条件，才可标记为功能实现完成：

- 用户入口、主要操作、结果和必要的加载、空态、错误、取消与恢复行为均已实现；
- domain、application、UI、原生能力、持久化和迁移按该功能实际需要闭环；
- 参数可序列化、可归零、可撤销、可恢复，预览与导出遵守同一语义；
- 窄单元、Widget 或原生回归测试随代码补齐并通过；
- 新增页面已通过生产导航接入，并在同一变更中加入 `integration_test`。

此状态不要求已经启动模拟器或连接真机。

### 模拟器验证通过

功能切片完整后，使用 iOS Simulator 集中验证：

- 通过生产导航进入页面，而不是只调用测试替身页面；
- 完成至少一条导入、编辑、撤销/恢复和导出主路径；
- 检查相关布局、加载、空态、错误态、取消、恢复与无障碍语义；
- 运行该切片的集成测试、静态分析和受影响的原生测试；
- 对固定工程样片运行可自动判断的方向、范围、中性值、确定性和预览/导出语义检查。

模拟器失败时回到实现阶段修复，完成同一批功能后再集中复测。

### 候选已冻结

一批 MVP 功能全部实现且模拟器验证通过后，才冻结候选：

- 运行完整 iOS 自动工程门；
- 冻结源码提交、版本、build、配置和产物身份；
- 保证工作树、远端 ancestry 和发布合同满足候选要求；
- 任何影响行为或产物的源码变化都会产生新候选身份。

### 真机验收通过

只对冻结候选执行最终真机阶段：

- Profile/Release 或精确 TestFlight build 的真实主旅程；
- PhotoKit、分享、前后台、低内存、权限、色彩和最终导出回查；
- 性能、内存、温控和设备矩阵；
- 同图竞品、盲评、无引导可用性和人工签字。

若真机发现 P0/P1，先汇总同一轮问题并回到实现阶段批量修复，再完成自动化与模拟器回归、冻结新候选，最后重做与新候选绑定的真机证据。不要在每个微小修复后立即要求一次完整真机矩阵。

## 唯一例外

当任务本身就是诊断或修复只在物理设备出现的问题，例如真机 Metal/Texture、PhotoKit、分享、签名、生命周期或温控问题，可以执行针对性的真机复现与验证；没有该证据时不得宣称这个具体真机问题已修复。

除此之外，真机不可用不会阻断功能实现或模拟器验证，只会阻断最终候选验收。

## 后续 Agent 的执行顺序

1. 从 MVP Spec 选择一个边界清楚、可观察的完整功能切片。
2. 写明行为验收标准和窄测试计划。
3. 完整实现功能，不为每个中间改动启动真机流程。
4. 运行窄自动测试、格式化和静态检查。
5. 功能切片完整后，集中运行 iOS Simulator 集成验证。
6. 本轮全部切片通过后，运行完整自动工程门并冻结候选。
7. 最后一次性执行与精确候选绑定的真机、竞品和真人验收。
8. 分别报告“功能实现完成”“模拟器验证通过”“候选已冻结”“真机验收通过”，不得合并为笼统的“完成”。
